# 多智能体协作「代理 / 编排」框架调研

> 调研对象：Omnigent、Tutti（tutti.sh）、teamai-cli（腾讯）、Multica，以及同类延伸方向。
> 背景：你正在推进 Git AI 区分代码工具的 spec（含 `ide_host` 识别 CodeBuddy / 灵码 / Qoder 等 VSCode 系 IDE）、审查 Claude Code 入门文档、梳理 CodeBuddy 与 Claude Code 的 checkpoint 数据来源差异。本报告重点对照「这些框架如何识别、代理、编排不同的 Agent / IDE」。

---

## 0. TL;DR — 一句话定位

| 框架 | 核心定位 | 协作范式 | 开源协议 | 与你工作的关联度 |
|---|---|---|---|---|
| **Omnigent** | 元编排层（meta-harness），坐在现有 Agent 之上做组合+治理+协作 | 多 harness 编排 + 实时会话共享/分叉 | Apache 2.0（~8.1k★） | 中高：沙箱治理、跨 harness 编排 |
| **Tutti** | 「实况级」多人多 Agent 实时协作空间（云端持久化工作现场） | 多 Agent 并发实时编辑同一文件（Google Docs 式） | 开源版（永久免费）+ VM 版（邀请码） | **高**：实时协作=checkpoint 数据来源差异的直接载体 |
| **teamai-cli**（腾讯） | 团队 harness：Git 原生分发 skills/rules/MCP/知识库 | 团队级配置与知识分发 + recall 子 Agent | MIT（v0.21.0-beta） | **最高**：你团队自家项目，直接对应 spec 的「区分/分发」命题 |
| **Multica** | 「Agent 即队友」的任务管理/编排平台（Agent 的 PM） | 任务生命周期 + autopilot + skill 复利 | Multica License（源码可见，非标准开源） | **高**：自动识别 23 种编码工具=现成的 `ide_host` 方案参考 |

**共同趋势**：单个 Agent 工具已碎片化（Claude Code / Codex / Cursor / CodeBuddy / Qoder…），这些框架都在做**同一层**——把多个异构 Agent 当作可统一寻址、调度、治理、协作的「组件」，而非一堆孤岛。差别只在切入点：

- **编排层**（Omnigent）：不替代 Agent，只在其上做编排/策略/可观测。
- **协作空间**（Tutti）：让不同人的本地 Agent 住进同一台云端电脑实时共编。
- **配置/知识分发层**（teamai-cli）：把团队统一的 harness 资产 Git 化、自动下发到各 Agent。
- **任务/人力管理层**（Multica）：把 Agent 当成「员工」，纳入任务队列与组织流程。

## 1. Omnigent —— 元编排层 + 治理（Databricks / Matei Zaharia）

> 一句话：**Kubernetes 之于服务器，Omnigent 之于 AI Agent**。

- **出处与体量**：Databricks 联合创始人、Apache Spark 发明者 Matei Zaharia 主导，2026-06 发布，约 **8,100★ / 1,200 fork**，Apache 2.0，Alpha。
- **架构三层**：
  - **Harness（执行层）**：claude-sdk、claude-native、codex、codex-native、cursor、hermes、opencode、pi、openai-agents、kiro 等（任意现有 Agent）。
  - **Runner（运行时层）**：把任意 harness 包进一个沙箱化、统一 API 的 session。
  - **Server（服务层）**：策略执行、会话共享、跨设备同步、REST API。
- **三大能力**（官网原词 Composition / Control / Collaboration）：
  1. **Composition（组合）**：一行切换/组合不同 harness，不重写代码；YAML 定义 Agent，Agent 可把其他 Agent 当工具调用。
  2. **Control（治理）**——其核心差异点：
     - **Contextual Policies**：有状态的花费上限（按 session/turn 暂停+人工确认）、模型路由、基于风险的升级。
     - **Secure OS Sandbox**：Linux `bwrap`、macOS `seatbelt`、Windows Job Objects；隐藏凭据、代理注入；可安全跑 YOLO 模式。
     - 有状态条件规则（例：`npm_install` 之后 `git_push` 需审批；永不读 `.env*`）。
  3. **Collaboration（协作）**：`omnigent share <session>` 生成可分享 URL 共驾；`omnigent run --fork <session>` 会话分叉（很适合 code review：主 Agent 实现后分叉出多个 reviewer）。
- **内置编排示例**：
  - **Polly**：多 Agent 监督器——两个不同 harness 的 coder 在各自 git worktree 并行实现同一功能，再把 diff 路由给跨厂商 reviewer 综合决策。
  - **Debby**：双头 Agent，`/debate` 让 Claude 与 GPT 互相评价后综合作答。
- **可观测性**：与 **MLflow Tracing** 集成，跨 harness 记录每轮对话、工具调用、token 消耗、session 元数据——便于模型对比 / A/B 测试 / 团队洞察。
- **部署**：`uv tool install omnigent`，本机 `localhost:6767`；Docker 可部署到 Render / Railway / Fly.io / Cloudflare；OIDC 登录（Google/GitHub/Okta/Microsoft）。

**对你的价值**：如果你的 spec 需要「治理 Agent 行为」（成本、工具权限、沙箱），Omnigent 的策略模型是最完整的现成参考；其「harness 抽象层」也正是 `ide_host` 要解决的「对不同 IDE 统一寻址」问题的一种解法。

## 2. Tutti（tutti.sh）—— 实况级多人多 Agent 协作空间

> 一句话：**让本地 Agent 像 Google Docs / Figma 一样，在同一台云端电脑里实时共编。**

- **两个版本**：
  - **Tutti · 开源版**：永久免费，连接已有 Agent、群聊、借用 Agent、跨设备、免部署分享；Big @ 跨**自己的** Agent。
  - **Tutti · VM**：早期免费，创建房间需邀请码；额外支持与他人及**他人的** Agent 协作、跨设备、Big @ 跨他人的 Agent。
- **接入的 Agent**：Claude Code、Cursor、Tutti · VM、OpenCode、Codex，以及内置的低成本的 **Tutti Agent**；**复用你已有的订阅额度与配置（MCP/工具/技能）**，不会取代你的编程 Agent。
- **四条技术路线（官网强调的差异化）**：
  1. **唯一的云端持久化工作现场**：文件/配置/运行中的服务/依赖只维持一份最新状态，runtime 不再与某个 Agent 绑定。
  2. **Agent 与项目的分布式组成网络**：Agent 不再与沙箱 1:1 绑定，进入同一项目即实时协作，离开保留各自身份/能力/经验。
  3. **基于底层文件系统的实时协作引擎**：不同人/不同厂商的本地 Agent 能像 Google Docs 一样并行实时协作，自动避免/解决冲突。
  4. **分摊云端成本压力的分布式系统**：本地设备作为执行节点，协作/共享状态/产物服务留在云端。
- **核心体验**：Agent Board（看见每个 Agent 在做什么）、实时协作（多人多 Agent 同编同文件）、无需同步即分享（产物诞生即共享）、借用 Agent（接手续用上下文、限本房间可撤回）、Big @（跨对话/文件/产物/Agent 引用调用）、内置应用（群聊/AI Canvas/原型设计/AI PPT/AI 文档）。
- **交付形态**：SDK 接入（敏感数据不出本机，获得团队共享工作现场/实时协作/免部署分享/借用 Agent）+ 企业私有化部署；VM 版支持 macOS（Apple Silicon）与 Windows。

**对你的价值**：你正在梳理「CodeBuddy 与 Claude Code 的 checkpoint 数据来源差异」——Tutti 的**云端持久化工作现场 + 文件系统级实时协作引擎**正是「多 Agent 共享同一份状态」的工程化实现。要理解 checkpoint / 状态同步在协作场景怎么落地，Tutti 是最贴近的样本。

## 3. teamai-cli（腾讯）—— 团队 harness 分发（你们自己的项目）

> 一句话：**The team harness for AI agents**，用 Git 把团队的 skills/rules/MCP/知识库统一分发到各 AI 编码工具。

- **协议与状态**：MIT，**v0.21.0-beta.2**（2026-08-25），npm 分发（`npm install -g teamai-cli`），TypeScript + Node.js CLI。
- **适用工具**：Claude Code / Codex / CodeBuddy / WorkBuddy / OpenCode 等（YAML 中间规格渲染为各工具原生格式：claude/codex/cursor/codebuddy，push 时逆向转回 YAML）。
- **核心能力**：
  1. **Harness 管理与分发**：`push → MR → 合并 → pull` 流程，把 skills/rules/docs/hooks 分发到成员本地。
  2. **分发控制**：`teamai roles`（按角色映射命名空间）、`teamai tags`（标签订阅）、`teamai source`（订阅其他团队/组织共享仓库）。
  3. **知识库**：
     - 自动经验分享（Stop hook 按「摩擦」评分触发 `/teamai-share-learnings`）；
     - **`teamai recall`**：隐私脱敏的 subagent 检索（BM25 + 图增强重排，默认关闭）；
     - 代码库知识图谱（`teamai import` 解析仓库到 `teamwiki/`）。
  4. **团队 Hooks / MCP**：声明式 `hooks.yaml` 与 `mcp.yaml`，pull 时自动写入各工具原生配置。
  5. **多智能体同步**：claude/codex/cursor/codebuddy 等格式的 agent 渲染与推送；`teamai-recall` subagent 经 `pull` 部署到各工具 `agents/`。
  6. **分析**：`teamai digest`（每周用量摘要）、`teamai session save`、`teamai dashboard`。
- **CI**：`teamai ci extract-mr` 从 MR 提取知识；提供 GitHub Actions 与 Coding CI 模板。
- **数据源**：Git 仓库（GitHub / GitLab / CNB / TGit / 私有 Git），知识存于 `teamwiki/` 与 `docs/team-codebase/`。

**对你的价值**：这是你团队（腾讯 liyong02）的自家项目，与你的 spec 命题——「Git AI 区分代码工具 + `ide_host` 识别 VSCode 系 IDE」——**直接同源**。值得重点对照的是它的 **YAML 中间规格 → 多工具原生格式渲染** 思路：这本身就是「用一个抽象层描述 Agent 配置，再按目标 IDE 落地」的实现，和你探索的 `ide_host` 方案是同一件事的不同切面。

## 4. Multica —— 「Agent 即队友」的任务编排平台

> 一句话：**Your next 10 hires won't be human.** 把编码 Agent 当成团队里真正的「员工」管理。

- **协议（注意口径）**：官网写「Open source for all」，但 GitHub 提交已改为 **source-available**——许可证为 **Multica License**（在 Apache 2.0 之上附加条件：向第三方提供托管服务需商业许可；UI 代码须保留 Multica 品牌）。**严格说不是标准开源**，做选型时务必留意。
- **架构**：monorepo（TypeScript + Go），含 `server`（REST）+ `gateway`（NestJS WebSocket）+ `daemon`（本地守护进程/worker）+ `cli` + `web/desktop/mobile`；部署支持 Docker Compose / Helm（K8s）/ Vercel / 本地 `make`。
- **四大能力**：
  1. **Agent 即队友**：Agent 有 profile、主动报状态、建 issue、评论、改状态；人/Agent 在同一 assignee 下拉框；统一 activity timeline 人/Agent 交错。
  2. **完整任务生命周期**：`enqueue → claim → start → complete/fail`，autopilot 自动化；Agent 主动上报阻塞；WebSocket 实时进度流。
  3. **Skill 复利**：可复用的能力定义（代码+配置+上下文打包），写一次全队 Agent 可用，团队能力随时间复利增长。
  4. **统一计算面板**：本地 daemon + 云 runtime 一屏管理，实时在线/离线、用量、热力图；**首次运行自动探测 23 种编码工具**并注册为 runtime。
- **自动识别的 23 种工具**（这条与你 `ide_host` 强相关）：Antigravity、Claude Code、**CodeBuddy**、Codex、Copilot、Cursor、DeepSeek Harness、DevEco Code、Dim、Grok、Hermes、Kimi、Kiro CLI、Oh-My-Pi、OpenClaw、OpenCode、Pi、**Qoder**、**Qoder CN**、Qwen Code、QwenPaw、Reasonix、Trae CLI。
- **安全边界**：Agent 执行发生在你本机 daemon 或自有云，代码不经 Multica 服务器；平台只协调任务状态与广播事件。

**对你的价值**：Multica 的**「首次运行自动探测 23 种编码工具并注册 runtime」**是 `ide_host` 识别问题最完整的现成清单与实现参考——尤其已覆盖 **CodeBuddy、Qoder、Qoder CN、OpenCode** 等你关心的 VSCode 系 IDE。其 agent 接入走 **ACP runtime** 协议（模型发现 + MCP 透传），是比「逐个写适配」更通用的抽象。

## 5. 横向对比（按你的 spec 关注点对齐）

| 维度 | Omnigent | Tutti | teamai-cli | Multica |
|---|---|---|---|---|
| 核心抓手 | 编排+治理 | 实时协作空间 | harness 配置/知识分发 | 任务/人力管理 |
| 多 Agent 协作范式 | 多 harness 编排 + 会话共享/分叉 | 并发实时同编（文件系统级） | 知识/配置分发 + recall 子 Agent | 任务队列 + autopilot + skill 复用 |
| **识别/代理异构 IDE** | harness 抽象层 | 连接已有 Agent（不重识别） | YAML→多工具格式渲染 | **自动探测 23 种工具** |
| 团队治理/权限 | **最强**（策略沙箱、有状态规则、成本上限） | 房间边界 + 借用权限可撤回 | 角色/标签/来源分发控制 | runtime 隔离 + 席位计费 |
| 可观测性 | **MLflow Tracing**（跨 harness） | 工作实况直播、Agent Board | digest/dashboard 用量摘要 | runtime 用量/热力图 |
| 状态/数据持久化 | Session + Server 同步 | **云端持久化工作现场** | Git 仓库 + teamwiki | 任务状态 + 事件广播 |
| 安全边界 | 本地沙箱 + 云执行环境 | 本地 Agent 跑本机，仅状态上云 | Git 仓库权限 | 代码不经服务器 |
| 协议 | Apache 2.0 | 开源版免费 / VM 邀请码 | MIT | Multica License（源码可见） |
| 部署形态 | 本机 + Docker + 云平台 | 桌面端 + 云端房间 + 企业私有化 | npm CLI | Docker/Helm/Vercel/自托管 |
| 与 `ide_host` 关联 | 中（harness 抽象） | 低（直接用已有 Agent） | **高**（自家、格式渲染） | **最高**（23 工具探测清单） |

## 6. 与你当前工作的直接映射

1. **`ide_host` 识别 VSCode 系 IDE**：
   - **最该看 Multica** —— 现成覆盖 CodeBuddy / Qoder / Qoder CN / OpenCode，且用 ACP runtime 统一接入。
   - **其次看 teamai-cli** —— 自家项目的「YAML 中间规格 → 各工具原生格式」渲染，是识别后的「按 IDE 落地配置」参考。
   - **Omnigent 的 harness 抽象层** 提供「统一寻址异构 Agent」的理论框架。

2. **Git AI 区分代码工具 spec**：
   - teamai-cli 即腾讯的官方落地：用 Git 做单一事实来源，分发 skills/rules/MCP/hooks。可直接作为 spec 的「团队侧分发」章节范例。
   - Multica 的 skill 复利、Omnigent 的 YAML agent 定义，提供「Agent 能力描述标准化」的对照。

3. **CodeBuddy 与 Claude Code 的 checkpoint 数据来源差异**：
   - **Tutti 的「云端持久化工作现场 + 文件系统级实时协作」** 是最贴近「多 Agent 共享状态」的工程样本，建议作为 checkpoint/状态同步章节的参考实现。
   - Omnigent 的 `share`/`fork` session 机制也涉及「会话状态如何共享/分叉」。

4. **审查 Claude Code 入门文档（auto 模式 / 实例 / ux-pro skill）**：
   - 多框架都强调「Agent 有身份、可复用配置、可被治理」——与你在文档里定的「新手 auto 模式、保留 gstack.qa / ieidev-qa 实例、补 ux-pro skill」思路一致：都是把 Agent 当可管理、可分发、有边界的一等公民。

## 7. 延伸方向（本次未深入，按需跟进）

- **OpenClaw**：出现在 Multica 支持的 23 种工具之一，是一个独立的编码 Agent，可单独调研其 IDE 集成方式。
- **Vibe Kanban**：腾讯云文章将其与 Multica 并列为「把人带 Agent 变成协作系统」的代表，偏向看板式任务流，可补 Multica 的看板视角。
- **ACP（Agent Client Protocol）**：Multica 接入 Agent 的协议层，是「异构 Agent 统一运行时」的关键抽象，值得单独研究其规范。

## 8. 一句话选型建议

- 想做**团队配置/知识统一分发** → 直接复用/对标 **teamai-cli**（自家、MIT、Git 原生）。
- 想做**异构 Agent 的统一治理与编排** → 参考 **Omnigent** 的 harness + 策略 + MLflow 模型。
- 想做**多 Agent 实时协作 / 状态共享** → 研究 **Tutti** 的云端工作现场与文件系统协作引擎。
- 想做**Agent 纳入研发流程（任务/人力管理）** → 参考 **Multica**，尤其其 **23 工具自动探测** 直接解决你的 `ide_host` 识别问题（注意其 license 实际为源码可见，商用前需确认合规）。
