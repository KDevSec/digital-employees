### 2.3 permission / model / effort / listModels

- **permission-mode**：CC 不传时 -p 会话**无写类工具**（模型自述+`permission_denials=[]`+文件未创建）；`acceptEdits` 下写任务实际完成。qodercli `accept_edits`（下划线值域）写任务成功。**编排驱动的员工会话必须显式传 permission 旗标才有写面**；两底座值域风格不同（映射层需值转换）。

## 4 ⑤：hooks 域内路径 + cmd /c 模板预触发——❌ 统一负面结论

**方法**：CC 夹具 `cc5` / Qoder 夹具 `q5`（独立夹具；JSON 程序化写入，P-1）——PreToolUse + matcher `Write` 的 hook 写 marker 文件；跑写文件任务触发 Write 工具。

**CC（2.1.226）四组对照**：① 域内 user 级 `config/settings.json`：trigger.txt 创建成功（Write 执行），marker 不生成，debug `Hooks: Found 0 total hooks in registry`；② `--setting-sources user,project,local` 显式传：无效；③ 同一 settings.json 加 `env` 键探针：`settingsEnv keys: L2M5_PROBE`——**文件被加载但 hooks 键被忽略（半生效）**；④ 改放项目级 `ws/.claude/settings.json`：同样 registry 0；`--output-format stream-json --include-hook-events` **零 hook 事件**（剥离 CLAUDE_* env 复测同样）。

**qodercli（1.1.32）全组合矩阵**：项目层 `.qoder/settings.json`（v0.1 V-4 实证形态）+ 域内 `<config>/settings.json` + 域内 `<config>/.qoder/settings.json` 三落位 × `cmd /c "echo X>> marker"` / 裸 `echo X>> marker` 两种命令形态 × 有 matcher / 无 matcher × `--permission-mode accept_edits` / `--dangerously-skip-permissions` 两种权限——**marker 全部不生成**（trigger.txt 均创建成功证明 Write 工具在跑）。附带发现：项目层 settings.json 在未信任目录 + `-p` 非交互下触发权限门控（「所有工具调用都需要权限确认，但没有交互式处理程序可用」→ 工具全禁；`--dangerously-skip-permissions` 可绕过但 hooks 仍不执行）。

## 7 附带发现

### 7.1 CC「用户全局指令污染」现象（来源待查）

CLAUDE_CONFIG_DIR 隔离域会话中，模型复述了**用户真实全局指令内容**（截图管理规则原文细节、「流程驱动、TDD 严格」、superpowers 工作流顺序）——不在域内 CLAUDE.md。三组对照（伪造 HOME+USERPROFILE / 剥离全部 `CLAUDE_*` env / HOME 根与 TEMP 链无 CLAUDE.md）均未屏蔽，debug 无加载痕迹，**来源未定位**（疑注册表 profile 解析等固定路径）。语义：**CC 的 config 域隔离不含用户全局指令**——当前用户全局无身份声明故无竞争；若含身份类内容存在 V-X1c 式双弃用风险。员工语义按「域内身份 + 用户全局工作原则叠加」理解。qodercli 侧同构现象：用户级 skills 从 `~/.agents/skills/` 叠加（不随域隔离）。

### 7.2 claude 版本断言基线在 Windows 误伤

本机 2.1.226 < 设计断言 `>= 2.1.245`（S4 Linux 基线）→ `/api/bases` 卡片 `supported:false`——按 B-8 语义将阻塞一切 CC 安装。修正：版本断言按平台分档（Windows 基线 2.1.226）或下调研证区间。

### 7.3 launch.ts prompt 通道与坑1

`launch.ts` 将 prompt 全文压 args 数组（注释假设「spawn args 不经 shell 多行安全」）+ promptFile 仅观测落盘；坑1 双底座复现表明 **shell 包装（win32）spawn 下多行必截断**——prompt 传输通道应升级为 stdin（双底座唯一共同可靠形态），属 L2/L3 接口任务。

### 7.4 qodercli 用户级 skills 路径与域隔离边界

用户级 skills = `~/.agents/skills/`（HOME 直下，**不在 config 域内、不随 --config-dir 隔离**）；员工私有 skills 落 `<config>/skills/` 实证有效（`.agents/skills` 域内形态不识别）。员工会话 skills 面 = 域内 skills + 用户全局 skills 叠加（非零基线，P-14 扩展语义）。
