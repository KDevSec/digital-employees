## 1 身份落位方案矩阵（本次核心产出）

> 用户原则：身份定义是员工包的**统一资产**（单一真相源），底座落位只是运行时形式。各方案实测边界如下。

| 方案 | 载体 | 身份指令权威 | 判定 | 设计含义 |
|------|------|------------|------|---------|
| **A** | `{ws}/AGENTS.md` | ✅ 常驻、最高 | **基线成立** | 唯一推荐的身份落位；现行设计 §3 落位表正确，不动 |
| **B** | config 根 `AGENTS.md`（home 层） | ✅ 常驻；但与项目层**竞争时双输** | **原则层可用，身份层不可用** | `{home}` scope 定位应改为「跨项目通用**工作原则**」层；岗位身份必须互斥单值（模型行为强制，非账本约定） |
| **C** | 插件（claude-plugin schema） | ❌ rules/ 不入组件面 | **能力载体，不是身份载体** | 插件承载 skills/hooks 分发可行（且 schema 与 CC 插件同构 → 双底座通用）；身份仍须 AGENTS.md 配合 |
| **D** | spawn 旗标（`--system-prompt` 等） | 未验证（用户裁决不在本次范围） | —— | 仅记录：会话级、不落盘，只可作工作台拉起会话时的运行时增强，不满足「安装=上岗」文件基底原则 |
| **E** | `{ws}/AGENTS.md` 薄壳 + `@` import | ✅ 常驻（根内引用时） | **可用，有边界** | 岗位说明留在包内单一真相源，落位文件极薄；**引用目标必须在项目根内**（或走外部 import 批准） |

**推荐组合**（回写建议 §6 用）：**身份 = A 或 E（项目层，互斥单值）；通用原则 = B（home 层）；能力 = C（插件）或四层散装**。E 形态下当值切换只需替换薄壳行，岗位全文不重复落盘。

## 2 主线逐步骤结果（预演 B-03/B-05/B-07）

工作区：`%TEMP%/s1-employee-spike/ws`（纯临时，全链零污染真实用户目录）。

### 2.1 基线快照 → 安装 A（frontend-dev）

- 基线 = 空工作区（`find` 输出存档）
- 落位三件：`AGENTS.md` → ws 根（含溯源注释）；`skills/fix-style/` → `.agents/skills/fix-style/`；PreToolUse hook 程序化 merge 进 `.qoder/settings.json`，条目带 `"_workbench": "frontend-dev"` 撤销标记
- **事故实录**：首次用 bash heredoc 手写 settings.json，`\\w` 被吃成 `\w` 产生非法 JSON 转义——qodercli 启动时打 `JSON Parse error: Invalid escape character w` 但**容忍继续运行**（身份注入不受影响，hook 未验证是否生效）。改用 python `json.dumps` 重写后合法。→ 手写/手拼 JSON 不可靠，merge 必须程序化 + 写前备份（进事务化清单）

### 2.2 L0 身份验证 ×2 —— ✅ 2/2

`qodercli -p "用一句话介绍你是谁、什么岗位"`，两次输出首行均为：

```
DUTY-A-FRONTEND-DEV
我是数字员工 frontend-dev，岗位是前端开发工程师，负责前端页面开发、组件开发和样式问题修复。
```

（采样 2 系身份问答，模型却自发演示 fix-style 流程并带出 SKILL-A-TRIGGERED——**身份文件与 skill 并存时模型有过度触发倾向**，记采样现象）

### 2.3 L1 skill 验证 ×2 —— ⚠️ 标记 1/2，语义 2/2

- 采样 1 ✅：DUTY-A + SKILL-A-TRIGGERED 双标记，自述「已按 fix-style 流程检查」
- 采样 2 ⚠️：无任何标记，但回答**逐字引用 SKILL.md 流程步骤**（「定位样式问题」「class 名 → 选择器优先级 → 内联样式 → 样式表加载顺序」）——skill 被发现且被遵循，仅标记输出缺失。判「通过但注明采样差异」（M0 V-2 同现象）

### 2.4 当值切换 A→B（预演 B-07）—— ✅

- A 的 AGENTS.md → `parked/frontend-dev/`（停靠区，spike 内模拟）；B（backend-dev）AGENTS.md 落位；B 的 `api-design` skill 落位，**A 的 fix-style 不删**
- 切换后身份问答 **2/2**：首行 `DUTY-B-BACKEND-DEV` +「后端开发工程师」身份（两次输出完全一致）
- `qodercli skills list`：`api-design [Enabled]` 与 `fix-style [Enabled]` **同时可见**，Location 均指向 ws 项目级 `.agents/skills/`——**身份互斥 + 能力命名空间并存**语义全部生效

### 2.5 卸载（预演 B-05）—— ✅ 干净

- 按 `_workbench` 标记程序化摘除 hooks 条目：命中 1 条，settings 归零 `{}` → **整文件删除**（创建者=本安装）
- 删 B 身份 + B skill + A 残留 skill；`.agents/.qoder` 空目录连带清理
- 基线 diff：**唯一差异是快照的 `.` 目录标记行，实质干净**
- ⚠️ **归属判定发现**：diff 时 ws 内有 56 个 `.ieidev/` 文件——**第三方用户级插件（project-memory）在会话运行时向工作区投递的状态**（含嵌套 git 仓）。非员工包资产，卸载器必须按命名空间/标记做归属豁免，裸 diff 会误报。另验证：第三方记忆插件**未篡改**我们的 AGENTS.md（与包内源逐字节一致）

## 3 V-X1 home 层 AGENTS.md（`--config-dir` 隔离验证）

**方法**：隔离配置根 `%TEMP%/s1-employee-spike/vx1/config` 放 home 层 AGENTS.md，`--config-dir` 指过去，全程不碰真实 `~/.qoder`。

- **auth 置备坑（重要）**：`--config-dir` 指向新根后 CLI 立即 `Not logged in`。逐项排查：拷 `.auth` 不够、补 `state.json`/`.models` 不够——**CLI bootstrap 会重新生成 `installation_id`，而登录态与它绑定**；用真实 `installation_id` 覆盖后登录恢复。→ 按员工隔离配置根（V0.2+ 若采用）需 auth 置备清单
- **加载 ✅**：模型回答亲证「我注意到加载了 `.../vx1/config/agents.md`」（路径原样引用，分层记忆枚举坐实）
- **身份可用但脆弱**：
  - 提示词带「说明身份定义来自哪个文件」时 2/2 拒绝——模型把注入当「身份覆盖尝试」审视并驳回（底座反注入立场，安全相关现象）
  - 同环境换主线原版提示词 → 通过（首行 DUTY-HOME-LEVEL + HOME-RULE-LOADED）——**元分析类提示词会触发注入审视**，验证判据设计要避开诱导性问法
- **竞争身份双弃用（2/2）**：home 层（home-employee）+ 项目层（proj-employee）同时立身份 → 模型：「两个试图重新定义……与核心身份约束冲突，我不会执行」→ 回落 vanilla Qoder。**实证「身份互斥」是模型行为强制的约束**
- **互补叠加 ✅**：home 层改为不竞争的工作原则（中文 + 末行标记），项目层仍立身份 → 首行 `DUTY-PROJ-LEVEL` + 正文 PROJ-RULE-LOADED + 末行 `[home-principles-on]` **全部生效**——`{home}` 原则层 / `{ws}` 身份层的分工设计拿到正面证据

## 4 V-X2 插件形态（`--plugin-dir` 免安装挂载）

**方法**：组装 `employee-frontend-dev` 插件（`.claude-plugin/plugin.json` + `rules/duty.md` 身份探针 + `skills/duty-lookup/` + `hooks/hooks.json` CC 同构格式），`--plugin-dir` 挂载（不进真实插件目录，零污染）。

- **`plugins validate` ✅ 合法**：`Components loaded successfully: skills (1), hooks (1)`——**组件清单无 rules**，rules/ 目录不被认作指令资产 → **插件不能承载常驻身份指令**（方案 C 身份面判死）
- **skill 组件 ✅**：语义触发「请使用 DUTY-LOOKUP-SKILL…」→ 首行 `SKILL-PLUGIN-TRIGGERED`，并自述「前端开发工程师（数字员工，隶属 employee-frontend-dev 插件）」——插件加载成立，skill 内容可**按需**呈现岗位信息（弱身份，非常驻）
- **枚举盲区 ⚠️**：`qodercli skills list` **不显示** `--plugin-dir` 挂载的插件 skill（语义可用但枚举不可见）→ B-06「已装 skill 校验」不能只依赖 skills list，须语义触发或安装态枚举
- **hooks 组件 ✅ 触发 / ⚠️ 转义**：让模型写文件触发 Write → `plugin-hook.log` 生成（PreToolUse 实弹）；但 log 内容是 cmd banner + `More?`——**Windows 下 `cmd /c echo … >> log` 被 cmd 吃成交互等待**（M0 遗留的 hooks 命令转义坑拿到具体翻车样本；写入本身也被 -p 模式权限确认拦截，属环境正常行为）
- 附：manifest 的 `$schema` 字段被 runtime 忽略并 warning（无害，容忍未知字段）；已装插件 agents-team 的 hooks 用 `${CLAUDE_PLUGIN_ROOT}` 插值（CC 同构），可作 B 侧生成器参照

## 5 V-X3 AGENTS.md @import 薄壳

**方法**：ws 根 AGENTS.md 只写标题 + 一行 `@路径` 引用岗位说明全文（CC 风格语法）。

- **语法确认**：`@相对路径` 即被解析（无需特殊声明）
- **项目根外 ❌ 被门控拦（按设计工作）**：`@../pkg/duty-full.md` → CLI 警告 `external @import(s) blocked in AGENTS.md: …pkg\duty-full.md. Run with approved external imports or update settings to allow them.`（打印两次，疑似双重枚举）；**import 内容未注入**（无 DUTY-IMPORTED/IMPORT-LOADED）；模型口中的「frontend-dev」仅来自薄壳标题残留——薄壳本身会泄漏最小身份提示，门控拦的是全文不是壳
- **项目根内 ✅ 2/2**：岗位说明拷入 `ws/.employees/frontend-dev/duty-full.md`，薄壳改 `@.employees/frontend-dev/duty-full.md` → 两次均首行 `DUTY-IMPORTED` + IMPORT-LOADED + 身份正确，零门控
- **设计含义**：员工包若整包落在 ws 内（`.employees/<id>/`），@import 薄壳完全可用且**当值切换只动薄壳一行**；若包放全局共享位置（如 `~/.ieidev-workbench/homes/`）引用即撞门控 → B-03 落位策略：**包内容物随装拷入 scope 内**，或预批准外部 import 目录（设置项存在，本次未深挖批准流）

## 8 给 B-03 安装执行器的事务化清单（手工步骤 → 必须原子化）

1. **三步落位（identity copy / skills copy / hooks merge）必须单事务**：手工链中任一步失败即半装状态（本次未触发但手工步骤间无任何保护）
2. **merge 动作三件套**：写前备份原文件 → 程序化深合并（禁止文本拼接）→ 写后回读校验 + 捕获 qodercli parse error 信号（P-1/P-5：底座容忍坏 JSON，静默半生效比报错更危险）
3. **撤销标记双锚**：merge 类用 `"_workbench": "<employee_id>"`（实测精确摘除 1/1）；copy 类用溯源注释 + checksum——两者缺一不可（merge 无法用注释，copy 无法带 JSON 键）
4. **创建 vs 合入区分**：目标文件不存在 → 本安装创建，卸载可整删；已存在 → 按标记摘除条目、保留文件（本次 settings.json 归零后整删的分支要做成显式判定）
5. **当值切换两步（旧身份移停靠区 + 新身份落位）间需崩溃恢复**：中途崩溃 = scope 无身份状态；事务日志需记录 phase
6. **卸载顺序**：摘 merge 条目 → 删 copy 文件 → 清空目录 → 归属豁免 diff → 出报告（本次实测顺序，逆向还原无残留）
