## 1 T1 单体二进制 ✅

**方法**：Bun 1.3.9 `bun build --compile`（Hono + /healthz，按 C-4 契约返回 `{app,status,version,pid,uptime,dataDir}`）→ 独立运行 → curl 验证 → taskkill。

**结果**：
- 编译 0.6s，108.8 MB（预期 60–100 MB 区间上缘，Bun 1.3.9 较调研时的参照略胖，可接受）
- exe 直跑无任何运行时依赖；杀进程干净
- 日志输出 JSON 行（与 S-08 横幅设计一致）

**关键代码**（可复用为实现骨架）：

```ts
// app.ts —— 框架唯一入口（route-registry 语义的最小形态）
import { Hono } from "hono"
const app = new Hono()
app.get("/healthz", (c) => c.json({ app: "ieidev-workbench-spike", status: "ok", ... }))
export default app

// 编译：bun build --compile src/index.ts --outfile workbench.exe
```

## 2 T2 sqlite-vec 外挂 ✅

**方法**：下载官方 [sqlite-vec v0.1.9](https://github.com/asg017/sqlite-vec) windows-x86_64（`vec0.dll` 0.3 MB）→ `bun:sqlite` 加载 → 建虚拟表 → 插入 2 条 4 维向量 → KNN 查询。

**结果**：KNN 正确（`[0.1,0.2,0.3,0.4]` 自身距离 0，另一条 1.095）。**外挂模式成立**：主二进制不含原生依赖，资源目录平铺 `.dll`，运行时加载——与调研 §4.3 结论一致。

**踩坑记录（实现必读）**：
- ❌ `new Database(":memory:", { allowExtension: true })` → `SQLITE_MISUSE`（Bun 1.3.9 Windows 不认该构造选项）
- ✅ `const db = new Database(":memory:"); db.loadExtension(absPath)` 直接可用
- 路径要**绝对路径**（相对路径在 daemon cwd 语义下易错）

## 3 T3 Node SEA 回退 ✅

**方法**：同一份 `app.ts`（Hono 业务代码零改动）→ `bun build --target=node --format=cjs` 打 bundle → `node --experimental-sea-config` 生成 blob → 复制 node.exe → `npx postject` 注入 → 独立运行验证。

**结果**：SEA exe **86.0 MB**（node.exe 85.8 + blob 0.14），/healthz 200。**回退路径成立**——「以 Bun 为运行时但不被 Bun 锁定」（R-10 缓解）有了实证。

**要点**：
- bundle 需 `--format=cjs`（SEA 对 ESM 主入口支持不稳，避免折腾）
- postject 注入会报 "The signature seems corrupted!" 警告——无签名 exe 的预期行为，不影响
- 四步链（build → sea-config → copy node.exe → postject）应封装为 npm script；与 Bun 一步编译相比工程链长，但作为回退可接受
- **意外数据**：SEA 反而比 Bun compile 小 22.8 MB（node.exe < bun runtime）。体积敏感时可反转为 SEA 优先——不建议（开发体验与 Bun 工具链优势），记录在案

## 4 T4a Windows 计划任务守护 ⚠️

### 4.1 已验证 ✅

- Task XML 字段渲染（四反直觉默认值全量：ExecutionTimeLimit=PT0S / DisallowStartIfOnBatteries=false / StopIfGoingOnBatteries=false / StopOnIdleEnd=false + RestartOnFailure Interval=PT1M Count=3 熔断 + MultipleInstancesPolicy=IgnoreNew + LogonTrigger）——**PowerShell `New-ScheduledTaskSettingsSet` 全参数构造成功**，guard/ 模块可编程生成，无需手拼 XML
- `schtasks /create /xml` 需要 **UTF-16** 文件（UTF-8 声明会报"无法序列化内容"）——用 PowerShell cmdlet 则完全避开此坑

### 4.2 未验证 ❌（环境受限）

**本机非提权上下文无法注册任何计划任务**——三种方式全部"拒绝访问"：
1. `Register-ScheduledTask` + S4U Principal
2. `Register-ScheduledTask` 默认 Interactive 主体
3. `schtasks /create /sc onlogon`（最简形态）

当前 shell 为 UAC 拆分令牌的非提权侧（`IsInRole(Administrator)=False`）。

### 4.3 修正 ①（设计影响）：守护注册需一次 UAC 提权

调研 §7.1.1 声称「LogonType=S4U + RunLevel=LeastPrivilege 已做到免 UAC」——**在本机不成立**：注册动作本身被策略拦截。设计修正：

- `install.ps1` / 首次 `workbench start` 以 **RunAsAdministrator 一次提权**完成注册（注册后运行不需要提权，S4U 语义在运行期仍免密码）
- 提权失败降级路径：`--no-keepalive` + UI 告警（R-11 既有机制），托盘壳探活层成为事实兜底（见 4.4）
- **此发现同时解释了 QoderWake 为什么放弃 OS 守护改托盘单点**——但我们的 D-027 双层结论不变：托盘不得为唯一保活（R-15），提权一次换 OS 级兜底是值得的

已备测试资产（提权后可直接执行）：`t4-guard/register.ps1`（Interactive 版）+ 验证步骤（kill 后等 PT1M 观察 RestartOnFailure 拉回；改 78 退码观察 Count=3 熔断停转）。Windows 运行时语义留 M1 首日提权环境补测。

## 5 T4b 托盘壳（Q-V6 选型验证）✅

**方法**：Go 1.26 + `fyne.io/systray`（GOPROXY 需换 goproxy.cn，proxy.golang.org 被墙）→ 最小壳（自构 ICO 字节 + 菜单 + 5s 探活循环，双条件判真挂：连续 3 次失败 + 超 30s 冷启动预算）→ `go build -ldflags "-H windowsgui -s -w"` → 真实服务配对实测。

**结果（全链路日志实证）**：

```
GREEN（healthz 200）
→ 杀服务 → YELLOW ×3（failCnt=1,2,3——黄态 skip 不重启，硬规则生效 ✓）
→ failCnt≥3 且过冷启动预算 → RED + recover_start 拉起服务（一次，不重复）✓
→ 拉起成功 → GREEN 恢复 ✓
→ 强杀壳（taskkill /F tray-spike.exe）→ 服务存活、healthz 仍 200（W-2/R-15 ✓）
```

双条件判定的时间语义精确生效：failCnt=3 但未过预算时仍 YELLOW（14:35:05），预算到点（14:35:10）才转 RED——与设计 §3 完全一致。

**踩坑记录**：手构 BMP-in-ICO 时 BITMAPINFOHEADER 差 4 字节导致 `SetIcon` 全部失败（systray 报"unable to set icon: The operation completed successfully."——误导性错误信息）；实现期直接用设计好的 .ico 资产文件嵌入即可。

### 修正 ②（待裁决）：托盘壳体量 6.4 MB，超 D-026 的 < 5 MB

| 选项 | 预期 | 建议 |
|------|------|------|
| UPX 压缩 | ~3 MB | ✅ 推荐（CI 加 upx 步骤；EDR 误报风险略增，需纳入 R-13 观察） |
| 放宽 D-026 至 < 8 MB | — | 备选（0.1 阶段体量本就不敏感） |
| 换 getlantern/systray | 未测 | 不建议（fyne 线维护更活跃，T-Q5 已记录比较意图） |
