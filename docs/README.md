## 约定

1. **划分轴**：design/ 下按**设计深度**分组——概要设计（架构/范围/协议/模块概要）与详细设计（开发依据 + as-built）；跨阶段过程记录（决策/评审/待讨论）留根目录。
2. **模块归属看文件名**：同模块的概要与详细分居两目录（如「员工安装与底座适配设计」与「...详细设计」），互为上下游引用。
3. **版本与归档**：文档迭代到新版本时（v0.1 → v0.2），新文件留在分类目录、旧文件移 `archive/`（保留原相对层级）；文件名带版本号。
4. **research 只增不改**：调研/评估结论被设计文档消费；后续实证推翻时在设计文档/决策记录里记录推翻，research 原文不动。
5. **冻结口径**：概要设计三篇（白皮书/功能点清单/UPP）与平台侧两篇 as-built 的改动需走 Q 决策流程（CLAUDE.md §2）；详细设计随开发迭代，但验收标准以功能点清单为准。
6. **链接纪律**：跨文档引用一律用相对路径 markdown 链接；移动文件时同步更新入链（可用 `grep -rn "](.*旧文件名" docs` 反查）。
