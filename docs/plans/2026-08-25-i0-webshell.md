## T1 注册约定化（地基，先行）

**service 侧**（先测后改）：
1. 红：新增 `test/routes-registry.test.ts`——① `collectRoutes()` 注册产物 = 期望路由表（GET /、GET /healthz、GET /api/events、GET /api/activity），method+path 全唯一；② 分域导出（infra/shell）各自注册函数只注册自己的端点（域间无交叉污染）。
2. 绿：建 `src/server/routes/infra.ts`（healthz/activity/events 三 handler + `registerInfraRoutes(reg, deps)`）、`src/server/routes/shell.ts`（root + `registerShellRoutes(reg, deps)`）、`src/server/routes/index.ts`（静态汇总表 + 唯一性断言函数）；`endpoints.ts` 删除，其导出的 handler 函数随域迁移（`server.test.ts`/`contracts.test.ts` 的 import 路径同步改，断言不动）；`main.ts` 装配改 `registerAllRoutes(registry, deps)`。
3. 回归：101 全绿（行为逐字节等价由既有契约测试佐证）。

**web 侧**（同构）：
4. 红：`test/router.test.ts`——路由表结构断言（`/` 在 access 域文件导出中、router.routes 长度与汇总一致）。
5. 绿：建 `src/router/routes/access.ts`（导出 `accessRoutes: RouteRecordRaw[]`，暂装 Home 组件——组件替换是 T2 的事）；`router/index.ts` 改为汇总各域数组（一行一域注释标明「I1 各线在此追加域」）。
6. 回归：web 11 全绿。

**验收**：全量绿；grep 确认 endpoints.ts 已删、main.ts 无直接域注册；routes/index.ts 每域一行。

## T2 F-03 登录与接入页

**测试先行**（vitest environment=jsdom + @vue/test-utils，先加 devDeps 与 vitest.config 调整——纯函数测试文件不动 include 规则，环境按文件级 `// @vitest-environment jsdom` 注释分流，避免拖慢既有 11 个纯逻辑测试）：
1. 纯函数红→绿：`api/access.ts` 的 `statusLabel`（demo 八状态中文映射全集）、`statusBadgeClass`（ACTIVE 绿 / PENDING 系黄 / REJECTED 系红）、`parseStateJson`（外部对象不可信容错——字段缺失/类型错归一为安全默认）。
2. 组件红→绿：`AccessStatusCard`——传入 fixture 各状态（NEW/PENDING_REVIEW/APPROVED/ACTIVE/REJECTED/REVOKED/ERROR + 未登录 + 登录未激活）断言徽章文案/类名、拒绝原因块、锁定提示块、心跳行格式；`AccessActions`——显隐矩阵（demo 布尔式照搬：登录按钮 !authenticated、重提 NEW|REJECTED|ERROR、心跳 ACTIVE、重置 REJECTED|ERROR、登出 authenticated）+ 各按钮触发对应 API 调用（fetch mock 断言 method/path）。
3. 视图红→绿：`AccessView` 挂载 → 拉取 `/api/state`（mock）渲染状态卡；PENDING_REVIEW 态 5s 轮询触发（vi.useFakeTimers）/ unmount 停止；轮询失败降级文案。登录按钮点击 → `window.location.href` 置 `/auth/login`（jsdom 下断言赋值）。
4. session store 骨架：`stores/session.ts`（state 形状 + fetchState 动作 + authenticated getter）——T3 守卫消费它，本任务先立骨架（含 store 单测）。
5. 组装：`router/routes/access.ts` 的 `/` 换挂 AccessView；Home.vue 删除（其 healthz 消费由 AccessView 顶部小徽章承接 + T4 顶栏承接，纯函数与 11 测试保留）。
6. 回归：web 全绿（11 + 新增）。

**验收**：`bun run --cwd workbench/workbench-web test` 全绿；手动 dev 抽查（vite 起 + 代理目标无服务时显示不可达徽章而非白屏）。

## T4 F-04 顶栏全局态

1. 纯函数红→绿：`interpretPlatformStatus(stateJson, stateFetchOk)`——ACTIVE+心跳新鲜（阈值 90s，常量）→ 'ok'；ACTIVE 但心跳陈旧 → 'stale'；REVOKED → 'revoked'；未激活各态 → 'inactive'（中性不告警）；fetch 失败 → 'unreachable'。`alertBanner(status)`——仅 unreachable/revoked 出告警条文案（D-032 提示不降级）。
2. 组件红→绿：`TopBar`——用户区（首字母圆徽 + name/email，未登录显示「未登录」）；平台状态徽章；版本行（复用 versionLineGated + fetchHealthz，接入页同款 2s 轮询迁此）；检查更新占位按钮（点击 → 提示条「检查更新功能即将上线」）；告警条条件渲染断言（unreachable/revoked 两态 + 正常态不渲染）。
3. 组装：Layout 顶栏换 TopBar；session store 扩展心跳刷新动作（沿 /api/state 轮询，节奏与顶栏健康轮询合并为一个 interval）。
4. 回归：web 全绿。

**验收**：mock ACTIVE fixture 顶栏绿徽章无告警条；mock fetch 失败 → 告警条常驻；版本行非健康态「版本未知」。
