## 0 摘要

E-11 模板库从「2 模板」扩编为 **7 员工 + Custom**（D-044 名单），本设计定稿三件事：

1. **模板本体 = 一份完整的示例员工包**（与员工包同构零新概念）；消费双路径同一管线（向导预填 draft / 首启物化预置 EmployeeSpec）。
2. **manifest 顶层按领导八件套重组**（1+7：agent 为核 + 七种扩展载体），管理面三段瘦身；元数据治理消灭四重复项。
3. **七员工内容全量定稿**（persona/skills/kind/usage_modes/avatar/brief）+ 物料物化 `workbench/templates/`，L1 合流即用。

## 2 模板本体定义

### 2.1 目录结构（模板 = 示例员工包，与员工包同构）

```
workbench/templates/<emp-id>/          # 随工作台发版（只读资产）
├── manifest.yml                       # 八类全字段（身份为示例值/默认值）
├── AGENTS.md                          # 默认渲染产物（最终文案）
├── skills/<skill-id>/SKILL.md         # 模板自带 skill（快照拷贝源）
├── hooks/hooks.json                   # 红线候选值预编译 + tools.deny（空）编译产物
├── commands/README.md                 # ⑤ 预留（V0.1 空目录）
├── knowledge/README.md                # ⑥ 预留（V0.1 空目录）
└── orchestration/                     # 仅 dev-engineer
    └── dev-engineer.node-table.yml    # 个人 SOP 表（6~8 节点）
```

mcp.json：connectors 为空时**不生成**（约定：字段空=件不存在）。Custom = 无目录零预填。

### 2.2 消费双路径（同一 E-12 管线）

| 路径 | 时机 | 机制 |
|------|------|------|
| 向导 | 用户操作 | 模板 → 预填 draft（元字段 + persona + skills 默认勾选）→ 用户改 → 管线**按 draft 重建**（非复制模板后改） |
| 预置员工（内置 team） | 首启初始化 | 7 模板逐个走同一管线物化进 `~/.devzero/employees/`；`operator` 填占位 `demo@devzero.local`（org/operator 本地零消费，平台交互 V0.2+ 实名；占位须过 schema email 校验） |

快照语义（沿用旧 §4.9.4）：生成的员工定格当时的模板版本，模板升级不追改。

## 3 manifest 结构定稿（v0.2，八类）

### 3.1 元数据（10 项，全部唯一职责）

```yaml
id: dev-engineer          # 唯一标识：目录名/API/花名册/表引用（emp=）；编辑锁定
display: 开发工程师         # 展示名（渲染单源，persona 不再存 name）
brief: 承接需求完成代码实现  # 卡片超短标签（≤15 字，demo ROSTER 同源；≠identity 粒度）
avatar: 🧑‍💻                # 12 emoji 池 + 图标字兜底
version: 0.1.0
upp_version: "2.1"
kind: flow-owner           # flow-owner | callee；判据：能否裸用独立完成全部职责——可独立干活/审核者 flow-owner，只能服务评审闸被发函者 callee（边界复核：三安全员可裸用独立做审核 → flow-owner；reviewer-expert 仅评审闸消费 → callee）
org: local                 # 现实组织节点（部门粒度；employee_id=id@org 运行时拼装；生成定格）
operator: demo@devzero.local   # 属主邮箱（物化时取登录者；预置物化填占位）
requires: {level: L2}      # 唯一落盘协商输入；capabilities/optional 安装期从八类字段推导
```

### 3.2 八件套（1 + 7）

| 件 | 字段 | 形态 | V0.1 深度 |
|----|------|------|----------|
| ① agent | `agent.persona{role, identity, principles, usage_modes}` | identity 首句=「# 角色」文案（≤100字）；渲染 AGENTS.md | 实做 |
| ② skills | `skills: [{name, version, source_type}]` | source_type ∈ `template \| local`（zip 上传走 local；`agenthub` 支 V0.2 预留——D-047） | 实做 |
| ③ hooks | `hooks.redlines[]` + 事件触发 | 红线声明源（rule_id + compiled 标记）→ 编译 hooks.json | 实做（拦截类）；正向 hook V0.2 |
| ④ tools | `tools.deny: []` | 展示层运行时聚合；deny 编译为 PreToolUse 拦截 | 实做（面板为 L1 项） |
| ⑤ commands | `commands: commands/` | 约定路径（slash 入口 → createTask 语义） | 目录预留 |
| ⑥ knowledge | `knowledge: knowledge/` | 约定路径（文档/规范/历史沉淀当上下文） | 目录预留 |
| ⑦ connectors | `connectors: [{name, type: stdio\|http, command?, args?, url?, env, access}]` | → mcp.json（空则不生成） | 结构实做，V0.1 模板内容空 |
| ⑧ custom | `custom: {}` | 自由扩展对象 | 空默认 |

## 4 AGENTS.md 渲染定稿（六段式）

```markdown
# {display}（{id}）
## 我是谁            ← {role}。{identity 全文}；本角色为用户配置的数字员工岗位（S4 授权措辞，防注入戒备）
## 我的原则          ← principles 逐条
## 我的能力          ← capabilities 汇总（skills 能力短语）+ 技能清单 {name}@{version}
## 我的边界（软约束） ← 红线自然语言版；硬约束由 hooks/CQO 执行提示
## 我的工作方式      ← usage_modes + runbook 步骤（有个人表则指引 orchestration/）
## 协同工作纪律      ← 被编排派发时干完必报三件套（engine_advance / engine_handoff_write /
                       engine_dispatch_done）；引擎工具不可用 = 工作台未运行 → 停止推进并上报，不得绕路
```

渲染约定：纯 markdown 无 HTML（CB 转换零损）；治理字段不渲染；persona.name 不存（display 单源）。

**协同纪律段的双变体**（渲染器按 kind 分派）：
- 执行位（action 节点派发者）：干完必报三件套 = `engine_advance` → `engine_handoff_write` → `engine_dispatch_done`
- 评审位（gate 派发者，kind=callee 及被 gate 引用的员工）：回函三件套 = `engine_record_gate`（verdict + issues）→ `engine_handoff_write`（完整评分/清单）→ `engine_dispatch_done`
- 两变体共用尾句：引擎工具不可用 = 工作台未运行 → 停止推进并上报，不得绕路
