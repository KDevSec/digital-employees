## 0 摘要

本线交付员工域「从无到有」全链：**schema 真源（zod）→ 构建管线（draft 驱动重建）→ 创建向导（七步 UI）→ skill zip 上传 → 预置物化（内置 team 吃狗粮）→ 物料实施批**。核心架构事实三条：

1. **生成即保存**：「生成员工包」= 原子落盘到 `~/.devzero/employees/<emp-id>/`（temp 写全 → rename），保存不是出口选项而是生成本体；花名册是扫描派生视图，无第二真源。
2. **模板只是预填源**：向导 draft 是管线唯一输入，E-12 按 draft 重建（非复制模板后改）；预置物化与向导走同一管线，产物完全同构。
3. **目录边界红线**：本线写域止于 `~/.devzero/employees/`、`~/.devzero/templates/custom/`、temp——🔴 禁写 `~/digital-staff/`（Deployment 运行目录归 L2 安装器）。

- schema 内容**逐字段照 v0.2 设计稿 §2/§3 落**（含 fable 修复批两处：template_id optional、frontmatter vendored_from/license）——不重新设计，实现稿即设计稿

## 5 E-12 构建管线（任务 2，service `src/employees/` 域）

**模块划分**（纯函数 + 目录操作注入，便于 vitest 离线测）：

| 模块 | 职责 |
|------|------|
| `store.ts` | 员工库路径解析（profileDir 注入）/ id 冲突预检 / 原子落盘（temp 写全 → rename；失败回滚丢弃 temp，报具体路径） |
| `renderer.ts` | AGENTS.md 六段式渲染（§5.1） |
| `hooks-compiler.ts` | manifest redlines(compiled) + tools.deny → hooks.json（§5.2） |
| `builder.ts` | 管线编排八步（§5.3），产出文件清单 |
| `scanner.ts` | 花名册扫描（employees/*/manifest.yml → 卡片数据；坏 manifest 跳过并在响应标注） |
| `templates.ts`（src/templates/） | 模板库读取：内置 `workbench/templates/`（随发版只读）+ `~/.devzero/templates/custom/` 扫描聚合 |

### 5.1 AGENTS.md 渲染（六段式，双变体按 kind 分派）

段序：我是谁 / 我的原则 / 我的能力 / 我的边界（软约束）/ 我的工作方式 / **协同工作纪律**。渲染约定：纯 markdown 无 HTML（CB 转换零损）；治理字段不渲染；persona.name 不存（display 单源）。

- 末段双变体（员工模板设计 §4）：执行位（action 派发）= 干完必报三件套 `engine_advance` → `engine_handoff_write` → `engine_dispatch_done`；评审位（gate 派发，kind=callee 及被 gate 引用者）= 回函三件套 `engine_record_gate` → `engine_handoff_write` → `engine_dispatch_done`
- 共用铁律尾句：引擎工具不可用 = 工作台未运行 → 停止推进并上报，不得绕路
- 我的能力段：capabilities 汇总（derive.ts）+ 技能清单 `{name}@{version}`；我的边界段：红线自然语言版（规则库描述表）
- 快照测试锚：模板物料 7 份 AGENTS.md 与「manifest 走渲染器」输出一致性（员工模板设计 §9 验收 2 落地——渲染器按模板 manifest 重渲须与物料 AGENTS.md 一致）

### 5.2 hooks.json 编译（一个编译器两件语义，T9）

- 输入：`hooks.redlines[]`（compiled:true 者）+ `tools.deny[]`
- 输出：PreToolUse 条目数组；命令格式（W3 规范锚）：`"${DEVZERO_HOOKS_ROOT}/redlines/run-hook.cmd" <rule_id>.py`，timeout 5s
- 规则→matcher 映射：no-push-to-main→Bash；no-devzero-state→Write|Edit|MultiEdit|Bash；no-external-request→Bash/WebFetch（按规则库定义表）；tools.deny 的工具名→对应 matcher 逐条拦截
- 产物 description 标注「由 devzero 从红线声明编译生成，请勿手改」；红线脚本本体（redlines/ 目录）随包物化（§10）
- 无 compiled 红线且 deny 空 → 不生成 hooks/hooks.json

### 5.3 管线八步（draft 驱动重建）

```
draft（向导表单态/预置物化源）
→ ① validateManifest（schema + 六跨字段规则；422 逐项 + step 定位回传）
→ ② 渲染 AGENTS.md（六段式，kind 分派）
→ ③ 生成 manifest.yml（yaml dump，八类 key 顺序；operator=登录邮箱，无登录态用占位；id 冲突预检）
→ ④ skills 物化：source_type=template → 模板库快照拷贝（版本定格）；
                  source_type=local → 上传 temp 拷贝（缺失 → 报「skill X 需重新上传」）
→ ⑤ hooks/hooks.json 编译（§5.2）+ redlines/ 脚本本体随包
→ ⑥ mcp.json（connectors 非空才生成；凭证环境变量占位不落明文）
→ ⑦ orchestration/<id>.node-table.yml（模板自带个人表则拷贝；无则省略）
→ ⑧ 原子落盘：temp 目录写全 → rename 至 employees/<id>/ → 返回 {package_path, files[], manifest}
```

- **版本替换语义**：编辑出新版只替换 `employees/` 内 spec；已装 Deployment 标「版本落后」等重装，不自动同步运行目录（安装侧归 L2）
- **目录边界红线**（守卫测试断言）：全程写域 = employees/ + templates/custom/ + tmp/；`~/digital-staff/` 零写入
- 构建同步实现（V0.1 包体量小）；workers.json 账本不进本批（S 系列接入留后续）

## 8 E-13 skill zip 上传（任务 4）

`POST /api/skills/upload` 流程：

```
multipart zip
→ 解包防护：zip-slip 路径穿越检查（entry 路径不得逃逸目标目录）/ 解压大小上限 / 文件数上限
→ 布局兼容：根目录有 SKILL.md，或唯一顶层目录下有 SKILL.md（sec 两 zip 实物即参照）
→ frontmatter 校验：skillFrontmatterSchema（name=目录 slug、description ≥10 字、可选 vendored_from/license）
→ 版本锁定：zip 无版本语义 → 服务端分配（Q2，plan 阶段定：frontmatter 扩展键优先，缺省 0.1.0）
→ temp 物化：~/.devzero/tmp/skills/<name>/（生成管线④消费；向导会话生命周期）
→ 返回 {name, version, source_type:'local', origin: <zip 文件名>, sha256}
```

- sha256 记录取向：溯源与展示（V0.1 不做持久缓存——重建包提示重传，沿 v0.1 详细设计「local 导入 → 提示重传」口径；分工表「缓存物化」的完整形态留 V0.2）
- 分工口径注记：功能点分工总表将 zip 上传服务标为仇伟涛，本线按开工任务指令划入（向导主路径依赖，等外部服务阻塞）——以本 spec 为准，合流时分工表刷新
