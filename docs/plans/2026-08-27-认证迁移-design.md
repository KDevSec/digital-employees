## 4. 契约层设计

### 4.1 Res/Ctx 扩展（registry.ts 类型 + hono-adapter.ts 单点落）

```ts
// registry.ts
export interface Res {
  status: number
  json?: unknown
  text?: string
  html?: string
  redirect?: string        // 3xx Location（A-02 登录跳转/回调落地）；与 json/html/text 互斥
  cookies?: ResCookie[]    // Set-Cookie 指令（建会话/清会话），adapter 逐条 append
}
export interface ResCookie {
  name: string
  value: string
  maxAgeSeconds?: number   // 缺省 = 会话 cookie；清除用 0
  httpOnly?: boolean
  sameSite?: 'Strict' | 'Lax'
  path?: string
}
export interface Ctx {
  method: 'GET' | 'POST' | 'PUT'
  path: string
  host: string
  body?: unknown
  cookies?: Record<string, string>   // adapter 单点解析 Cookie 头（demo cookies() 函数迁入）
  query?: Record<string, string>     // adapter 单点解析查询串（/auth/callback 消费 code/state）
}
```

adapter 行为：
- `resToResponse(res)`：`redirect` 存在 → `Location` 头 + 空 body（status 由 handler 显式给 302，adapter 不猜）；`cookies` 逐条 `Set-Cookie` append（序列化 `name=value; Max-Age=N; HttpOnly; SameSite=Strict; Path=/`，按 ResCookie 可选项拼）
- `parseCookies(header)`：demo 原实现迁移（split/trim/decodeURIComponent/filter）
- Host 白名单守卫先于一切（不变，S-12）

### 4.2 鉴权档位（A-08；详设 §10.2「业务模块只声明档位，不自己写鉴权」）

```ts
// registry.ts
get/post/put(path, handler, opts?: { auth?: 'session' | 'session-active' })
export type SessionGuard = (ctx: Ctx, grade: 'session' | 'session-active') => Promise<Res | null>
// hono-adapter.ts
toHonoApp(registry, opts?: { sessionGuard?: SessionGuard })
```

- 执行点：adapter dispatch 内、Host 守卫之后、handler 之前；`route.auth` 存在则调 guard，返回非 null Res 即短路返回（401/403）
- guard 实现（app/platform-access，框架无关）：**开发环境（`isDevEnvironment` 同一判据）→ 全放行**；生产语义 → 无有效会话 401 `{error:{code:'PERSON_SESSION_INVALID', message:'请先使用企业账号登录'}}`；`session-active` 档再加 state 非 ACTIVE → 403 `{error:{code:'ENROLLMENT_NOT_ACTIVE', message:'终端实例尚未激活，请先完成接入审批'}}`
- `session-active` 档本线只建机制（V0.1 无消费端点，E/B 线声明即用）
- 会话数据不入 Ctx：各域经注入的 `readPersonSession(ctx)` 获取（demo personSession 迁移，未登录返回 undefined 不抛）；`/api/state` 会话可选语义照 demo

## 5. 核心域逻辑设计

### 5.1 crypto.ts（随迁，零语义变更）

PKCE S256 / ES256 JWK 对生成 / private_key_jwt assertion（iss=sub=workbenchId，exp 2m，jti）/ enrollment proof JWT（绑 challenge/nonce/installation）。demo crypto.spec.ts 三测随迁。

### 5.2 加密存储与密钥（A-06）

- `EncryptedJsonStore<T>`：demo `EncryptedStateStore` 泛化——AES-256-GCM（envelope v1：version/iv/tag/ciphertext，base64url）、scrypt 派生密钥（盐 `digital-employees-workbench-state-v1` 沿用）、原子写（tmp + rename，0600，目录 0700）、ENOENT → load 返回 undefined（损坏 → 抛错）
- **加密密钥首启随机生成**：`loadOrCreateAuthSecret(authDir)`——读 `auth/state.key`；无则 `base64url(randomBytes(32))` 生成落盘（0600）。**demo 的 `WORKBENCH_STATE_SECRET` 环境变量默认值绝不带入**（A-06 硬约束）；测试经构造参数直接注 secret（随迁测试零改动）
- `WorkbenchStateStore`：`loadOrCreate()` 首启生成 ES256 密钥对；**`installationId` 字段从 state 中删除**——外部注入 `getOrCreateInstallationId(profileDir)`（service.json uid 同源，详设 §6.1「A 系列消费」；**偏差落档 #8**）
- WorkbenchState 形状（迁移后）：`{ privateJwk, publicJwk, enrollmentId?, workbenchId?, status(八态), lastHeartbeatAt?, rejectionReason?, error? }`

### 5.3 SessionStore（A-07 新增）

- 落盘 `auth/sessions.enc`（同一加密机制/同一密钥文件）：`Record<sessionId, { accessToken, claims, expiresAt }>`
- 单用户多会话并存（多浏览器 cookie 隔离，设计 §7）；读取时惰性清过期项
- `get(sessionId)`（过期返回 undefined 并清理）/ `set(sessionId, session)` / `delete(sessionId)`
- 过期对齐平台 token 效期：`expiresAt = now + expires_in*1000`；cookie `MaxAge = expires_in`（浏览器与服务端同步过期）
- 重启免重登：构造时 load；登出删记录 + `Set-Cookie` 清除（`maxAgeSeconds: 0`）

### 5.4 PlatformClient（随迁 + 三处适配）

- 构造改 `new PlatformClient(getBaseUrl: () => string, deps?: { fetchImpl, version })`——**运行时读配置**（PUT `/api/config/platform` 后即时生效，D-049 语义）
- `workbench_version`：demo 硬编码 `'0.1.0'` → `brand.version` 注入（**偏差落档 #12**）
- `display_name`：`Workbench ${id.slice(0,8)}` → **`终端 ${id.slice(0,8)}`**（品牌 §4，平台管理端可见名称；**偏差落档 #11**）
- internal/public URL 拆分与 `OIDC_INTERNAL_ISSUER` **不迁移**（V0.1 服务装机用户机器，单地址直达；compose 内网直连是 e2e 时代工作台形态——**偏差落档 #6/#7**）
- `PlatformError`（status/code/message）与 `request()` 错误归一（HTTP_x 回退）原样迁移

### 5.5 OIDC 流（A-01/A-02）

- `OidcFlowStore`：内存 `Map<state, {verifier, nonce, createdAt, configuration}>`；5min TTL、**取出即删**（单次使用）；create 时机会式清扫过期项（demo 只增不删的轻微泄漏修正）
- discovery 文档获取 + `document.issuer === issuer` 校验（demo oidcDocument 迁移，去掉 internalize）
- code 换 token（authorization_code + PKCE verifier）；id_token 验签：`createRemoteJWKSet`（jose 内建 JWKS 缓存）+ `jwtVerify`（issuer/audience/nonce）+ **`clockTolerance: 120`**（设计 §7；demo 未设——**偏差落档 #2**）
- `redirect_uri` 从请求 Host 推导：`http://${ctx.host}/auth/callback`（Host 已过 S-12 白名单，可信；支持 localhost/127.0.0.1 两种访问形态）——**验收环境需 Keycloak redirect 白名单含 19990**（见 §9.3）
- **发现配置缓存（A-01）**：discover 成功 → 原子写 `auth/platform-config.json`（明文，非敏感：五个端点字段 + 来源 baseUrl）；`/auth/login` 时 discover 失败 → 回退缓存，**仅当缓存的 `platform_base_url` 与当前配置 baseUrl 归一化后相等**（去尾斜杠后全等；防平台迁移后误用旧缓存指向旧 Keycloak）；无可用缓存 → 503 `PLATFORM_UNREACHABLE`（取代 demo 的 500）

### 5.6 EnrollmentService（A-03/A-04 编排迁移）

- `submitEnrollmentIfNeeded(person, state)`：demo 原样迁移——已有 enrollmentId 且非 REJECTED/ERROR → 查询既有申请（**COMPLETED + workbenchId → ACTIVE 的状态分离修复原样保留，含注释**）；查询失败 → 重置回 NEW 重提；否则提交新申请（幂等）
- `acquireAndHeartbeat(state, configuration)`：机器 token → 心跳 → `lastHeartbeatAt` + `ACTIVE` 落盘（demo 迁移；机器 token 改经 MachineTokenManager 缓存）
- `progress(person)`：demo `/api/progress` 编排——无 enrollmentId → 409 `ENROLLMENT_NOT_FOUND`；查询状态 → APPROVED → challenge/proof/complete 换 workbenchId；COMPLETED + workbench_instance_id → 补记 workbenchId；随后 acquireAndHeartbeat
- `reset()`：清 enrollmentId/workbenchId/status→NEW/lastHeartbeatAt/rejectionReason/error；**保留 installationId + 密钥对**（D-am2）

### 5.7 机器 token 与心跳（A-05）

**MachineTokenManager**：机器 token（5min，scope `workbench.heartbeat`）缓存 + 剩余效期 < 30s 时重签（private_key_jwt）+ **单飞**（并发请求合并为一次获取，A-Q4）；demo 每次心跳重签 token 的浪费行为按设计 §2.3「到期前自动刷新」修正。

**HeartbeatScheduler**（后台定时，demo 手动按钮 → 自动化——A-05 核心增量）：
- `ensureRunning()` 幂等启动：`state.workbenchId` 存在才起（服务启动时 + 激活成功后各调一次）
- 周期 60s；失败退避 2s/4s/8s/16s/32s 封顶（A-Q2 临时立场），成功回 60s；**持续失败不放弃**（设计 §2.5 恢复即自动恢复）
- 单跳 = 取机器 token（缓存）→ POST heartbeat → 更新 `lastHeartbeatAt` + `status:'ACTIVE'` 落盘
- **REVOKED 近似映射**：心跳应答 401/403 → `status:'REVOKED'` 落盘（顶栏告警数据源，设计 §2.3）；精确错误码映射留联调裁（**偏差落档 #10**）
- `stop()`：优雅退出挂接（详设 §14 通知后台任务停）
- 实现 setTimeout 链（非 setInterval，退避需要）；`tick()` 暴露为可测单元；定时器逻辑薄，vitest fake timers 覆盖

### 5.8 错误处理

`errorRes(error)` helper：PlatformError → 其 status/code/message；其他 Error → 500 `WORKBENCH_ERROR`（demo 错误中间件迁移）。全线端点 catch 后归一为 `{error:{code,message}}`。
