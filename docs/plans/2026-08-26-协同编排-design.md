## 0. 摘要

本设计定稿「内置 team 协同编排执行」的实现级方案：**五阶段（准入-需求-设计-开发-准出）流程由引擎真实推进（非手写账本）、7 员工内置团队全自动/手动双深度驱动、任务看板实时可视化**。三大结构性升级相对 1.0：

1. **编排=代码，智能=LLM，兜底=人**——LLM 主控会话被 service 内确定性驱动器取代（node-table 是有限状态机，调度不需要 LLM）；LLM 只保留在干活（员工会话）与评审（gate verdict），spawn runner 做手脚；人工闸停靠可对话式放行（底座会话）。
2. **通道=MCP 回报 + SSE 推送**（spike 已实证 CB/Qoder/CC 全通）——引擎在 service 进程内单点写账本，员工经 MCP 工具自报推进，看板经 SSE 消费事件。
3. **契约三件套**（node-table / events / SSE）本文档定稿，I0-4 落仓真源，此后只在 main 变更。

token 消耗相对 1.0 CLI 派单的三层根因全部消除：主控不持有全表（nextStep 最小返回）、成员产出不回灌（handoff 文件 + summary）、无 LLM 常驻（驱动器查表循环零 token；LLM 仅员工干活 + gate 评审会话按需 spawn）。

## 3. 架构总览

### 3.1 组件全景

```
workbench-service（19980 常驻进程）
├─ engine（TS 纯库，@devzero/engine，D-017）   R1/R2/R3 + 账本 + 表快照
├─ HTTP API（hono）                             发起任务/查询（看板 + 降级写面）
├─ /mcp 路由（@hono/mcp，受控例外口）           引擎工具面（员工回报通道，spike 实证）
├─ /api/engine/stream（SSE）                    事件推送 → 看板
├─ ★ driver 确定性驱动器（TS 模块）             事件订阅 → 查表决策 → 派发/收尾（无状态）
└─ ★ spawn runner（TS 模块）                    launch(deployment,…) → spawn 底座 headless 会话 → 进程管理

本机员工侧
├─ ~/digital-staff/<host>/<emp-id>/             员工 home：config 域（身份锚）+ memory + sessions
├─ <workspace>/.devzero/tasks/<task_id>/        活动任务账本（引擎单点写）
├─ <workspace>/.mcp.json                        引擎连接器（发起任务时落位）
└── 被 spawn 的底座 headless 会话               cwd=工作区，身份经 CLAUDE_CONFIG_DIR 注入

操作入口（三入口同一引擎 API 面）：底座会话（对话式，主推）/ 看板 UI / devzero CLI（V0.2+）
```

### 3.2 「派单」的实质变化（与 1.0 对照）

1.0 CLI 派单是一个动作（主控会话内 Task dispatch，派发+干活+回灌同上下文）；2.0 拆为两半：**记账**（dispatch 事件 → 引擎账本 → 看板动画）走 MCP；**工作触发**走 spawn runner 自动 spawn（L1）或人开成员会话（L0 fallback）。主控从头到尾不经手工作内容。

| 1.0 全家桶插件 | 2.0 归宿 |
|---|---|
| 引擎 ieidev_core（Python） | service 内 engine（TS 纯库） |
| HUD 看板 | 工作台任务看板（SSE） |
| flow-driver skill（LLM 剧本） | service 内 driver（确定性代码） |
| 5 角色 agent 定义 | 每员工独立员工包（独立安装/卸载） |
| orchestration/*.node-table.yml | 工作台内置 flow 模板库（跨员工 team flow） |

「team」在 2.0 是**组合关系不是交付单元**：team = node-table（emp/reviewer 字段引用员工）+ 被引用员工集合；V0.2 群组功能再正式化团队资产。

### 3.3 一次 demo run 全剧本（L1 自动）

```
【发起】看板「发起任务」：选 demo-flow（team）→ 底座 → 模型（留空走默认）→ 工作区 → 需求文本
  → createTask：建工作区账本目录 + 表快照 + .mcp.json + TASK.md/AGENTS.md 引用 + run.created 事件
【准入】driver 查表首节点 n-adm(emp=sec-compliance) → dispatch-start → spawn 安全员会话
  → secretgate 扫描输入 → advance/…/dispatch-done → 会话退出
【需求】driver 续派 req-clarifier → 干活自报 → g-req-review(reviewer=评审专家) spawn 评审会话
  → record_gate verdict → PASS 推进 / FAIL reflow 重派
【设计→开发】同构：sys-engineer → g-design-review + g-sec-design(sec-design·sec-scan-design)
            → dev-engineer → g-code-review + g-sec-code(sec-code·sec-scan-code)
【准出】n3-sec(emp=sec-compliance·检查点占位) → n-done
【收尾】completeTask → run.completed → 归档搬运 → 看板全绿
```

## 5. 驱动形态（β-lite 双层）

### 5.1 驱动器事件循环（无状态、确定性、可恢复）

```
on run.created   → 查表首节点：action(emp) → dispatchStart + spawn 会话
on dispatch.done → 查表推进情况：
                     action(下段 emp=Y) → dispatchStart(Y) + spawn Y
                     gate(reviewer=R)   → dispatchStart(R) + spawn R 评审会话
                     terminal           → completeTask + 归档
on gate.recorded → 引擎已自动 advance/reflow（零动作）；FAIL reflow 到 action → 重派修复会话
on confirmGate   → 清停靠 + advance → 续派
on spawn 失败/超时 → 重试 1 次 → 仍失败：任务 blocked + 看板黄条 + resume 通道
```

驱动器无状态：全部决策从「表快照 + 任务状态」纯派生，事件处理幂等——崩溃恢复 = service 重启后重新订阅、从当前状态续推（M3 崩溃恢复验收锚 U7）。

### 5.2 spawn 细则

```
launch(deployment, workdir=任务工作区, prompt=渲染后节点指令, permission=预配放行, model/effort=解析结果)
CC 系命令形：env CLAUDE_CONFIG_DIR=<员工 config 域> + cwd=<工作区> + <cli> -p "<prompt>" -y …
· prompt 走文件中转不进 argv（防 .CMD 垫片截断多行）
· spawn 前置 healthz 自检（工具在会话启动时注册——spike 顺序约束）
· 超时/退出异常 → Windows 进程树清理（TerminateProcess 语义，孤儿回收）
· 归档/改名用 replace + 代际新文件名
```

评审会话 prompt 模板（引擎内置，非表配置）：

> 你是员工 `{{reviewer}}`，被派执行闸 `{{gate}}` 评审。读 `{{workspace}}/.devzero/tasks/{{task_id}}/handoffs/` 与相关产物，按闸覆盖范围（`{{covers}}`）给出 PASS/FAIL + issues，调 `engine_record_gate` 回报，然后 `engine_dispatch_done`。

### 5.3 人工闸（gate_paused + 对话式放行）

- advance 进入 `human_gate=true` 节点 → 引擎自动置 `gate_paused`（transition 事件带 status 快照，看板零额外拉取）
- 放行 = `confirmGate` 操作（approve→advance 后继 / reject→回流或停留；actor=human 记入事件）
- **主通道 = 底座会话对话式**：工作区 .mcp.json 连引擎 + `.devzero/TASK.md` 可发现（§9.6）→ 人在任务工作区开任意底座会话（qodercli/codebuddy，无需员工身份）说「批准」→ 会话 LLM 读 TASK.md 发现 gate_paused → 调 `engine_confirm_gate`。看板审批按钮为辅。
- 底座会话即 V0.1 的「对话界面」（白皮书 §4.1⑥ V0.2 能力的零成本先行）

### 7.2 flow-state.json（单级 task 模型）

```json

  "status": "in_progress", "current_node": "n1-design",
```

- 状态集：`in_progress | gate_paused | blocked | completed | aborted`（gate_paused 为人工闸停靠态）

### 7.3 events.jsonl（六类事件 + OTLP span 基因）

| type | 触发 | 载荷要点（通用壳之外） |
|---|---|---|
| `run.created`★ | 发起任务 | flow/title/workspace/display_name |
| `run.completed`★ | complete | final_node/duration_s |
| `run.aborted`★ | abort | final_node/reason |
| `transition` | advance（1.0 原生） | from/to/reflow/forced_fail/reason/**status**（推进后状态快照） |
| `gate` | record-gate（1.0 原生） | gate/kind/node/verdict/iter/**reviewer**/issues/request_id |
| `dispatch` | dispatch-start/done（1.0 原生，phase 区分） | phase/emp/dispatch_id/node/status/usage |

通用壳：`{seq, ts, type, trace_id, parent_seq, actor, …payload}`——snake_case 对齐 1.0。handoff 不进事件流（文件真源，看板详情经 API 查）。

**span 基因**（裁决 10）：`trace_id`=task_id（run 贯穿，跨系统聚合锚）；`parent_seq`=父事件行号（因果链：advance 指回触发它的 dispatch.start，gate 指回评审派发，段间 dispatch 接力成链）；`seq`=行号（1-based，SSE 重放锚）。**OTLP 路径**：基因现在埋（丢了补不回来）、全量 span 格式不做（无消费方且破坏 cat/grep）、导出器（扁平行→OTLP span→Honeycomb/管控平台）V0.2+ 接。团队共享不共享账本本体：工程记忆走记忆仓同步（1.0 ieidev-sync 模式）、任务数据走平台聚合（白皮书 §7.3「运行数据上报 OTLP 不可关闭」）。

### 7.4 与 1.0 差异清单

① 账本位置（工作区 .devzero/ 热账本 + ~/.devzero/archive/ 冷归档，取代 1.0 单一 .ieidev/）② 单级 task 取代 feature 两级 ③ +3 类 run 生命周期事件（1.0 HUD 轮询弥补）④ +seq/trace_id/parent_seq ⑤ gate 事件 +reviewer ⑥ 虹吸机制取消（1.0 write_state 内存增量虹吸进 events 的两文件一致性复杂度 → 2.0 引擎单进程**先 append 事件、再写状态**，「事件丢一行可容忍、状态文件是真相源」原则保留）。

## 12. 工程注意项

### 12.1 Windows spawn 坑（1.0 四连修前车之鉴，spawn runner 必修）

| 坑 | 1.0 症状 | 对策 |
|---|---|---|
| npm .CMD 垫片 | 多行 -p prompt 首个 \n 截断，worker 只收首行 rc=0 假成功 | 解析垫片直连 node/js；或 prompt 文件中转（本设计已选） |
| Path.rename 撞占用 | Windows 目标存在即抛；杀软/资源管理器持句柄任意久 | replace + 代际新文件名（.r2.*），别跟占用较劲 |
| 观战流持句柄 | tail 流攥文件致续跑无法归档 | 读文件流不持句柄 |
| python3 Store 占位符 | 静默 rc=49 零输出假成功 | 解释器探测 + spawn 后产物自检 |
| 半推进状态 | confirm 不看闸标记删除结果照样推进 | 删除停靠标记失败必须拒绝推进 |
| 错误只 toast 一次 | resume 失败人不在场看似成功 | 错误常驻卡面 |

### 12.2 MCP spike 输入（全部实证锚）

① MCP server 不再是路线图风险项（I3 回写移除）② 员工会话权限模式必答（§9.2）③ 工具会话启动时注册→spawn 前置 healthz、service 重启窗口期在跑会话引导重开 ④ AGENTS.md 健壮性指令「引擎工具不可用=工作台未运行→停止推进并上报，不得绕路」（实证模型会自作主张降级）⑤ 多客户端 per-session transport 是 L3 实现设计点（spike 未压测）⑥ 降级语义：service 死→停跑上报不降级 curl；HTTP 回报真正价值=未来底座不支持 MCP http 形态。
