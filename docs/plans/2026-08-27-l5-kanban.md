## 执行纪律

- 每任务严格 TDD：先写失败测试（红）→ 最小实现（绿）→ 重构；subagent 每任务收尾跑 `bunx vitest run`（workbench-web 目录）确认不破基线
- 提交节奏：每 1~2 任务一个 commit（feat(webs): KB-xx 前缀）；**web-dist 不提交**（feature 分支纪律）；每 2~3 天向 main 小合流
- 品牌硬规则随时自查：文案「终端」不用「工作台」、无 DevZero 字样（CLAUDE.md §4）
- 契约歧义不自创接口（design §10 六条）；发现新歧义记 design 文档追加，不现场发明

## 任务序列（依赖序）

### T1 事件类型与帧解析（api/engine-events.ts）
- **测试先行** `test/engine-events.test.ts`：
  - 六类事件类型守卫矩阵：合法载荷（对齐 design §3.1 逐字段）逐类通过；缺字段/错类型拒绝且**不抛异常**（归一 ok:false）
  - 帧解析 `parseSseFrame({event, data, id})`：六类 type 正常出事件；未知 type 兜底分类；坏 JSON 容错；缺 id → seq=-1
- **实现**：判别联合类型 + `isEngineEvent` 守卫 + `parseSseFrame`
- 依赖：无（叶子）

### T2 表快照与四剧本（fixtures/demo-flow.table.ts + scenarios.ts）
- **测试先行** `test/scenarios.test.ts`（剧本自检 = 契约消费者侧锚）：
  - 四剧本（happy-path / gate-pause / reflow / abort）：seq 1-based 连续、trace_id 全 = task_id、parent_seq 引用合法（< 自身 seq 或 null）、首事件 run.created、终事件 run.completed|run.aborted、六类载荷字段完备
  - happy-path：12 节点全链——每 action/gate 节点有 dispatch(start/done) 配对、transition 链首尾相接（n-adm→…→n-done）、5 个 gate PASS
  - gate-pause：变体表、停靠 transition 带 status:'gate_paused'、人工 gate 事件 actor:'human' + verdict:'approve'
  - reflow：FAIL gate + transition reflow:true 回 n2-impl + 重派 dispatch、iter 递增
  - abort：dispatch done status:'error' + run.aborted reason
- **实现**：`demoFlowTable`（§6.1 十二节点）、`demoFlowGatePauseTable`（n0-req human_gate:true）、`employees` 七员工映射、`buildScenario(name, opts)` 纯生成器（ts 等差递增；节奏归 mock source）
- 依赖：T1

### T3 SSE 消费层（fixtures/mock-event-source.ts + api/engine-stream.ts）
- **测试先行** `test/engine-stream.test.ts`：
  - 帧分发：mock source 推六类帧 → onEvent 依序收到六事件；`:ping` comment 不出事件
  - 连接状态机：构造 → connecting；open → live；error → reconnecting；close() → closed 且不再收事件
  - seq 去重：replayFrom(seq) 重放已见帧 → onEvent 不重复派发
  - factory 注入：断言自定义 factory 被调用且 URL 正确（含 ?task_id= 拼接）
- **实现**：`MockEventSource`（队列/节奏/pause/resume/simulateError/replayFrom）+ `createEngineStream`
- 依赖：T1、T2（mock 推帧用剧本片段亦可手造小帧集）

### T4 归并 store（stores/kanban.ts）
- **测试先行** `test/kanban-store.test.ts`：
  - applyEvent 单事件矩阵（design §5.1 七行语义逐条）

  - 混流：两任务事件交错 → 各自状态正确（task_id 分拣）

- **实现**：`applyEvent` 纯函数 + `useKanbanStore`（defineStore，setup 风格对齐 stores/session.ts）
- 依赖：T1、T2

### T5 派生层（stores/kanban.ts 内导出 deriveBoard 或独立 derive.ts）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 契约歧义（design §10 六条）联调时形状变化 | fixture 收敛单文件；getTask/剧本生成器改一处即全量测试跟随 |
| EventSource 真机行为与 mock 有偏差 | T3 状态机只依赖 readyState/onopen/onerror 标准面；live 模式预留 ?live=1 手测通道 |
| jsdom 无滚动/动画 | 动画为 CSS 类名断言（不测视觉效果）；视觉走查归 T11 手动 |
| placeholder.test.ts 耦合 kanban 占位 | T8 随路由替换同步改写，保持三域占位测试语义不破 |
