## 4. 协调规则（多人多机并发）

1. **契约只在 main 变更**：E-01~03（员工域产出，shared-protocol 包本体在 L1 分支）、契约三件套 node-table/events/SSE（已随 L3 落 main ✅）；各 worktree 只消费，变更走设计修订记录。
2. **D 号防撞（硬规则）**：决策记录现至 **D-061**；下一真号 ≥D-062（A 线 D-am1~4 转号优先占用）。各线 design 用占位号，**合流 main 时统一编真号**。本线占位 **D-bb01**（底座 CLI 探测 / 真模型 / npm 安装）。
3. **worktree 纪律**：每人每域一个 worktree/分支；端口为单机纪律（新线先 netstat 探）；系统级集成测试只在 main 做。
4. **web-dist 不提交**（feature 分支）；合流 main 时统一重建提交。
5. **合流节奏**：每 2~3 天向 main 小合流一次，禁止长漂移；合流顺序：文档线 → 契约产出线 → 消费线。
6. **品牌规范**：Web 正式名称一律「研发零处数字员工终端」，DevZero 仅内部代号——照 [CLAUDE.md §4](../../CLAUDE.md)。
7. **素材交接面**：素材（persona/ROSTER/skills 拆定）→ 田装配进模板库；skill 获取服务对能力组装步骤只暴露服务接口。
8. **远程同步**：main 已与 origin/main 对齐（认证线推送 365af0f 起）；平台侧机器持续推平台域——合流前先 fetch。

## 5. 与在线表的维护约定

- 在线表 = 日常状态勾选处（⬜→✅ 由责任人随手更新）；
- 本表 = 版本化快照，每迭代合流时由协调人（李）刷新一次并提交；
- 行结构变更（新增/修订 AR）先改本表（走仓库评审），再同步在线表，避免在线表成为无版本事实源。
