# 真安装包设计（Inno Setup）——数字员工工作台分发形态升级

> 2026-08-25 brainstorm 产物。上游裁决链：托盘单实例修复（836a027）完成后，用户裁决分发形态从「绿色制品 + install.ps1 轻量安装脚本」直接升级为**真安装包（setup.exe）**。

## 1. 背景与目标

| 维度 | 现状（V0.1） | 目标 |
|---|---|---|
| 制品形态 | 三 exe 绿色兼容（workbench.exe / workbench-daemon.exe / workbench-tray.exe） | 不变（绿色兼容性保留） |
| 正式分发路径 | install.ps1 安装脚本（落盘 + 计划任务 + 快捷方式 + 起托盘） | **Inno Setup 安装包 setup.exe**，install.ps1 退役 |
| 卸载 | 手工说明（stop → 删目录 → 删任务） | 「设置 → 应用」原生卸载入口 |
| 升级（U-03） | 手动重跑脚本 | 双击新 setup.exe 覆盖升级，中断窗口 ≤ 15s |

三制品分工不变：服务（workbench.exe）+ 守护变体（workbench-daemon.exe，GUI 子系统防黑窗）+ 托盘壳（workbench-tray.exe，含单实例 + 唤醒重定向）。

## 2. 裁决记录（2026-08-25，用户逐项裁决）

| # | 议题 | 裁决 | 要点 |
|---|---|---|---|
| 1 | 安装路径边界 | **C：setup.exe 单一路径 + 静默参数** | install.ps1 退役删除；开发者用 `/VERYSILENT` 同一路径，不维护两套落盘逻辑 |
| 2 | 卸载数据去留 | **B：卸载时询问，默认保留** | 数据含登录态/机器密钥/工程记忆；MsgBox 询问「是否同时删除」，默认否；静默卸载零弹窗走默认；显式清除通道 `/DELETEDATA=1` |
| 3 | 升级恢复语义 | **B 修订版：服务恢复与用户解耦** | 落盘完成后 `ssPostInstall` 立即起托盘+服务，不等用户点完成；完成页复选框仅控制「打开工作台页面」（开浏览器）；中断窗口 ≈ 5–8s |
| 4 | R-2 签名策略 | **A：接受 SmartScreen 弹窗** | 零成本路线：安装说明预告 + 平台 sha256 核对；构建链预留 signtool 挂点（`WORKBENCH_SIGN_CERT` 环境变量存在才签名）；平台 `signature_status` 如实报 UNVERIFIED，证书是后续版本的独立花钱决策 |
| 5 | 安装器选型 | **Inno Setup** | per-user / 快捷方式 / 覆盖升级 / 静默安装四个核心诉求原生声明式支持；唯一妥协 = 卸载数据询问降级为 MsgBox（NSIS 为此一个界面手搭全套不值；WiX 对单用户桌面工具 YAGNI；MSIX 强制签名与裁决 4 冲突，排除） |
| 6 | 安装目录 | **固定不可改**（`DisableDirPage=yes`） | `%LOCALAPPDATA%\Programs\workbench`（与 install.ps1 一致，老用户原地升级零迁移）；计划任务/Run 键/快捷方式引用的绝对路径永远不变，升级 = 原地换文件 |
| 7 | 图标 | **临时占位** | `workbench-installer/assets/workbench.ico`；用户后续生成正式图标同路径覆盖，iss 零改动 |

**端口边界澄清**：安装阶段的端口风险由装前优雅 stop 消除（服务退出即释放 19980）；装后启动若遇**第三方**占用 19980，属服务运行期端口冲突语义（§7.4 裁决：退出码 78 + 诊断），不在安装器责任边界。

**发布卡口豁免**：「VersionInfo 不泄露构建工具」继续约束三制品；setup.exe 携带 Inno 编译器签名，豁免该卡口（安装器是分发载体非业务制品）。

## 3. 工程结构

```
workbench/workbench-installer/
├── workbench.iss                # Inno 脚本：固定 AppId GUID、PrivilegesRequired=lowest、
│                                #   DisableDirPage、中文向导、SetupIconFile=assets/workbench.ico
├── assets/
│   └── workbench.ico            # 临时图标（裁决 7：同路径替换即换标）
└── scripts/
    ├── build-installer.sh       # bash 构建（对齐 build.sh / build-tray.sh 形态）
    └── installer-smoke.sh       # 安装包冒烟（§6）
```

## 4. 构建链（build-installer.sh）

1. **前置检查**：三制品已在 `workbench-service/dist/`（不代跑上游构建，与 build-tray.sh 依赖 build.sh 产物的形态一致）；`iscc.exe` 不在 PATH 时报清晰错误并退出
2. **版本注入**：读 `workbench-service/package.json` 的 `version` → `iscc /D` —— 安装包版本 = 服务主版本线；壳版本独立线（W-12）不进安装包版本
3. **编译产物**：`dist/workbench-setup-<version>-x64.exe` + 同名 `.sha256` 文件（平台上传 U-02 校验直接消费）
4. **signtool 挂点**：`WORKBENCH_SIGN_CERT` 存在才调 signtool，否则跳过（裁决 4 预留位）

工具链依赖：构建机一次性安装 Inno Setup（不进 git）；与现状无 CI、本地 bash 构建形态一致。

**中文向导**：官方 SimplifiedChinese 语言文件；InfoBeforeFile「安装前须知」页承载 SmartScreen 预告 + sha256 核对说明。

**平台对接（U-01/U-02/U-03）**：运营手动上传 admin 端点（os=windows、arch=x64、version、sha256、signature_status=UNVERIFIED）——V0.1 不做上传自动化；工作台 UI 检查更新 → 引导下载 → 校验 sha256 → 用户手动执行，全程不静默替换（既有裁决）。

## 5. 三大行为语义

### 5.1 安装（首装 + 覆盖升级同一路径）

| 步骤 | 行为 | 说明 |
|---|---|---|
| 1. 装前清理 | `[Code] PrepareToInstall`：healthz 可达 → `workbench.exe stop`（等 ≤2s）；杀残留托盘（解文件锁） | install.ps1 重装健壮性段（2c7f3fb）翻译 |
| 2. 落盘 | 三制品 → `{localappdata}\Programs\workbench` | 固定路径（裁决 6） |
| 3. 系统集成 | 清 user-stopped 哨兵 → 快捷方式（[Icons]，指向托盘 exe）→ 计划任务 **Force 重建**（PowerShell 单次 exec：每分钟触发器 + 四反直觉默认值覆写 + `__daemon` 变体，逐字翻译 install.ps1；重建不跳过——新版任务设置演进不被旧装机残留拖住） | 哨兵清除 = 安装意图要运行 |
| 4. 立即恢复 | `ssPostInstall` 后台起托盘 → 启动即活拉服务（裁决 3：与用户解耦） | 中断窗口结束点 |
| 5. 完成页 | 复选框「打开工作台页面」默认勾 → 开浏览器；`/VERYSILENT` 按默认勾执行 | 仅控制浏览器，不控制服务 |

**中断窗口预算**（裁决 3）：stop(≤2s) + 落盘(<1s) + 集成(1–3s) + 服务冷启动(1–2s) ≈ **5–8s**，与用户手速无关。

### 5.2 升级

用户从平台下载新 setup.exe → 双击 → 5.1 全流程（步骤 1 自动停旧版、步骤 4 自动恢复）。安装器不感知「升级 vs 首装」。

### 5.3 卸载

1. 前置：`workbench.exe stop`（落哨兵，守护不复活）→ 杀托盘 → `schtasks /Delete /TN WorkbenchDaemon /F` → 删 HKCU Run 键 `WorkbenchTray`（对齐壳侧 W-16 双侧注销）
2. 数据询问（裁决 2）：交互模式 MsgBox「是否同时删除用户数据（登录态 / 密钥 / 工程记忆）？」默认否；静默卸载零弹窗走默认保留
3. 显式清除：命令行 `/DELETEDATA=1` = 连 `~/.workbench` 一起删

**冒烟 installer-smoke.sh**（真 setup.exe 全链，场景化风格对齐 tray-smoke.sh）：

| 场景 | 动作 | 断言 |
|---|---|---|

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 构建机需装 Inno Setup | 一次性安装不进 git；iscc 缺失时 build 脚本报清晰错误 |
| 覆盖升级服务中断 5–8s | 单机工具可接受；不做热替换（D-l 无 bootstrapper 既有裁决覆盖）；冒烟 S2 硬断言看住 |
| SmartScreen 弹窗（未签名 + MOTW） | 裁决 4：说明预告 + sha256；signtool 挂点已预留 |
| 卸载 MsgBox 体验不够优雅 | 已知妥协（裁决 5 接受）；NSIS 换血不划算，留 V0.2+ 若有强诉求再评估 |

## 9. 平台边界（用户问询 2026-08-25：是否牵连其他 OS 重新设计）

本设计 = **Windows 分发层 + 系统集成层**的设计，不牵连其他 OS：

- 服务本体（服务/CLI/编排/记忆）跨平台、托盘壳业务内核（状态机/契约/菜单模型）平台无关——均零触碰
- 平台差异被压缩在「分发 + 系统集成」层：Inno/per-user 免 UAC/计划任务/HKCU Run 全是 Windows 专属机制
- 既有裁决：D-h（Linux 无托盘壳）、darwin 托盘变体归 0.2
- 将来扩 OS = 增量新增「分发层设计 B（Linux：tar.gz + systemd user unit + .desktop，无 GUI 层反而更简）/ C（macOS：.app bundle + launchd + dmg）」，本设计不被推翻

## 10. 明确不做（YAGNI）

- 上传平台自动化（运营手动上传）
- 热替换/差量升级（D-l：无 bootstrapper）
- 代码签名（独立花钱决策，后续版本裁决）
- MSIX / 组策略部署（无此场景）
- 安装目录可选（裁决 6 固定）
- Linux/macOS 分发（§9：增量设计，非本设计范围）
