# 管理平台 V0.1 开发交接上下文

**更新时间**：2026-08-16
**代码仓库**：`qhdhuowen/digital-employees`
**当前分支**：`main`

## 1. 已完成范围

已按 brainstorm → spec → decisions → plan → tasks → TDD → verify 完成管理平台 V0.1：

- `platform/backend/`：FastAPI 模块化单体、PostgreSQL/Alembic、Keycloak OIDC BFF、六固定角色与四类数据范围、包管理、审计、设置、接入审批、ES256 持钥证明、`private_key_jwt`、短期机器 Token、心跳和撤销。
- `platform/frontend/`：公开下载首页及总览、工作台、接入申请、审计、安装包、权限配置、平台设置页面。
- `workbench/`：Node/TypeScript 最小登录认证 Demo，包含 PKCE、加密本地状态、接入申请、持钥证明、机器认证和心跳，不包含业务功能。
- `iam/`：Keycloak 26.7 Realm、组织属性、OIDC Client、服务账号及 PostgreSQL 初始化。
- `tools/`：Compose、构建、启动、停止、健康等待、单测和真实 Playwright E2E。

公开首页和已发布安装包下载按需求保持匿名；上传、发布、下架、审批、撤销和管理功能均要求对应权限。

## 2. 认证与默认账号

验收环境默认密码由用户指定为 `Horse~test@2026`。

| 账号 | 用途 |
|---|---|
| `system.admin` | 首次登录自动成为系统管理员 |
| `platform.admin` | 可由系统管理员授予平台管理员 |
| `department.admin` | 可授予部门管理员及部门集合范围 |
| `security.admin` | 可授予安全管理员及域范围 |
| `audit.admin` | 可授予审计管理员及域范围 |
| `employee` | 普通员工/工作台登录 |
| `admin` | Keycloak master Realm 管理员，不是管理平台人员账号 |

人员身份以 `(issuer, sub)` 稳定映射；平台浏览器不保存 OIDC Token，只保存 HttpOnly opaque BFF Cookie。工作台为 Public Client，不保存 Client Secret。

## 3. 动态外部地址

硬编码 `192.168.153.128` 已替换为方案一：显式 `PUBLIC_HOST`。

```bash
PUBLIC_HOST=<虚拟机IP或DNS名> ./tools/up.sh
```

也可复制 `tools/.env.example` 为被 Git 忽略的 `tools/.env`。命令行值优先。当前机器的本地 `tools/.env` 使用 `192.168.153.128`，仅供当前人工验收，不进入提交。

启动工具会：

1. 校验 `PUBLIC_HOST`；
2. 通过 Compose 派生平台、Keycloak、工作台和 issuer；
3. 等待真实服务健康；
4. 通过 Keycloak Admin API 幂等同步已有 Client 的 Redirect URI/Web Origin；
5. 输出三个可访问地址。

生产演进使用稳定域名、DNS、HTTPS 反向代理和固定 Keycloak hostname，详见 `docs/design/管理平台V0.1部署与外部访问设计.md`。

## 4. 测试与验证

主要命令：

```bash
./tools/test-unit.sh
PUBLIC_HOST=<当前可达IP> ./tools/test-e2e.sh
```

E2E 不拦截路由、不伪造 Token、不预写业务结果，真实启动 Keycloak、PostgreSQL、平台和工作台。测试覆盖：

- `system.admin` 管理平台 OIDC 登录；
- 匿名实际包字节下载及上传/发布/下架权限；
- `employee` 工作台 PKCE 登录、申请、审批、challenge、ES256 proof；
- `private_key_jwt`、真实机器 Token、心跳、在线状态、撤销后拒绝；
- 五类管理员和普通员工真实登录与导航权限。

`tools/test_external_access.py` 使用两个不同 `PUBLIC_HOST` 值验证 Compose 的全部公开 URL 派生，并验证 Realm 占位符与本地配置优先级。

## 5. 已解决的重要问题

- Docker daemon 曾因代理配置无法拉取；用户已恢复 Docker systemd 环境。后续不得修改 OS、Docker、代理或防火墙设置。
- 根分区空间不足时，按用户明确批准清理了 npm/pip/Mozilla/DNF/PackageKit 缓存、旧 journal、可重建 Python 环境、`/root/rpmbuild` 和 `/root/works/openssl`。
- PostgreSQL 18 数据卷必须挂载 `/var/lib/postgresql`。
- Nginx SPA 配置曾缺失站点 root，已修复。
- Uvicorn 默认访问日志会记录 OIDC Authorization Code，生产入口已使用 `--no-access-log`，业务审计不记录 Token、Cookie、私钥、challenge 或完整 JWS。
- 前端 Nginx 也会把 OIDC Authorization Code 记录在回调 URL 中，已仅对精确路径 `/auth/callback` 关闭 access log，其他访问日志保留。
- 接入申请增加数据库唯一约束和并发冲突回读，401/403 失败进入脱敏审计。
- 特殊字符数据库密码的 `%40` 会触发 Alembic INI 插值，迁移配置已进行 `%` 转义。
- 固定 IP 导致物理机跳转失败，现由 `PUBLIC_HOST` 统一派生并同步 Keycloak Client。
