## 1 定位与范围

### 1.1 定位

定义**工作台（本地）↔ 管控平台（远端）**之间的账号体系与信任链：邮箱登录、JWT 双 token 生命周期、设备绑定，以及治理分级 L1-L4 与平台 RBAC 的对齐模型。同时覆盖**浏览器 ↔ 工作台本地服务**这一段的本地安全边界（它不是"登录"，但属于认证链路的最后一环）。

### 1.2 范围内 / 不做什么

范围内：邮箱+验证码登录（主）与可选密码（辅）；token 签发/刷新/吊销/存储；设备注册与多设备管理；平台 API 鉴权约定（401/403/429 处理）；OTLP 上报专用凭证；治理分级 L1-L4 权限矩阵与上架审批路由、市场可见性过滤、工作台 UI 显隐；离线降级。
不做：❌ 平台侧账号服务的内部实现（存储/发码通道，Q-007）；❌ 企业 OIDC SSO 的完整设计（mg-org 显示"已接入"，本文只留对接扩展位）；❌ 组织架构同步协议（HR 系统，平台侧规划中）；❌ 员工包签名的 PKI 细节（Q-004 立场：平台上架统一签名，本文只定义公钥获取端点的鉴权）。

### 1.3 账号模型前提（Q-005 立场）

**单用户多设备**：一个邮箱账号可登录多台工作台（每台一个 device_id）；一台工作台同时只登录一个账号（切换账号=登出再登）。工作台本地数据（roster/安装清单/记忆）归属机器而非账号——换账号登录不清空本地员工（治理归属以 operator_id 区分，UI 提示）。

## 2 用户旅程

### 2.1 首次启动与登录

```
安装工作台 → `ieidev-workbench start`
  → CLI 打印：本地地址 http://localhost:19820 + 一次性配对码（6 位，防本机他人抢连，§4.4）
  → 浏览器打开 → 输入配对码 → 建立本地会话（此后该浏览器免配对）
  → 未登录态首页：顶栏灰条「未登录管控平台——本地功能可用，市场/上架不可用；本机尚未注册设备，遥测上报不可用 [登录]」
  → 点击登录 → 登录页：
      输入邮箱 → [发送验证码]（60s 冷却）→ 输 6 位码 → 登录
      （首次登录即注册；可选勾选"同时设置密码"）
  → 成功：平台签发 access + refresh token；工作台注册设备（hostname/OS/版本 → device_id）
  → 顶栏变绿：头像 + 邮箱 + 所属部门（组织架构接入后）
```

### 2.2 日常与静默续期

- 启动时：读安全存储中的 refresh token → 静默刷新 access → 登录态直达。
- access 过期（≈1h）：任一平台调用 401 → 自动 refresh → 重放原请求（对用户无感）。
- refresh 过期/被吊销：顶栏灰条「登录已过期，请重新登录——本地功能与遥测上报不受影响」；OTLP 上报凭独立遥测 token 继续（§4.3），仅市场/上架类操作不可用。

### 2.3 登出与多设备管理

- 工作台「设置→账号」：登出（本机 token 作废并请求平台吊销）/ 查看本设备信息。
- 平台侧「组织权限→我的设备」（原型 mg-org 范畴）：设备列表（名称/OS/工作台版本/最后活跃/IP 摘要）+ 远程吊销（该设备 refresh 全家族失效，下次调用强制重登）。

### 2.4 密码路径（可选辅助）

设置密码后：登录页出现「密码登录」切换；连续 5 次失败锁 15 分钟并强制回验证码路径；忘记密码=验证码登录后重设。企业接入 OIDC 后（扩展位）：登录页出现「使用企业账号登录」按钮，走平台侧 OIDC 流程后同样落到本设计的 token 体系（token 签发层与登录方式解耦）。

### 2.5 离线旅程（Q-002/Q-008 立场）

| 平台状态 | 工作台行为 |
|---------|-----------|
| 不可达 ≤7 天（宽限期） | 登录态 UI 保持（缓存身份），本地功能全量；市场/上传置灰"平台不可达"；OTLP 本地缓冲（events.jsonl 本就落盘，补传游标记录待传位点） |
| 不可达 >7 天 | 登录态标"待重新验证"（不清 token，恢复连接后静默刷新验证）；治理分级 L1/L2 员工的编辑操作提示"无法同步审批，变更将在恢复后提交" |
| 恢复连接 | 补传缓冲（限速）；刷新 token；同步审批/市场状态 |

## 3 信息架构与界面设计

### 3.1 登录页（工作台内嵌页，非独立站点）

| 元素 | 说明 |
|------|------|
| 邮箱输入 | 格式校验；企业域提示（配置了企业域白名单时，非白名单域给黄条提示但不阻断） |
| 发送验证码 | 60s 冷却倒计时；调 P1 接口；错误映射（429→"请求过频"） |
| 验证码输入 | 6 位分格；5 次错误锁定 15 分钟（服务端判定） |
| 密码切换 | 仅当该邮箱已设密码（P2 探测接口返回 has_password）才显示 |
| 服务条款/隐私 | 链接占位（企业内部署可配置隐藏） |
| 登录后跳转 | 回到触发登录的上下文（如上传流程中途登录，回到上传确认步） |

### 3.2 设置 → 账号页

登录身份卡（邮箱/部门/角色徽章）· 本设备卡（device_id 摘要/注册时间/token 状态）· 操作（登出/复制诊断信息）· OTLP 上报状态（上报中/缓冲中 n 条——与看板观测边界卡同数据源）。

### 3.3 权限驱动的 UI 显隐（消费 §4.6 矩阵）

| 界面元素 | 所需权限 | 无权限表现 |
|---------|---------|-----------|
| 创建向导·治理分级选择器 | 角色可建等级上限（个人开发者→治理分级 L4/L3；团队负责人→治理分级 L3 并拥有其审批权；部门管理员→治理分级 L2；平台管理员→治理分级 L1） | 超限卡片置灰+"需 XX 角色" |
| 上传到 AgentHub | `market:publish` | 按钮置灰+登录/权限提示 |
| 市场浏览/安装 | `market:read`（登录即有） | 未登录：市场入口显示登录引导 |
| 详情页·权限与治理 tab 的治理字段编辑 | 治理分级 L1/L2 需对应管理员角色 | 只读+锁标 |
| 审计数据查看（平台侧） | 合规审计员 | 平台侧控制，工作台不出入口 |
| 底座/安装/对话/看板等本地功能 | 无需平台权限 | 永远可用（含未登录） |

## 4 数据模型

### 4.1 实体

| 实体 | 关键字段 | 归属 |
|------|---------|------|
| 账号 User | user_id / email / has_password / org_node（部门/团队）/ roles[] | 平台 |
| 设备 Device | device_id / user_id / hostname / os / workbench_version / created_at / last_seen / revoked | 平台（工作台持有自己的 device_id） |
| Token 对 | access(JWT) + refresh(不透明串) | 签发：平台；持有：工作台后端 |
| 本地会话 | browser session cookie + csrf token | 工作台本地 |

### 4.2 JWT 设计

- **签发与验证**：平台 RS256 签发；工作台经 JWKS 端点（P0）缓存公钥本地验签（离线宽限期内凭缓存判定）。
- **Claims**：

```json
{
  "iss": "https://platform.example/auth", "sub": "u_8f3k2",
  "email": "ly@corp.com", "device_id": "d_a1b2c3",
  "roles": ["developer"], "org": "dept-rd/team-pay",
  "scope": "market:read market:publish telemetry:write registry:write",
  "iat": 1765600000, "exp": 1765603600, "jti": "…"
}
```

- **有效期**：access 1h；refresh 30d **滚动轮换 + 一次性使用**（每次 refresh 返回新对并作废旧 refresh；检测到旧 refresh 复用 → 判定泄露，吊销该设备全家族并通知）。
- **时钟偏移**：验签容忍 ±120s；工作台启动时与平台对时（响应头 Date），偏移过大给诊断告警。

### 4.3 Scope 定义

| scope | 授予 | 用途 |
|-------|------|------|
| `market:read` | 登录即有 | 市场浏览/skill 搜索/下载（K1-K5） |
| `market:publish` | 登录即有（发布行为的治理约束走审批流，不靠 scope 收紧） | 上传（K6）/审核查询（K7） |
| `telemetry:write` | 登录即有 | OTLP 上报 |
| `registry:write` | 登录即有 | AgentCard 注册/注销 |
| `admin:*` 族 | 管理员角色 | 平台侧管理操作（工作台不使用） |

**OTLP 专用凭证**：设备注册时同时签发**遥测 token**（有效 90 天、仅 `telemetry:write`、绑定 device_id、可独立吊销）——上报管线不因登录态波动中断（"元数据上报不可关闭"的工程保障），也避免长期缓存高权 token。

### 4.4 存储与本地安全

| 项 | 方案 |
|----|------|
| refresh/遥测 token 存储 | OS 凭据库优先（macOS Keychain / Windows Credential Manager / libsecret）；无凭据库环境降级 `~/.ieidev-workbench/credentials.json`（0600 + 机器指纹派生密钥 AES-GCM 加密，报告降级告警） |
| access token | 仅内存，不落盘 |
| 本地服务绑定 | 仅 `127.0.0.1:19820`；拒绝非 localhost Host 头（**DNS rebinding 防护**：Host 白名单 localhost/127.0.0.1） |
| 浏览器会话 | 首次配对码（CLI 打印，6 位一次性，§2.1）→ 签发 session cookie（HttpOnly + SameSite=Strict）；变更类 POST 带 CSRF token（双提交） |
| token 出域约束 | 平台 token 永不下发到浏览器——浏览器只持本地 session；所有平台调用由工作台后端代理 |

### 4.5 平台 API 鉴权约定（全部平台调用共用）

| 场景 | 约定 |
|------|------|
| 请求头 | `Authorization: Bearer <access>` + `X-Device-Id: <device_id>` + `X-Workbench-Version` |
| 401 | 自动 refresh → 重放一次；再 401 → 进入未登录态 |
| 403 | 不重试；UI 权限提示（含所需 scope/角色） |
| 429 | 指数退避（base 2s，上限 5 次）；UI"平台繁忙" |
| 5xx/网络错误 | 幂等 GET 重试 3 次；写操作不自动重试（入队/提示） |
| 审计 | 所有平台调用记 events.jsonl（adapter.platform_call span，元数据级：端点/结果码/耗时，不含 body） |

### 4.6 治理分级 L1-L4 ↔ RBAC 对齐

**角色集**（对齐 mg-org 原型：平台管理员/合规审计员/资源管理员/部门管理员/业务专家 + 默认"个人开发者"）：

| 角色 | 组织范围 | 关键能力 |
|------|---------|---------|
| 个人开发者 developer | 本人 | 建/装/跑员工；上传治理分级 L4/L3 包；下载可见市场资产 |
| 团队负责人 team-lead | 团队 | + 审批治理分级 L3（团队自审）；团队命名空间管理 |
| 部门管理员 dept-admin | 部门 | + 审批治理分级 L2；部门模板/员工上下架；部门命名空间 |
| 平台管理员 platform-admin | 全平台 | + 审批治理分级 L1；规则/平台配置 |
| 合规审计员 auditor | 审计通道 | 审计中心（独立高权限通道，mg-audit 两档）；不参与业务审批 |
| 资源管理员 resource-admin | 配额/成本 | 配额分配、算力调度、运维监控 |

**上架审批路由**（治理分级 → 审批人）：

```
上传（K6）携带 manifest.governance.level
  治理分级 L4 个人级：不上架市场（visibility=仅自己），上传仅作云备份/跨设备同步 → 免审
  治理分级 L3 团队级：路由 团队负责人 → 通过后上架到团队命名空间
  治理分级 L2 部门级：路由 部门管理员 → 部门命名空间
  治理分级 L1 公司级：路由 平台管理员（+合规扫描强制全过）→ 全局命名空间
  ——审批之前一律先过 AgentHub 机器审核管线（内容安全→依赖扫描→schema→冒烟，mg-market）
```

**市场可见性过滤**：`governance.visibility ↔ 命名空间`同构映射（仅自己→私有 / 团队内→团队空间 / 部门内→部门空间 / 全公司→全局空间）；K1/K4 查询由平台按请求者 org+roles 服务端过滤，工作台不做客户端裁剪（防绕过）。

**审计级别执行**：`governance.audit` 随包上报；平台按 mg-audit 两档模式落库（默认元数据档；全量档需安全团队显式开启+强制脱敏——本文不设计全量档协议）。

## 5 接口契约

### 5.1 工作台内部 API（浏览器 ↔ 本地服务，认证链路最后一环）

| 端点 | 方法 | 请求 → 响应 | 说明 |
|------|------|------------|------|
| `/api/local/pair` | POST | `{pairing_code}` → 200 + Set-Cookie（HttpOnly + SameSite=Strict session） | 首次配对（§2.1）；连续 5 次错误后要求重新生成配对码 |
| `/api/local/csrf` | GET | → `{csrf_token}`（会话内有效） | 变更类 POST 的双提交 token |
| `/api/local/session` | DELETE | → 204 + 清 cookie | 本浏览器断开配对 |
| `/api/local/auth/status` | GET | → `{logged_in, email?, org?, roles?, device_id?, grace_until?}` | 顶栏登录态数据源 |
| `/api/local/auth/login` | POST | `{email, code?/password?}` → 同平台 P2 语义（本地服务代理转发） | 浏览器永不直接持有平台 token（§4.4） |

### 5.2 平台 Auth API（工作台消费）

| # | 端点 | 方法 | 请求 → 响应 | 说明 |
|---|------|------|------------|------|
| P0 | `/.well-known/jwks.json` | GET | → JWKS | 验签公钥（含员工包签名公钥集的引用，K8 复用此机制） |
| P1 | `/api/v1/auth/send-code` | POST | `{email}` → 202 | 发验证码；限流：同邮箱 60s/次、每日 20 次；不泄露邮箱是否已注册（恒 202） |
| P2 | `/api/v1/auth/login` | POST | `{email, code}` 或 `{email, password}` + `{device: {hostname, os, workbench_version}}` → `{access, refresh, telemetry_token, device_id, user:{email, org, roles}}` | 首登即注册；device 首次出现即注册 |
| P3 | `/api/v1/auth/refresh` | POST | `{refresh, device_id}` → 新 `{access, refresh, telemetry_token?}` | 轮换+复用检测；遥测 token 剩余 <30 天时顺带轮换下发（D-Q3） |
| P4 | `/api/v1/auth/logout` | POST | `{refresh}` → 204 | 吊销本设备 |
| P5 | `/api/v1/auth/password` | PUT | `{new_password}`（Bearer） → 204 | 设置/重设密码 |
| P6a | `/api/v1/devices` | GET | → `[{device_id, hostname, os, workbench_version, last_seen, revoked}]` | 设备列表（平台 UI 为主，工作台只读展示本机） |
| P6b | `/api/v1/devices/{device_id}` | DELETE | → 204 | 吊销指定设备（refresh 全家族失效） |
| P7 | `/api/v1/me` | GET | → `{email, org, roles, quota…}` | 启动时身份刷新 |

错误码约定：`401 invalid_token / 403 insufficient_scope / 423 locked（验证码/密码锁定，带 retry_after）/ 426 upgrade_required（工作台版本过旧，见 §7）/ 429 rate_limited`。

## 7 边界情况与降级

| 情况 | 行为 |
|------|------|
| 平台不可达 | §2.5 离线表；本地功能永不因登录态受限 |
| refresh 复用检测触发 | 吊销设备全家族 + 顶栏红条"检测到凭证异常，已强制下线" + 平台侧通知 |
| 系统无凭据库（headless Linux） | 文件降级存储 + 启动告警一次 |
| 时钟严重偏移 | 验签失败诊断信息含"本机时钟偏移 xx s"指引 |
| 多浏览器/无痕窗口 | 每浏览器独立配对（配对码可在设置页重新生成）|
| 邮箱换绑 | 本轮不设计（平台侧账号管理范畴），记开放问题 |
| 工作台版本过旧被平台拒绝 | 426 Upgrade Required → UI 强提示升级（API 版本协商：X-Workbench-Version） |
