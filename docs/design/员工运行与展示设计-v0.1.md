## 1 定位与范围

### 1.1 定位

本文档定义工作台交互前端中"看员工、用员工"的全部界面与状态模型：员工列表页（默认首页）、员工详情页（canonical 10 tab，D-002）、对话界面、任务看板与审批工作台，以及支撑它们的员工状态机、任务模型与数据管线（.ieidev/ 文件 → 本地服务 → SSE → 前端）。

### 1.2 范围内 / 不做什么

范围内：上述四大界面 + 状态机 + 任务三类型 + 会话路由机制。
不做：❌ 群组功能本体（Q-010，仅入口占位）；❌ workflow 编辑器的节点编辑交互细节（引用原型 wb-workflow 形态与 1.0 node-table schema，完整编辑器设计留下一轮）；❌ handoff 4 消息 schema 正式化（交接文档 §5.2）；❌ OTLP span 字段正式化（§5.4）；❌ 工程记忆蒸馏管线（白皮书 §9，使用深度 L2+）。

## 2 用户旅程

### 2.1 日常主旅程

```
打开 localhost:19820（默认首页=我的员工）
  ├─ 看卡片：谁在线、谁在跑、谁停在闸口
  ├─ 点卡片 → 详情页（10 tab 深挖）
  ├─ 卡片「＋对话」→ 对话界面（选/默认工作目录 → 发消息或点任务建议卡）
  ├─ 卡片「＋自动任务」→ 定时任务创建浮层
  └─ 侧栏「任务看板」→ 全局任务视图 → 审批工作台处理人工闸
```

### 2.2 一次对话任务的完整旅程

```
对话界面选中员工 → （可选）选择工作目录（触发当值检查，文档 B §4.6）
  → 点任务建议卡（task_templates 渲染，填变量）或自由输入
  → 发送 → 工作台以员工当值 cwd 启动底座会话（§4.4 会话路由）
  → 流式回显（消息区）+ 任务看板出现"对话任务·进行中"
  → 员工回复/完成 → 任务标已完成，产物链接（diff/文件/报告）附在消息里
```

### 2.3 flow 任务旅程（使用深度 L2）

```
详情页「工作流」tab 或对话内指令 → 选 node-table + 输入任务参数 → flow-driver 启动
  → 看板运行中卡片：节点 chips 逐个点亮（需求澄清→方案设计→…）
  → 到 gate_pause 节点 → 状态"gate 停等" → 审批工作台出现停靠卡
  → 人批准（可附意见）→ 续跑；驳回 → 回流上一节点或终止
  → 终态：已完成（历史任务表）/ 失败（失败任务表，可重跑）
```

### 2.4 异常旅程

| 场景 | 表现与处理 |
|------|-----------|
| 员工所在底座掉线 | 卡片状态变"离线"（灰），在跑任务标"中断"，恢复在场后可续跑（flow-state 未丢） |
| 任务失败 | 失败任务表 + 卡片红点；行内「重跑」（从失败节点续）或「详情」（事件流定位） |
| gate 停等超时 | 停靠卡黄条"已等待 2h 13m"；可配置超时提醒（推送到平台/邮件，扩展位） |
| 版本漂移中的员工 | 卡片黄徽章"版本落后"，点击跳文档 B 漂移矩阵 |

### 3.3 对话界面（基线 wb-chat + QoderWaker 对话界面）

**布局**：左栏（「＋新建群组」置灰占位 + Chat 会话列表：头像 · 名称 · 最后消息摘要 · 时间 · 未读点）｜右侧主区（顶栏 + 消息区 + 输入区）。

| 区域 | 元素 | 行为 |
|------|------|------|
| 顶栏 | 员工名 + 在线徽章；右侧「＋对话任务」「＋自动任务」「任务列表」 | 任务列表=右滑抽屉，该员工任务表（tab③ 复用） |
| 欢迎态 | 头像 + "你好，今天我能帮你什么？" + 一句话自介（persona.identity 首句） + 任务建议卡 ×3 | 建议卡 = manifest `task_templates` 渲染；带 `{变量}` 的卡点击后变量高亮为行内输入框，填完回车发送（"填参一键发起"） |
| 消息区 | 用户气泡（右）/ 员工气泡（左，流式打字）；系统卡片：任务状态变化（"已创建对话任务 #T-88"）、gate 停靠卡（内联审批入口）、产物卡（文件/diff/链接） | 流式来自 §4.4 会话路由 SSE |
| 输入区 | 「选择工作目录」chip（当前 cwd：驻地 或 项目路径）+ 文本框（"输入消息，@ 选择当前工作区上下文…"）+ 模型档位显示（默认档位徽章，点击可临时切换本次会话档）+ 发送 | 切工作目录 → 当值检查（文档 B §4.6 提示流）；@ 弹出工作区文件引用选择器 |

**会话与任务的关系**：自由聊天不建任务；点建议卡或显式「＋对话任务」→ 创建对话任务（进看板）。一个会话可串多个任务；任务在消息流中以系统卡片标记起止。

| 实时事件流 | events.jsonl tail 渲染（时间 · 主体 · 事件一句话），标注数据源徽章「.ieidev/events」 |
| 观测边界卡 | 固定文案：只跟踪工作台注册的工作区与对话；底座内其他无关活动不纳入；OTLP 上报状态（上报中 · 元数据线，不可关闭 · 数据源自 .ieidev/ flow-state+events）；平台不可达时此处黄条"缓冲中 n 条待补传" |

**审批工作台**（人工闸，白皮书 §8.3 human_gate 的 UI 面）：

| 元素 | 内容 |
|------|------|
| 停靠卡列表 | 每卡：任务名 + 员工 + 停靠节点（如"设计评审闸"）+ 等待时长 + 请求摘要（员工提交的决策请求文本）+ 关联产物链接（方案文档/diff）|

| 记录 | 每次审批写 events（gate.human_approval span）+ 任务详情 gate 记录；平台审计中心可见（元数据） |

### 3.5 workflow 页（引用级设计）

沿用原型 wb-workflow 形态：文件名头（`dev-flow.node-table.yml` + 所属员工徽章）/ Canvas·Script 双视图 / 顶部「schema 校验通过」徽章 + 执行记录 + 试运行 / 自然语言生成条（"说出来，就能跑起来"→ 生成 workflow 骨架）。节点类型速查（task / gate_pause 人工闸 / handoff 向 callee 发函 / guard 准入条件）。YAML 本体 = 员工包 orchestration/ 文件（schema 见 1.0 实证格式 + 文档 A §4.8）；编辑保存 = 包变更 → 版本递增提示。完整编辑器交互（拖拽/连线/gate 配置表单）留下一轮设计（本文 8 开放问题 C-Q5）。

## 4 数据模型

### 4.1 员工状态机（D-009：两维正交）

**维度一：可用性**（安装完好性，不是进程存活——使用深度 L0/L1 员工无常驻进程）

| 状态 | 判定 | 徽章 |
|------|------|------|
| 在线 | ≥1 个安装目标满足：底座在场 ∧ 身份文件存在且校验和匹配 | 绿点·在线 |
| 离线 | 所有目标的底座不在场 | 灰点·离线 |
| 异常 | 底座在场但身份文件缺失/被改（校验和不符）或版本漂移 | 黄点·需处理（悬浮说明）；版本漂移场景的显示文案为「版本落后」（§3.1 卡片特殊态即此态） |
| 未安装 | roster 有记录但无任何安装目标 | 灰字·未安装 |

**维度二：工作状态**（任务态聚合）

| 状态 | 判定（flow-state + 会话运行器） | 徽章 |
|------|-------------------------------|------|
| 空闲 | 无 active 任务 | 空闲 |
| 在跑 | ≥1 任务 running | 绿·在跑 n |
| gate 停等 | ≥1 任务 gate_paused（且无 running） | 黄·gate 停等 |
| 失败待处理 | ≥1 任务 failed（且无 running/paused）；该任务被重跑或取消后解除 | 红点·失败 |

聚合优先级（卡片单徽章）：失败 > gate 停等 > 在跑 > 离线 > 空闲；离线且有在跑任务显示「中断」（对齐 §2.4）。详情页页头两维徽章并列展示，可用性异常/离线时工作状态徽章降饱和。

**迁移事件源**：底座探测（60s 轮询+手动）改可用性；events.jsonl 的任务 span（task.start / node.enter / gate.pause / gate.resume / task.done / task.fail）改工作状态。前端经 SSE 增量更新。

### 4.2 任务模型（三类型统一 schema）

```json
{
  "task_id": "T-1042",
  "type": "chat | auto | flow",
  "title": "支付网关对接联调",
  "employee_id": "dev-engineer",
  "base": "claude-code",
  "workspace": "/home/ly/work/pay-portal",
  "source": { "kind": "chat|schedule|flow|group", "detail": "与 frontend 的对话 / cron 表达式 / 群组名" },
  "flow": { "node_table": "orchestration/dev-flow.node-table.yml",
             "run_id": "R-1042", "current_node": "n6b-impl-subagent",
             "nodes_done": 5, "nodes_total": 8 },
  "status": "queued|running|gate_paused|completed|failed|interrupted|cancelled",
  "gate_wait": { "node": "n4-plan-review", "since": "…", "request": "…" },
  "usage": { "tokens": 128000, "duration_s": 2520 },
  "created_at": "…", "last_active_at": "…", "finished_at": null
}
```

> 命名约定（D-015）：`employee_id` 字段取 manifest.id（纯 id，不含域后缀）。

| 类型 | 触发 | 执行形态 | 终态产物 |
|------|------|---------|---------|
| 对话任务 chat | 会话内建议卡/显式创建 | 底座会话（§4.4），单员工 | 消息流 + 产物卡 |
| 自动任务 auto | 定时（cron）/事件触发（扩展位） | headless 底座会话（-p 模式） | 运行记录 + 产物 |
| flow 任务 flow | workflow 试运行/对话内指令/群组（占位） | flow-driver 按 node-table 驱动独立会话链 | flow-state 终态 + delivery_node 交付物 |

**生命周期**：`queued → running ⇄ gate_paused → completed | failed | cancelled`；`interrupted`（底座掉线）可恢复到 running。**重跑**：flow 任务从失败节点续（flow-state 保留，max_retries 约束，超限走 terminal_fail——1.0 语义）；chat/auto 任务整体重跑（新 task_id，标注 retry_of）。

### 4.3 数据管线与 .ieidev/ 布局（工作区/驻地内）

```
<workspace>/.ieidev/
├── features/<slug>/flow-state.json   # flow 任务状态机（引擎写）
├── features/<slug>/events.jsonl      # OTLP span 格式事件（引擎/hook 写，白皮书 §4.3）
├── chats/<session_id>.jsonl          # 对话消息持久化（工作台写）
└── memory/                           # 工程记忆（使用深度 L2+）
```

工作台本地服务聚合：文件 watcher（fs 事件 + 1s 去抖）→ 内存态 → SSE 推前端（`/api/stream` 单通道多主题，topic 命名以 §5 为准：employee_status / task_update / event / approval / chat:<sid>）。前端断线降级为 10s 轮询。跨工作区聚合：roster + duty.json 提供工作区清单，服务端逐一 watch（上限 100 工作区，超限告警）。

### 4.4 会话路由（对话 → 底座执行）

```
用户发送消息
  → 工作台后端解析会话绑定：employee × base × cwd（驻地或项目工作区）
  → 会话运行器（base adapter 提供）：
      CC:        claude -p --output-format stream-json --resume <sid> …
      CodeBuddy: codebuddy -p …（1.0 实证 spawn 路线）
      Qoder:     qodercli 等价形态（V-B2 验证）
  → stdout 流 → 解析 → SSE 推消息区；usage tap → events.jsonl
  → 会话 id 持久化（chats/ 头部），后续消息 --resume 续会话
```

- 模型档位：按 manifest tier-map 的默认对话档（query 档）传 `--model`；输入区临时切档只影响本会话。
- 中断/停止：向运行器进程发停止信号，任务标 cancelled；底座残余进程守护（超时 kill）。
- 安全边界：运行器只在已登记 cwd 启动；命令模板由 base adapter 静态定义，用户输入只作为 prompt 传入（不拼接 shell）。

## 7 边界情况与降级

| 情况 | 行为 |
