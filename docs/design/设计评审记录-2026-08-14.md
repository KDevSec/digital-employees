## 5 发现清单

### R-001 ⏳ P1｜「能力共存」对三层适配性质不同：MCP 层有未讨论的上下文污染代价

- **位置**：文档 B §2.2 / §4.6（当值切换设计）。
- **问题**：当值互斥只解决身份文件（AGENTS.md/CLAUDE.md）冲突；skills/hooks/mcp 命名空间并存、切换当值不增删。但三层性质不同——
  - **skills**：按需加载（description 触发），并存无害 ✅
  - **hooks**：保护性拦截，并存基本无害，但**生效语义未定义**——非当值员工的红线（如 `no-push-to-main`）仍在底座上拦截，用户会困惑"当前员工没勾这条规则为什么被拦"
  - **MCP**：merge 进工作区配置后**底座启动即常驻加载**——多员工并存意味着员工 A 对话时底座还连着员工 B 的 MCP server：工具定义占用上下文、可能调错 connector、凭证环境变量可能互相覆盖
- **建议**：MCP 层随当值切换（或在文档 B 显式讨论该 trade-off 后留档）；hooks 层补一句"非当值员工红线仍生效"的明示（含保留理由）。

### R-002 ⏳ P2｜市场下载 / zip 导入的员工 id 与本地撞车无冲突流程

- **位置**：文档 B §2.1 步骤 [1]（注册花名册）。
- **问题**：D-015 分层后本地一律用纯 id，roster 本地唯一。文档 A 向导路径有重名失焦校验，但**入口②（市场下载）及批注稿新增的外部 zip 导入路径均无 ID 冲突预检**——平台下载 `frontend-dev@部门B` 而本地已有自建 `frontend-dev` 时撞车。
- **建议**：注册花名册前加 ID 冲突预检（改名安装 / 覆盖确认 / 取消）。

### R-003 ⏳ P2｜JWKS 本地验签的威胁模型含混

- **位置**：文档 D §4.2「工作台经 JWKS 端点缓存公钥本地验签」。
- **问题**：工作台是 client 而非 resource server，真正验签方是平台；本地验签唯一可想象的用途是 UI 显隐读 roles claim，而 §4.6 已明确"服务端过滤、工作台不做客户端裁剪（防绕过）"。服务端兜底后本地验签的动机不成立。
- **建议**：澄清动机（如用于宽限期登录态判断则写明）或删除该句，避免多余设计。
