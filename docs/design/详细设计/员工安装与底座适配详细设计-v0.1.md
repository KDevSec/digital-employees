## 1 定位与模块结构

安装 = **文件位置映射**（UPP W-20：第一类适配面 = 向底座约定目录投递文件，不依赖底座插件 API；plugin 后端留 0.2+ 优化，D-014）。安装后底座自行加载运行，工作台不驻留底座进程。

```
workbench-service
├── app/installs/        安装域：协商 -> 落位计划 -> 事务执行 -> 报告 -> 卸载 -> 当值
│   ├── negotiator.ts    能力协商（§3）
│   ├── planner.ts       落位计划（§4 输出）
│   ├── executor.ts      事务执行器（§5）
│   ├── report.ts        安装/卸载报告读写（§6）
│   ├── uninstall.ts     反向清理（§8）
│   └── duty.ts          当值登记与切换（§7）
├── app/bases/           底座域：在场探测 + 底座注册表（§9）
└── adapters/            每底座静态档案 + 转换器（file 后端的底座差异全部收敛于此）
    ├── codebuddy/       capability-profile.yml + transforms
    └── qoder/           capability-profile.yml + transforms（验证后回填）
```

**数据目录**（文件基底，全部在 `~/.ieidev-workbench/`）：

| 数据 | 位置 | 说明 |
|------|------|------|
| 安装报告 | `installs/<employee_id>@<base>.json` | D-008；一份数据三处消费（报告/卸载/版本对比）；employee_id 取纯 id（D-015） |
| 当值登记 | `installs/duty.json` | `(base, workspace) -> {employee_id, installedAt}` |
| 停靠区 | `installs/parked/<id>@<base>/` | 当值切换的旧身份文件暂存（§7） |
| 安装日志 | `installs/logs/<id>@<base>-<ts>.log` | 逐行时间戳 |
| 底座探测缓存 | `bases/<base>.json` | 最近探测结果（mtime 缓存失效） |

> **roster.json 不设**（对上游设计的修订）：花名册 = 扫描 `employees/*/manifest.yml` + 关联安装报告的**派生视图**（见[员工业务详细设计](员工业务与前端详细设计-v0.1.md) §1）——manifest 文件是唯一身份真相源，杜绝双真相源漂移。

## 3 落位映射表（B-01/B-02）

scope 记号：`{ws}` = 项目工作区根 · `{home}` = 员工驻地（`~/.ieidev-workbench/homes/<employee_id>/`，D-013 默认）。**通用原则**：隔离优先（命名空间目录必用，绝不覆盖用户资产；冲突一律走 §5 冲突流程）；幂等（重装同版本 checksum 比对跳过）；全部走 **file 后端**（D-014）。

### 3.1 CodeBuddy CLI（B-01）

| 包内源 | 目标（两种 scope 同构，`{ws}` / `{home}`） | 动作 |
|--------|------------------------------------------|------|
| AGENTS.md | `CODEBUDDY.md`（scope 根） | **convert**（§3.3 转换规则） |
| skills/<n>/ | `.codebuddy/skills/<n>/` | copy（目录整拷） |
| hooks/hooks.json + hooks/redlines/ | merge 进 `.codebuddy/settings.json` 的 `hooks` 键；脚本 copy 到 `.codebuddy/ieidev-hooks/<employee_id>/` | **merge**（JSON 深合并，本员工条目带 `"_ieidev": "<employee_id>"` 撤销标记） |
| mcp.json | merge 进 `.codebuddy/mcp.json` | merge（server 名冲突 -> 冲突流程） |
| orchestration/ · knowledge/ | 不落位（引擎自读包目录 / 后续管线消费） | —— |

> **B-Q1 目录复核**（CB 侧唯一真机验证项）：`.codebuddy/` 目录名、skills 子目录、settings.json/mcp.json 位置——1.0 走 plugin CLI 路线未做裸文件落位。复核方法见 §11。SKILL.md frontmatter 严格 YAML（description 双引号包裹，CodeBuddy 解析器教训）。

### 3.2 Qoder CLI（B-02，设计假设待验证）

| 包内源 | 目标（假设） | 动作 | 验证项 |
|--------|------------|------|--------|
| AGENTS.md | `{scope}/AGENTS.md` | copy（原生读取零转换） | **Q-006**：原生读取实证 |
| skills/<n>/ | `.qoder/skills/<n>/`（假设） | copy | **B-Q3**：skill 目录位置 |
| hooks/hooks.json | Qoder hooks 配置落点（假设 `.qoder/settings.json`） | merge | **B-Q3**：hooks 配置位置 |
| mcp.json | Qoder MCP 配置落点（假设 `.qoder/mcp.json`） | merge | **B-Q3** |

验证失败的处理预案（按验证结果三选一）：① AGENTS.md 非原生 -> 加身份转换器（复用 §3.3 管线，目标名按 Qoder 实际约定）；② 目录不同 -> 改落位表（纯配置级改动）；③ hooks 配置形态不同 -> adapters/qoder/transforms 补 merge 适配。三种情况都不动执行器与报告模型。

### 3.3 AGENTS.md 转换规则（convert 动作，适用 CB 与未来的 CC）

1. 基线 = identity copy（渲染模板刻意只用交集 markdown 特性）
2. 首行追加溯源注释：`<!-- generated by ieidev-workbench from <employee_id>@<version>/AGENTS.md; do not edit by hand -->`——卸载/漂移/接管判定锚点
3. 目标已有**用户手写**身份文件 -> 冲突流程：默认备份后接管（`<name>.bak-<ts>`），用户原文以「项目既有约定」段附录到生成文件尾（不丢规则）
4. spec 分歧适配位：`adapters/<base>/transforms/instruction.ts` 预留，当前为空

## 4 安装执行器（B-03）

**模型**：落位计划（源->目标->动作）+ file 后端 + 事务。上游 §4.5 事务流程原样实现：

```
① 协商（§2）→ ② 生成落位计划（§3 表 + checksum 预计算）
→ ③ 冲突预检（全部落点；用户文件存在/他员工标记/checksum 不符）
→ ④ 写事务日志 installs/logs/…（计划 + 每步意图，崩溃恢复依据）
→ ⑤ 逐项执行：copy/convert 先写临时文件再原子 rename；merge 先备份原文件再深合并
→ ⑥ 全部成功 → 写安装报告（§5）+ 更新 duty.json
→ ✗ 任一失败 → 按事务日志逆序回滚（rename 回退 / 恢复备份 / 删已拷目录）→ 报告 result=rolled-back
```

- **checksum 语义**：单文件 sha256；目录 = 清单哈希（文件列表 + 逐文件哈希的哈希）
- **merge 撤销标记**：settings.json/mcp.json 内本员工条目带 `"_ieidev": "<employee_id>"`，卸载按标记精确摘除
- **子进程账本**：安装/卸载不派生长任务（文件操作同步完成），不写 workers.json；报告与日志落盘即持久

## 5 安装报告（B-04，D-008）

schema 照上游 §4.3（report_version 1）原文实现：`{employee_id, package_version, base, base_version, scope, negotiation{design_level, reachable_level, missing_required, degraded[], warnings[]}, placements[{source, target, action, checksum, conflict}], result, started_at/finished_at, log}`。

- 存储：`installs/<id>@<base>.json`；**多版本历史**：重装新版本时旧报告移入 `installs/history/<id>@<base>/<ts>.json`（E-15 版本时间线数据源）
- UI 双入口：底座与环境页（按底座聚合）/ 详情页 tab⑩ 员工包（按员工聚合）
- **一份数据三处消费**：报告展示 · 卸载清理（placements 反查）· 版本对比（package_version vs 最新包 version -> 「版本落后」黄标，E-10）

## 6 安装作用域与当值（B-07，D-013）

- **两种 scope**：员工驻地 `{home}`（默认，`homes/<employee_id>/`，对话会话以此为 cwd）× 项目工作区 `{ws}`（用户选目录，员工"进驻项目"）
- **身份互斥**：同一 (底座 × scope) 只有一名**当值员工**（身份文件是单一身份源）；**能力共存**：skills/hooks/mcp 按员工命名空间目录并存（切换当值不增删能力文件）
- **当值切换**（`duty.ts`）：

```
switch(base, scope, new_id):
  旧身份文件（含 _ieidev 溯源注释）-> 移停靠区 installs/parked/<old>@<base>/
  新员工身份文件落位（convert/copy）
  skills/hooks/mcp：命名空间目录并存，不动
  更新 duty.json；lifecycle 级日志记 duty_switch
```

- 冲突检测：安装时若目标 (base×scope) 当值非本员工 -> 预检报告列出，用户确认走「切换当值」（install 接口 `conflict_resolutions` 传 `switch-duty`）

## 7 卸载（B-05）

上游 §4.7 数据流，V0.1 调整（无引擎/无平台注销）：

```
输入：安装报告 placements + 残留扫描
① 保护检查：V0.1 无 flow-state/在飞任务 -> 保留接口位（workers.json 活动 + 0.2 会话进程）
② merge 类：按 _ieidev 标记精确摘除（settings.json/mcp.json）；无法解析 -> 报告列"需手工处理"+ diff
③ copy/convert 类：checksum 一致 -> 删；不一致（用户改过）-> 默认保留 + 报告列"检出手工改动，已保留"，可勾选强删
④ 残留扫描：按命名空间约定 glob（.{codebuddy,qoder}/**/*_ieidev*、ieidev-* 目录、溯源注释文件）-> 孤儿文件确认清理
⑤ 卸载报告 {cleaned[], kept[], manual[]}；停靠区该员工文件一并处理
```

**验收**：卸载后底座目录与安装前 diff 干净（除用户数据）；重复卸载幂等（无报告则 no-op）。

## 9 API（installs/bases 域，挂服务本体 §10）

| 端点 | 方法 | 请求 -> 响应 | 说明 |
|------|------|------------|------|
| `/api/bases` | GET | -> `[{id, label, present, version, version_tested, supported, employees_count, last_install_at}]` | 卡片数据（§8.2） |
| `/api/bases/probe` | POST | `{base?}` -> 探测结果 | 手动刷新（缺省全部） |
| `/api/install/plan` | POST | `{employee_id, targets:[{base, scope}]}` -> 每目标 `{negotiation, placements, conflicts}` | **干跑**不落盘（预览/冲突决议收集） |
| `/api/install/execute` | POST | plan 请求 + `conflict_resolutions: {"<target>": "backup-overwrite"\|"skip"\|"switch-duty"\|"cancel"}` -> 每目标安装报告 | 未决议冲突 -> 422 |
| `/api/install/reports` | GET | `?employee_id= \| ?base=` -> 报告列表（含历史版本） | 双入口 |
| `/api/uninstall/plan` | POST | `{employee_id, targets, remove_parked: bool}` -> `{cleanup[], kept_predicted[], manual_predicted[]}` | 卸载干跑 |
| `/api/uninstall/execute` | POST | plan 请求 + `{force: bool}` -> `{cleaned[], kept[], manual[]}` | §7 |
| `/api/duty/switch` | POST | `{base, scope, employee_id}` -> 结果 | §6 |

鉴权 `会话+激活`（服务本体 §10.2）；`/api/bases/register`（自定义底座类型）-> V0.2。
