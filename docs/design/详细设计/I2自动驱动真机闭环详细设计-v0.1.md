**先行底座**：claude-code（用户裁决 A；本机 claude CLI + L2 M2 已实证 config 域身份注入）。

## 4 前置批（P0a/P0b/stdin）

### 4.1 P0a：版本断言按平台分档（阻塞一切 CC 安装）

`/api/bases` 断言 `>= 2.1.245`（S4 Linux 基线）在本机 Windows（2.1.226）误伤 `supported:false`。修正：Windows 分档基线 2.1.226（或下调研证区间）——实现位在 L2 档案/探测断言处（bases 域），改断言常量 + 对应测试。

### 4.2 P0b：packageRoots 接线（execute 端点对任何员工 404）

main.ts `packageRoots: {}` → 映射 `workbench/templates/<emp>`（七员工快照）→ E 系列员工库接管前的装配口径（注释已预留此语义）。

### 4.3 P0c：launch.ts prompt 通道升级 stdin（L2/L3 接口任务，M2 §7.3 点名）

现状：launch.ts 把 prompt 全文压 args + promptFile 仅观测——shell 包装（win32）下多行必截断（坑1 双底座实锤）。升级：prompt 经 **stdin 管道**传输（双底座唯一共同可靠形态）。launch.ts 现实现为 args 数组——升级点：构造 LaunchSpec 时 prompt 走 stdin（写进 spawn 的 input 流），promptFile 保留观测/溯源。

## 5 新资产：simple-flow 简化流程表（demo-flow 不动）

新增预置 **2 张流程表**（展示名「五阶段快速交付」），**5 action + 2 机检 gate + 终点**，**人工评审门禁可配置（表单开关 → 选表）**：

```
simple-flow          全机检版：5 action + 2 gate(全 human_gate:false) + 终点
simple-flow-human    人工闸版：g-exit 置 human_gate:true（准出前人工评审）

n-adm    准入        action  sec-compliance
n-req    需求核验    action  req-clarifier
n-design 设计核验    action  sys-engineer
g-design 设计评审    gate    reviewer-expert   (两表均 human_gate:false 机检)
n-impl   开发实现    action  dev-engineer
g-exit   准出评审    gate    reviewer-expert   (simple-flow-human 置 human_gate:true)
n-done   交付        terminal
```

- **人工评审门禁 = 发起表单开关「准出前人工评审」（方案 C，用户批准）**：勾选 → 提交用 `simple-flow-human`，不勾 → `simple-flow`。表单只多一个 checkbox，**不改表结构**（表配置驱动，human_gate 逐节点布尔为引擎原生——engine.ts:340 落点停靠 + Driver `gate:human:*` PASS 续派 + 看板 confirmGate 已实证）。`human_gate:true` 时该闸停靠（`status=gate_paused`）等人在看板点「放行/驳回」，PASS 后续派续跑。注：1.0 demo 无发起表单开关先例（协同编排 §5.3 是引擎层能力 + 看板辅按钮），本方案为表单开关 + 选表映射
- 节点 prompt **轻量化**（每个节点产出一份几行 markdown 写入工作区 handoffs/），确保真会话单节点分钟级完成
- 发起表单流程下拉自然多出「五阶段快速交付」选项（flows 源自动带出）；开关联动选表（提交时映射，下拉仍可见两张表）
- demo-flow 保持不变（既有测试/演示依赖它）

## 6 RealLauncher（唯一新组件，消费 L2 LaunchSpec）

实现既有 Launcher 契约，**只做 spawn + 生命周期**（D-048：launch 不 spawn，进程管理归本层）：

- 消费 L2 `adapter.launch()` 返回的 LaunchSpec（command/args/env/cwd 均来自 L2，本层不拼命令）
- spawn：env 注入（CLAUDE_CONFIG_DIR + 继承 service env→认证零置备）+ cwd=任务工作区
- prompt 走 **stdin**（P0c 升级后的 LaunchSpec）
- 超时 kill 进程树：Windows `taskkill /T /F`（TerminateProcess 语义）
- 垫片解析：.CMD → 真实 node/js 入口直连（L2 辅助）
- 退出码即结果（0=成功，非 0=失败→Driver 重试→挂起兜底）
