## 1 定位与制品形态（TR-01）

托盘壳 = Windows 通知区图标 + 右键菜单 + health 探活（keepalive 第二层，D-027）+ 打开浏览器。**独立制品**：

| 项 | 值 |
|----|-----|
| 产物 | `workbench-tray.exe`（单文件，Go + `fyne.io/systray`；`-ldflags "-H windowsgui -s -w"`） |
| 体量 | 上限 **< 8MB**（2026-08-24 用户裁决放宽：实测 6.4MB 当前可接受）；**UPX 压缩（~3MB）为后续优化项**（EDR 误报风险纳入 R-13 观察，见 [M0 Spike 报告](../../research/M0技术验证Spike报告-2026-08-24.md) §5）。另：GOPROXY 需 goproxy.cn（proxy.golang.org 被墙） |
| 版本 | 独立版本线，落 `run/native-shell-version`（与服务版本分离） |
| 日志 | 独立 `logs/tray.log`（与服务日志不交叉） |
| 契约 | 对 Service 的全部认知 = `GET /healthz` + `run/service.json` + `workbench` CLI（C-4/TR-01）——满足该契约的任何实现可互换 |
| 可杀性 | 杀壳进程：Service 照常运行且计划任务可拉起；壳与服务可分别升级（验收硬项） |

**macOS 复用**：同一 Go module 出 darwin 变体（模板图标 + 菜单栏惯例）归 0.2——本设计所有状态机/契约层平台无关，仅交互层（左键行为/图标资产）分平台文件。

## 2 Go module 结构

```
workbench-tray/                  独立 Go module（不进 pnpm workspaces，D-026）
├── main.go                      入口：runtime.LockOSThread + systray.Run
├── internal/
│   ├── statemachine/            四态状态机（§3）——纯逻辑，单测覆盖
│   ├── probe/                   health 探测循环（HTTP /healthz + service.json 端口发现）
│   ├── contract/                service.json / reliability.json 读取（schema 定义与 TS 侧共享 JSON 文件）
│   ├── menu/                    菜单构建与状态联动（§4）
│   ├── actions/                 动作执行：exec `workbench` CLI 子命令 + ShellExecute 开浏览器
│   ├── autostart/               HKCU Run 注册 + 哨兵文件（§6）
│   └── logging/                 tray.log（UTF-8，大小轮转 1MB × 3）
├── assets/                      图标资产（§4.3）
├── versioninfo/                 goversioninfo 模板（TR-08）
└── go.mod
```

与 TS 侧的唯一共享物 = `run/*.json` 的 schema（字段表抄自服务本体 §6，保持手写同步并在两仓 CI 各自校验字段存在性）。

## 3 四态状态机（TR-02/TR-05，D-027 壳层）

**探活判据 = `/healthz` 就绪，不是进程在**（源码拆解实证：「进程在但不健康」两周出现 19 次，是常态）。

| 态 | 图标 | 进入条件 | 菜单联动 |
|----|------|---------|---------|
| 🟢 运行中 | 绿 | `/healthz` 连续成功（1 次即可进入，防抖 2s） | 显示「停止/重启」；「打开工作台」可用 |
| 🟡 启动中 | 黄 | 进程在（service.json pid 存活）但 `/healthz` 未就绪 | **全部操作禁用**（防抖） |
| ⚪ 已停止 | 灰 | 用户主动停止（CLI stop 成功 / service.json 消失且非崩溃） | 显示「启动服务」；「打开工作台」仍可用（先拉起再开，§4.2） |
| 🔴 异常 | 红 | 连续 **3 次**探测失败 **且** 超过冷启动预算（默认 30s）；或启动报端口冲突（退码 78） | 显示「重启服务」+「查看日志」；**气泡通知一次**（不重复打扰） |

**黄态硬规则：skip 不重启**——冷启动实测可达 11s+，此窗口内重启必然造成重启风暴且每次都失败在同一个窗口。判「真挂」= 连续三次失败 + 超冷启动预算，双条件缺一不可。

探活循环：默认 5s 间隔（黄态加密到 2s）；探测 = `GET http://127.0.0.1:<port>/healthz`（超时 2s）；**端口发现链**：`run/service.json.port` -> `config/config.json` 的 `network.port` -> 默认 19980（端口可配置 D-022，壳不得硬编码）。

红态恢复动作：壳只做两件事——调 `workbench start`（一次）+ 通知；不做循环自愈（OS 守护负责进程级，壳只补 health 级这一层）。

## 4 菜单与交互（TR-03/TR-04）

### 4.1 右键菜单（调研 §6.1 结构，V0.1 版）

```
│ ● 工作台运行中 · 127.0.0.1:19980     │  状态项（禁用，仅展示；随四态与端口更新）
├──────────────────────────────────────┤
│ 打开工作台                    Enter  │  默认项（加粗）= 左键行为（§4.2）
│ 复制访问地址                         │
├──────────────────────────────────────┤
│ 停止服务 / 启动服务（互斥显示）         │  调 workbench stop / start
│ 重启服务                             │  stop && start（等 healthz）
├──────────────────────────────────────┤
│ 打开数据目录                         │  explorer 打开 ~/.ieidev-workbench/
│ 查看日志                             │  explorer 打开 logs/（lifecycle.log 优先）
│ 检查更新…                            │  调 workbench update --check，结果气泡通知
│ 关于（工作台 vX / 壳 vY）             │  两版本线都展示（W-12 研发视角）
├──────────────────────────────────────┤
│ 退出                                 │  仅退出壳（不停服务——服务归 OS 守护）
└──────────────────────────────────────┘
```

有 pending 更新时追加禁用展示项「⬆ vX 已就绪」+「立即重启以应用」（V0.1 应用方式 = 提示跑新安装包，D-028；菜单项引导打开下载目录）——C-8 三处可见性要求的壳侧落点。

### 4.2 左键直达（TR-04，Windows）

左键单击/双击 = 直接打开默认浏览器（`ShellExecute`）到 `http://127.0.0.1:<port>`。**服务未运行时**：先 `workbench start` -> 等 `/healthz` 就绪（`workbench __health-wait 15000` 内部子命令，超时 15s）-> 再开浏览器——不让用户看到浏览器连接失败。启动中菜单顶栏状态项同步「启动中…」。

### 4.3 图标资产

四套 `.ico`（绿/黄/灰/红），每套多尺寸 16/20/24/32/48/256；浅色/深色任务栏均可辨（设计验收：两主题截图对比）；Tooltip = `数字员工工作台 · 运行中 (端口)`（随态更新：启动中/已停止/异常）。

## 5 自启注册（TR-06）

- 注册位置：**HKCU Run 键**（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，值名 `IEIDevWorkbenchTray`）或启动文件夹——默认 Run 键
- **两份独立配置**：壳自启（Run 键）与 Service 守护（计划任务）互不隶属（D-027/C-4）——卸载服务不动 Run 键，反之亦然
- **哨兵文件**：`run/sentinels/tray-autostart-defaulted`——区分「用户显式选了不自启」与「默认注册过一次用户没表态」；升级重装只在后者补注册，杜绝「用户关了自启，升级后又自己打开」（W-16 实证事故）
- 用户开关落在 Service 的 `settings.json`（`system.tray.enabled` + `launchAtLogin`），壳读该文件执行注册/注销；壳自身不弹设置 UI

## 6 优雅停服交互（TR-07）

「停止服务」动作执行前：先调 `workbench activity` 查在飞任务 -> `conversationTasks + triggerTasks > 0` 时弹确认框（「有 n 个任务在飞，确认停止？」）；V0.1 在飞任务基本为 0，但**接口链路必须通**（验收即验链路：mock 非零返回确认框出现）。「退出」（壳自身）不做活动检查。

## 7 身份与安全（TR-08）

| 要求 | 实现 |
|------|------|
| VersionInfo 四字段 | CompanyName/FileDescription/ProductName/LegalCopyright 全部填实（goversioninfo 模板，CI 校验非空 + ProductName ≠ "Go" 构建工具名——实证反面教材 ProductName="Bun"） |
| FileVersion | = 壳版本（独立版本线） |
| 网络边界 | 只连 `127.0.0.1`（healthz 探测）；无任何外部连接（网络审计验收） |
| 进程动作 | 只 exec `workbench` CLI 与 `explorer`；**无进程注入、无全局钩子** |
| 签名 | 不购证书（D-c 口径）；EDR 拦截风险记 R-13——VersionInfo 填实是缓解手段，签名例外 0.2 再裁 |

## 8 安装与分发（TR-09）

- `install.ps1` 双制品落盘：Service + Tray 同目录（`<install-root>\bin\workbench.exe` + `workbench-tray.exe`，稳定路径不嵌版本号）
- 安装序列：Service 注册守护 -> 注册托盘自启（哨兵逻辑）-> 拉起托盘 -> 首启开浏览器
- 发布清单带绑定关系 `{bundled: {service: vX, shell: vY}}`；两制品独立升级（壳单独重发包只覆盖 exe + Run 键幂等）
- `workbench status --verbose` 输出三版本线（service/shell/installer，W-12：用户看一个，研发看三个）
- 卸载：cleanup 脚本删 Run 键 + 哨兵 + 壳文件（与服务清理共用独立脚本，W-11）

| 功能点 | 验收（= 测试口径） |
|--------|------------------|
| TR-01 | `taskkill /f workbench-tray.exe` 后：服务仍运行、计划任务仍能拉起服务、浏览器照常访问 |
| TR-02 | 四态流转：绿->黄（模拟 11s 冷启动）->绿；绿->红（停 healthz 三轮超预算）；灰（手动 stop）|
| TR-03 | 菜单全项动作经 CLI/HTTP 生效；状态项与实际端口一致（改 config 端口后壳跟随） |
| TR-04 | 服务停止时左键完成「拉起 + 就绪 + 打开」全链（15s 超时给失败气泡而非白屏浏览器） |
| TR-05 | 黄态全程 skip 不重启（日志无 restart 记录）；红态仅重启一次 + 通知一次 |
| TR-06 | 登录后托盘自动出现；用户关自启后升级不重开（哨兵验证）；壳自启与服务守护互不干扰（各删各的） |
| TR-07 | activity 非零（mock）-> 停止需二次确认 |
| TR-08 | CI 校验 VersionInfo 四字段；壳体量 < 8MB（2026-08-24 放宽）；netstat 无外部连接 |

| T4/W-2 | M0 spike：最小托盘 + 四态刷新 + 探活循环可跑；杀壳恢复语义成立 |
