## 1 定位与数据流总览

```
workbench-web（Vue 3 SPA，嵌入单体二进制）
   │  /api/**（会话鉴权，A-08）
   v
workbench-service
   ├─ app/employees/     花名册（扫描 + 聚合，只读视图）
   ├─ app/packages/      包构建管线（向导 draft -> 员工包，写 workers.json 账本）
   ├─ app/agenthub/      AgentHub CLI API 客户端（E-13）
   └─ app/installs/      （归详细设计 4，本文只消费其报告数据）
        │
        v  文件基底（单一真相源 = 文件，SQLite 只做缓存索引）
~/.ieidev-workbench/
   ├─ employees/<id>/          生成的员工包（canonical 源，UPP v0.3 §2 布局）
   ├─ templates/               内置模板（dev-engineer / req-architect）+ 用户存的自定义模板
   ├─ drafts.db                向导草稿（SQLite 表，见 §5.4 落实【修订】）
   ├─ installs/<id>@<base>.json 安装报告（详细设计 4 写）
   └─ bases/                   底座探测缓存
```

**花名册 = 派生视图**：扫描 `employees/*/manifest.yml` + 关联 `installs/*.json` + 底座在场状态实时聚合；**不设 registry.yml 第二真相源**（防漂移；扫描结果缓存进 SQLite，manifest mtime 变更时失效）。

## 2 前端骨架（F-01~F-04）

### 2.1 包结构（F-01）

```
packages/workbench-web/
├── src/
│   ├── router/            路由 + 守卫
│   ├── stores/            Pinia：session / roster / bases / wizard
│   ├── views/             LoginGate / Employees / EmployeeDetail / CreateWizard / BasesEnv
│   ├── components/        StatusBadge（两维正交徽章）/ ManifestPreview / SkillPicker ...
│   └── api/               类型化客户端（类型从 shared-protocol import）
├── vite.config.ts         dev 代理 -> http://127.0.0.1:19980
└── package.json
```

与 platform-frontend 同栈（Vue 3 + Vite + Pinia + vue-router），人力可流动；build 产物交服务本体嵌入（S-01/T5）。

### 2.2 路由表与守卫（F-02 / D-031）

| 路由 | 视图 | 守卫 |
|------|------|------|
| `/` -> redirect `/employees` | —— | —— |
| `/gate` | LoginGate（登录 + 接入状态卡，F-03） | 未登录才可进 |
| `/employees` | 员工列表（E-10，默认首页） | `session` + `active` |
| `/employees/:id` | 详情页（E-14，10 tab） | 同上 |
| `/employees/new` | 创建向导（E-11） | 同上 |
| `/bases` | 底座与环境（B-06，归详细设计 4） | 同上 |

- **全局前置守卫**：未登录 -> `/gate`；已登录未激活 -> `/gate`（接入状态卡展示审批进度，A-03/A-04 状态机徽章）
- 侧栏（白皮书六大模块的 V0.1 裁剪）：**我的员工**（默认）· **底座与环境**；「我的群组」「对话」**置灰占位**（能力未就绪不露死入口，D-030）；workflow 编排与任务看板 **隐藏**（L2）
- 顶栏（F-04）：登录用户（头像/邮箱，id_token claims）+ 平台连接状态（心跳 OK / 不可达告警条，D-032 提示非降级）+ 工作台版本 + 检查更新入口（U-01）

### 2.3 登录与接入页（F-03）

auth demo ui.ts 的 Vue 化：登录按钮 -> `/auth/login` 跳转；回岛后状态卡轮询 `/api/state`（2s，激活完成后停）：状态机徽章（待审批/已批准/激活中/已激活/被拒绝/被撤销）+ 拒绝原因 + 最后心跳时间 + 「重新申请」（REJECTED 态）。接线定义见[登录与认证设计 v0.2](登录与认证设计-v0.2.md) §5。

## 3 员工列表页（E-10，D-009）

卡片 grid（每行 4 张自适应）+ 筛选条（状态 / 底座 / 搜索）+ 「＋新建员工」入口。

**状态徽章 = 两维正交**（D-009），V0.1 数据可得性：

| 维度 | 判定（V0.1） | 展示 |
|------|-------------|------|
| 可用性（在线/离线） | **所绑底座在场 && 全部安装目标身份文件完好**（读安装报告 + 探测复验） | 绿点在线 / 灰离线 |
| 工作状态 | V0.1 无引擎无事件管线 -> 恒「空闲」（模型先建，渲染从简） | 空闲 |

> 工作状态维度的完整状态机（在跑 n / gate 停等 / 失败待处理）按员工运行与展示设计 §4.1 保留，数据源（events.jsonl）随 L2 启用——V0.1 徽章组件按两维 API 设计，空数据渲染空闲。

卡片字段：头像/图标字 · 岗位名 + id · 底座徽章（安装报告多目标，最多 2 + "+n"）· 状态徽章 · 简介（persona.identity 截 2 行）· 快捷操作（「⋯」菜单：详情 / 安装到其他底座 / 卸载 / 导出包）。**V0.1 无「＋对话」按钮**（对话归底座，D-030；卡片给「在底座中使用」提示文案替代）。

**特殊态**：「版本落后」黄标（包 version > 安装报告 version，E-15）；「安装中」转圈（installs 进行态）。**无「未安装」「草稿」卡片**（落实用户修订：生成出口不落未安装卡，见 §5.3）。

空态：居中引导卡「＋新建员工」+ 三路径一句话说明。

## 4 创建向导（E-11）

全屏子页（非模态），左 2/3 步骤表单 + 右 1/3 sticky 产出物预览（schema 校验徽章 + manifest.yml 实时渲染 + 目录树动态显隐）。交互细节基线 = 员工新建设计 §3，此处只列 V0.1 决策与修订落实。

### 4.1 五步与 V0.1 取舍

| Step | 内容 | V0.1 决策 |
|------|------|----------|
| 1 模板 | 模板卡片选择 | **仅 2 个内置模板：dev-engineer / req-architect**（落实修订）+ Custom 白纸；卡片字段照 §3.2 |
| 2 身份 | 岗位名/ID/部门/职责/原则/使用深度/头像 | 全字段默认值可一路下一步（E-11 验收）；ID 失焦校验唯一性（含与已装底座 skill 目录冲突预检） |
| 3 能力 | skills（AgentHub 搜索 + 模板默认）+ MCP | MCP 区块**降优先级**：V0.1 只读展示模板默认，不提供接入编辑（修订落实） |
| 4 约束 | 红线 chip / 模型档位 / Token 配额 | **降优先级**（修订）：模板默认值即终值，区块折叠展示可展开微调 |
| 5 流程+治理 | 流程形态 / 治理三件套 | **降优先级**（修订）：dev-engineer/req-architect 模板带完整预置 node-table（1.0 同源素材），Custom 生成骨架 |

> Step 2 的身份定义模式（AGENTS.md 五段式）受用户修订指派的调研项影响（openclaw/Hermes/CC 的 agent 身份定义对比 + qoderwake-role-template.zip）——**V0.1 先按员工新建设计 §4.4 五段式模板实现**，调研结论若推翻渲染模板只影响 packages/ 渲染器一个模块（开放问题 E-Q1）。

### 4.2 AgentHub skill 选择（Step 3，E-13 交互面）

- 「从 AgentHub 添加」浮层：搜索框（防抖 300ms）+ 结果列表（name@latestVersion / namespace / summary / assetType 徽章）+ 版本切换 + 「添加」
- **assetType 过滤**：仅展示 `SKILL` 资产；`PLUGIN`（skill 打包/bundle）灰显并注「V0.1 不支持包内单抽」——落实用户修订提出的「只想要 superpowers 里的 brainstorming」问题：Keyhub 协议按 `ns/slug` 粒度检索与下载，**单 skill 粒度成立的前提是该 skill 以独立 SKILL 资产上架**；bundle 形态（PLUGIN）V0.1 不拆包（边界，见 E-13；开放问题 E-Q2）
- AgentHub 不可达：搜索区置灰「AgentHub 不可达」；模板默认 skill 走**本地模板库拷贝**（模板自带素材不依赖网络）；「本地导入」降级入口始终可用（目录选择 -> SKILL.md frontmatter 校验 -> 复制进包，source_type=local）
- 已选列表行：name@version · 来源徽章 · fingerprint 校验状态 · 移除

### 4.3 右侧预览与生成

- 校验徽章：字段变更 300ms 防抖 -> 前端本地跑 shared-protocol `validateManifest`（schema 同源，无需网络）——`校验通过` 绿 / `失败 n 项` 红（点击逐项跳转对应 Step 字段）
- 「生成员工包」-> `POST /api/employees/generate`（§7）；成功进入生成完成态：包路径 + 文件清单 + **两出口**：
  - ① **「安装到底座」** -> 底座选择（B 系列流程，详细设计 4）-> 安装报告 -> 详情页
  - ② **「保存为角色模板」**（落实修订：取代"仅保存到本地"）-> 写 `templates/custom/<id>/`（含 manifest 素材 + skills），Step 1 出现「我的模板」分组；**不产生员工包落盘、不进花名册**

## 5 员工包构建管线（E-12）

### 5.1 管线（员工新建设计 §4.1 收敛为实现模块）

```
draft（SQLite）-> ① 交叉校验（shared-protocol 跨字段规则）
  -> ② 渲染 AGENTS.md（五段式模板，员工新建设计 §4.4；治理字段不渲染）
  -> ③ 生成 manifest.yml（schema 2.1；employee_id = <id>@<部门>，operator_id = 登录邮箱）
  -> ④ 物化 skills/：agenthub 来源 -> resolve + download（fingerprint 校验）解包复制；
                       local 导入 -> 拷贝 + frontmatter 校验；模板内置 -> templates/ 拷贝
  -> ⑤ 编译 hooks/hooks.json（红线规则库可编译子集，员工新建设计 §4.6；无勾选则省略）
  -> ⑥ mcp.json（模板默认连接器，凭证环境变量占位不落明文）
  -> ⑦ orchestration/<id>.node-table.yml（模板预置或 Custom 骨架，员工新建设计 §4.8）
  -> ⑧ 原子落盘：临时目录写全 -> rename 至 employees/<id>/ -> 写 workers.json 账本（构建任务）+ 生成日志
```

- **skill 复制进包、锁定版本**（D-006）：manifest.skills 记 `{name, version, source_type, namespace?, slug?, fingerprint?}`；构建失败回滚（临时目录丢弃），磁盘错误报具体路径
- 构建任务作为 S 系列子进程跑（写 workers.json，S-05 账本语义一致）；V0.1 构建体量小（<10MB 包）同步实现亦可，**账本先接上**（与 §9 服务本体保持同构）

### 5.2 内置模板

`templates/dev-engineer/` 与 `templates/req-architect/`：完整预置素材（manifest 全字段 + AGENTS.md 文案 + 默认 skills 素材 + 红线 + runbook + 预置 node-table），内容 = 员工新建设计 §4.9.1/§4.9.2 全量表。模板随工作台发版，「使用模板」**快照拷贝**（模板升级不追改已生成员工）。

### 5.3 草稿与模板存储（落实修订【要考虑是文件保存还是DB保存】）

| 数据 | 存储 | 理由 |
|------|------|------|
| 向导草稿 | **SQLite 表 `drafts`**（draft_id / template / current_step / form JSON / updated_at） | 单机单用户、需频繁部分更新、与员工包生命周期无关——DB 比文件省心（无锁无原子写负担）；表随服务本体 SQLite 实例 |
| 角色模板 | 文件 `templates/custom/<id>/`（与内置模板同构布局） | 模板是可分享/可 git 的资产，文件形态与员工包同构 |
| 员工包 | 文件 `employees/<id>/` | 包自包含、可 git 管理（白皮书不变式）；DB 只做索引缓存 |

草稿功能 V0.1 **降级为自动保存**（防误关页面：localStorage + drafts 表双写，进入向导弹「检测到未完成草稿，恢复？」），无草稿列表页。

## 6 AgentHub 对接（E-13，D-033）

### 6.1 客户端（app/agenthub/）

对接 Keyhub 实证 CLI API（鉴权 `Authorization: Bearer <token>`，scope skill:read；地址 + token 为 settings 配置项，A 系列 token 加密存储）：

| 能力 | 端点 | 说明 |
|------|------|------|
| 搜索 | `GET /api/cli/v1/skills/search?q=&limit=` | 匿名可用（限流 20/min）；`{items:[{namespace, slug, latestVersion, summary}]}` |
| 版本解析 | `GET /skills/{ns}/{slug}/resolve?version=` | `{version, versionId, fingerprint, downloadUrl, assetType}` |
| 下载 | `GET /skills/{ns}/{slug}/versions/{v}/download` | 流式 ZIP/tarball |

- **fingerprint 校验**：下载完成比对 resolve 返回值，不匹配拒绝（E-13 验收）
- 缓存：下载物按 `ns/slug@version` 缓存 `~/.ieidev-workbench/cache/agenthub/`（重试/重建包不重复下载；磁盘 GC 纳入 S-10）
- 失败语义：搜索 429/超时 -> UI 置灰；resolve/download 失败 -> 向导内行级报错重试；**全程不阻塞生成**（本地路径兜底）

### 6.2 边界

- `assetType=PLUGIN` 不支持（bundle 不拆包）；skill 协议 = SKILL.md（frontmatter name+description）+ references/ + scripts/ + assets/，安装目录名 = slug
- AgentHub 部署环境（地址/token 发放，R-20）是联调前置，不是设计前置：全部经配置注入

## 7 工作台本地 API（employees/packages/agenthub 域）

挂载于服务本体 §10 端点表，鉴权 `会话+激活`；错误体 `{code, message, field_errors?: [{step, field, message}]}`。

| 端点 | 方法 | 请求 -> 响应 | 说明 |
|------|------|------------|------|
| `/api/templates` | GET | -> `[{id, display, kind, summary, builtin}]` | 内置 + 自定义模板（Step 1） |
| `/api/templates` | POST | 模板素材 -> `201 {id}` | 出口②保存为模板 |
| `/api/employees` | GET | `?status=&base=&q=` -> `{items: [roster card]}` | 花名册聚合（§1 数据流） |
| `/api/employees/:id` | GET | -> `{manifest, installs[], availability}` | 详情页聚合 |
| `/api/employees/validate-id` | GET | `?id=` -> `{available, suggestion?}` | Step 2 失焦 |
| `/api/employees/generate` | POST | `{draft_id}` 或内联 draft -> `{package_path, files[], manifest}` | 构建管线（§5.1）；409 ID 冲突 / 422 校验失败（逐项 + step 定位） |
| `/api/employees/:id/export` | GET | -> tarball 流 | 导出包 |
| `/api/employees/:id/rollback` | POST | `{version}` | 回滚 = 重装旧版本（E-15，走 installs 流程） |
| `/api/skills/search` | GET | `?q=&limit=` -> AgentHub 映射 | 代理（6.1）；AgentHub 不可达 503 -> UI 置灰 |
| `/api/skills/:ns/:slug/versions` | GET | -> `[{version, publishedAt}]` | 版本下拉 |
| `/api/drafts/current` | GET/PUT/DELETE | draft JSON | 单草稿（自动保存，§5.3） |

（安装/卸载/底座端点归详细设计 4；`/api/agenthub/*` 命名统一为 `/api/skills/*`，向导语义优先。）

| ⑧ 连接器 | 🔹 只读 | mcp.json 渲染表：server / 类型 / access / 凭证环境变量状态（缺失红标） |
| ⑨ 权限与治理 | 🔹 只读 | manifest constraints/governance 段渲染：红线表（落地路径徽章）/ tier-map / 配额声明 / 治理卡（L1/L2 变更需平台审批锁标） |
| ⑩ 员工包 | ✅ 实做 | 文件树只读浏览（语法高亮预览）+ manifest 五类分节卡（复用向导预览组件）+ 安装报告行（每底座：版本/可达 Level/降级项/告警）+ 版本历史（semver 列表 + 回滚）+ 操作（打开目录/导出/卸载） |

编辑档案（§3.10 规则）：向导预填、id 锁定、版本三档递增按 diff 推荐；保存 = 新版本包 + 已装目标标「版本落后」。

## 9 版本管理（E-15）

- 包版本 = manifest.version（semver），编辑递增规则照员工新建设计 §3.10
- 安装历史 = 安装报告时间线（installs/<id>@<base>.json 多版本记录，详细设计 4 定义 schema）
- 升级 = 重新构建 + 重装（漂移标记 -> 用户在详情页或底座页触发对齐安装）
- 回滚 = 选历史版本重新执行安装事务（`/api/employees/:id/rollback`）
- **不做**：灰度/多通道/changelog 编辑（§9 明确不做表）
