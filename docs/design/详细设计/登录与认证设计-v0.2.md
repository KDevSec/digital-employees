## 0 v0.1 -> v0.2 的实质变化

| 维度 | v0.1 方案（已废弃） | v0.2 方案（已实现） |
|------|-------------------|-------------------|
| 人员登录 | 邮箱验证码（首登即注册）+ 可选密码 | **Keycloak OIDC**（Authorization Code + PKCE S256，Public Client） |
| 浏览器持有 | 本地 session cookie（配对码建立） | 本地 session cookie（登录回调建立）--不变，但无配对码 |
| 平台凭证 | JWT 双 token（access 1h + refresh 30d 轮换），工作台后端持有 | **BFF 会话**：平台 token 不落工作台；人员身份每次经 OIDC 验证后进本地会话 |
| 设备/实例注册 | 登录时顺带注册 device_id | **enrollment 接入审批**：独立状态机 + 管理员审批 + 密钥证明激活 |
| 机器身份 | 无（遥测 token 独立设计） | **ES256 private_key_jwt** 换机器 token（5min，scope workbench.heartbeat）+ 心跳 |
| 离线宽限 | 7 天宽限 + 缓冲补传 | **不做**（D-032：平台不可达即功能不可用） |
| 权限显隐 | 治理分级 L1-L4 ↔ RBAC 全矩阵 | **推后**（R-18：V0.1 只用 `(issuer, sub)` 身份 + 顶栏展示） |
| 遥测凭证 | OTLP 专用 token 90 天 | **L2+**（OTLP 本身不在 V0.1） |
| 本地端口 | 127.0.0.1:19820 | 127.0.0.1:**19980**（D-022，可配置） |

> 三层信任链（v0.2 核心心智模型）：**人员身份**（OIDC，谁在用）-> **实例身份**（enrollment，这台工作台是否被企业接纳）-> **机器身份**（ES256，心跳与服务调用凭据）。三层全部已在平台侧交付，工作台侧为 auth demo 原型，V0.1 任务 = 迁移 + 自动化 + 加固（A-01~A-08）。

## 1 定位与范围

### 1.1 定位

定义**工作台（本地）↔ 管控平台（远端）**之间的信任链：OIDC 人员登录、enrollment 接入审批与激活、ES256 机器身份与心跳；以及**浏览器 ↔ 工作台本地服务**这一段的会话与本地安全边界。

### 1.2 范围内 / 不做什么

范围内：平台发现（A-01）；OIDC 登录与 BFF 会话（A-02/A-07）；enrollment 状态机与激活（A-03/A-04）；机器 token 与心跳（A-05）；密钥与状态存储安全（A-06）；登录态能力边界（A-08）。
不做（V0.1）：❌ 离线宽限/降级（D-032）；❌ 治理分级权限显隐与角色消费（R-18，specs/002 组织权限完成后再议）；❌ OTLP 遥测凭证（L2+）；❌ 邮箱验证码/密码路径（被 OIDC 取代，企业 IdP 自带账号管理）；❌ 配对码（v0.1 概念，实现未采用；本地加固候选 0.2 再议，见 §8）；❌ 平台侧任何改动（已交付冻结）。

### 1.3 账号模型前提

**单用户单实例**：一台工作台同时只登录一个人员账号（切换账号 = 登出再登）；工作台实例身份（installation_id / workbench_instance_id）与登录人员账号独立--实例注册一次，人员可换登（心跳凭实例身份，不随人员切换失效）。

## 2 用户旅程

### 2.1 首次启动与登录（A-01/A-02，已实现主线）

```
安装 -> workbench start -> 浏览器自动打开 http://127.0.0.1:19980
  -> 未登录态：仅接入引导页（D-031：未登录无任何业务功能）
  -> [登录] -> GET /auth/login -> 302 跳 Keycloak
     （Authorization Code + PKCE S256；Public Client 无 secret；state + nonce 随行）
  -> 用户在企业账号页完成认证 -> 302 回 /auth/callback?code&state
  -> 工作台后端：code 换 token -> 验 id_token（JWKS 拉取缓存 + nonce + iss/aud + exp）
     -> 签发本地 HttpOnly session cookie
  -> 登录后自动提交接入申请（无需手动按钮，A-03）
```

### 2.2 接入审批与激活（A-03/A-04，enrollment 状态机）

```
登录即自动提交：installation_id + ES256 公钥(JWK) + display_name
                + workbench_version + os/arch   （幂等：重复提交返回原申请）
  NEW -> PENDING_REVIEW
      -> 管理员在平台审批（通过 / 拒绝）
  APPROVED -> 工作台请求一次性 challenge（JTI 防重放，短时效）
          -> ES256 签名 proof JWT 回应
          -> complete -> 获得 workbench_instance_id -> ACTIVE
  分支：REJECTED（UI 展示拒绝原因）/ ERROR（可重试）/ REVOKED（激活后被撤销）
```

### 2.3 激活后常态（A-05）

- 机器 token：ES256 private_key_jwt（client_credentials 断言）换取，**5 分钟效期**，scope `workbench.heartbeat`；到期前自动刷新。
- 心跳：**后台定时**（建议 60s + 失败指数退避；demo 为手动按钮，V0.1 必须自动化），携带 workbench_version。
- 心跳失败（网络/REVOKED）-> 顶栏常驻告警条；REVOKED -> 显式提示「实例已被平台撤销」。

### 2.4 登出

`POST /api/logout` -> 清本地会话 -> 前端回未登录态（仅接入引导页）。实例身份与心跳**不中断**（心跳凭机器身份，不凭人员会话）。

### 2.5 平台断联（D-032，取代 v0.1 §2.5 的 7 天宽限表）

| 平台状态 | 工作台行为 |
|---------|-----------|
| 不可达 | 功能不可用；UI 常驻「平台不可达」提示（顶栏告警条，提示而非降级）；不做宽限计数、不做离线模式 |
| 恢复 | 自动恢复（发现配置用本地缓存 + 心跳重连） |

## 4 数据模型

### 4.1 实体（平台侧已实现，工作台只消费）

| 实体 | 关键字段 | 归属 |
|------|---------|------|
| 人员账号 | Keycloak realm 用户；身份键 = `(iss, sub)`，email 展示用 | 平台（iam/） |
| 接入申请 Enrollment | installation_id / workbench_instance_id / ES256 公钥 JWK / display_name / workbench_version / os / arch / status / reject_reason | 平台（enrollment.py） |
| 机器 token | 5min 效期，scope `workbench.heartbeat`，Bearer | 平台签发，工作台短期持有（仅内存） |
| 本地会话 | session cookie（HttpOnly）+ 会话记录 | 工作台本地 |

### 4.2 密钥与状态安全（A-06）

| 项 | 方案 |
|----|------|
| 密钥对 | 首启生成 P-256（ES256）；公钥以 JWK 随 enrollment 上报；私钥 AES-256-GCM 加密落盘 `0600` |
| 加密密钥 | **首启随机生成、单独落盘**（取代 demo 的环境变量默认值） |
| 状态存储 | installation_id / 私钥密文 / 接入状态 / 最后心跳 加密存储（state-store.ts 迁移 + 加固） |
| 删除恢复 | 删状态文件后可重新走全流程（新 installation_id） |

### 4.3 会话持久化（A-07）

demo 的内存 session（重启失效）-> 持久化会话（加密文件或 SQLite，随服务本体详细设计定）：工作台服务重启后浏览器免重登；过期策略对齐平台 token 效期。

### 4.4 本地安全边界（S-12 / D-022）

| 项 | 方案 |
|----|------|
| 服务绑定 | 仅 `127.0.0.1:19980`（默认，可配置）；拒绝非 localhost Host 头（DNS rebinding 防护） |
| 平台 token 出域约束 | id_token/access_token 仅在工作台后端内存中验证与交换，**不下发浏览器**；浏览器只持本地 session cookie |
| cookie | HttpOnly + SameSite=Strict |

## 5 接口契约（全部已实现，工作台侧为迁移目标）

### 5.1 平台发现（A-01）

`GET /.well-known/workbench-configuration` -> `{oidc_issuer, oidc_client_id, enrollment_endpoint, machine_token_endpoint, protocol_version}`（[core.py:43](../../platform/backend/app/api/core.py)）。工作台启动时拉取 + 本地缓存上次成功配置（平台不可达时登录页提示「平台不可达」而非白屏）。

### 5.2 工作台本地 API（浏览器 <-> 本地服务；auth demo 已有，迁入 Hono）

| 端点 | 方法 | 说明 |
|------|------|------|
| `/auth/login` | GET | 302 跳 Keycloak（state + nonce + PKCE S256） |
| `/auth/callback` | GET | code 换 token；验 id_token（JWKS/nonce/iss/aud/exp）-> 建 session cookie |
| `/api/logout` | POST | 清会话 |
| `/api/state` | GET | 登录态 + 接入状态聚合（前端状态卡数据源） |
| `/api/progress` | GET | enrollment 进度（demo 有，迁移保留） |
| `/api/heartbeat` | POST | demo 手动触发保留为诊断入口；V0.1 常态由后台定时器驱动 |

### 5.3 Enrollment API（平台侧已实现，enrollment.py）

| 操作 | 端点语义 | 要点 |
|------|---------|------|
| 提交申请 | `POST {enrollment_endpoint}` | 幂等（installation_id 去重）；body：installation_id + JWK 公钥 + display_name + workbench_version + os/arch |
| 查询状态 | `GET .../{installation_id}` | 状态机 + reject_reason |
| 请求 challenge | `POST .../challenge` | 一次性、短时效、**JTI 防重放** |
| 完成激活 | `POST .../complete` | body：proof JWT（ES256 签名 challenge）；成功 -> workbench_instance_id |
| 撤销 | 平台侧管理员操作 | 下次心跳失败 + REVOKED 显式提示 |

### 5.4 机器 token 与心跳（A-05）

- 机器 token：`POST {machine_token_endpoint}`，OAuth2 client_credentials + **private_key_jwt** client assertion（ES256 签名，sub = installation_id）；响应 access_token（5min，scope `workbench.heartbeat`）。
- 心跳：`POST .../heartbeat`，`Authorization: Bearer <机器 token>`，body 含 workbench_version；建议 60s 间隔 + 失败退避。

### 5.5 错误处理约定

| 场景 | 行为 |
|------|------|
| 401（机器 token 过期） | 自动刷新（private_key_jwt 重签）-> 重放一次 |
| id_token 验证失败（nonce/iss/aud 被篡改） | 拒绝登录，回登录页并提示 |
| challenge 过期/重放（JTI） | 重新走 challenge 流程 |
| enrollment REJECTED | 状态卡展示拒绝原因，无自动重试（用户可手动重新申请 = 新 installation_id） |
| 平台 5xx/网络错误 | 幂等操作退避重试；非幂等（complete）不自动重试 |

## 7 边界情况与降级

| 情况 | 行为 |
|------|------|
| 平台不可达（启动时） | 发现配置用本地缓存；登录页提示「平台不可达」 |
| 平台不可达（运行中） | D-032：功能不可用 + 顶栏告警；心跳按退避重试 |
| 心跳持续失败 | 顶栏常驻告警；REVOKED 时显式「实例已被撤销」 |
| Keycloak 时钟偏移 | 验签容忍 ±120s；偏移过大给诊断告警（沿用 v0.1 立场） |
| 私钥文件损坏/丢失 | 视同新实例：新 installation_id 重新走接入审批 |
| 多浏览器/无痕窗口 | 每浏览器独立会话（cookie 隔离，天然成立） |
| 工作台版本过旧 | protocol_version 协商（发现端点）；不匹配提示升级（对齐 U-01 检查更新） |
| 人员换登 | 登出 -> 新 OIDC 登录；实例身份与心跳不断 |
