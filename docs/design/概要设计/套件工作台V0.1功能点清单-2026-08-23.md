## 1 定位与版本口径

### 1.1 一句话定义

**套件工作台 V0.1 = 参照 QoderWake 实现方式的独立应用（单体二进制服务 + 浏览器 UI + OS 守护 + CLI），叠加已交付的管理平台认证接入体系，跑通「安装 -> 登录接入 -> 创建员工 -> 从 AgentHub 拉 skill -> 生成员工包 -> 安装到底座（CodeBuddy / Qoder CLI）-> 底座内使用 -> 检查更新」的最小端到端闭环（使用深度 L0/L1）。**

### 1.2 版本口径澄清（三个"0.1"不是一个东西）

| 名词 | 指什么 | 状态 |
|------|--------|------|
| **管理平台 V0.1** | platform/ 的 Keycloak + FastAPI + Vue 单机部署（specs/001） | ✅ 已交付，V0.1 期间只修不加 |
| **套件工作台 V0.1** | **本文定义**，本地端独立应用 | 🚧 待开发 |
| **部署形态 0.1** | 部署调研 §5.2 的分期（原：0.1 无托盘，0.2 加 Windows 壳） | 工作台 V0.1 含托盘（2026-08-23 裁决），实际介于调研的部署形态 0.1 与 0.2 之间；0.2 剩余项 = GUI 安装器 + macOS 壳 |

### 1.3 与 QoderWake 的参照关系

用户口径（2026-08-23）：工作台本体**直接参考 QoderWake 的实现方式**。对应到功能点即部署调研的全部结论：单体二进制 daemon（不引 Electron）、进程守护委托 OS、UI 由系统浏览器承载本地端口、壳与服务完全解耦。

**2026-08-23 追加裁决（推翻调研 D-i）**：**V0.1 包含 Windows 托盘壳**--桌面层工作量不再为 0，托盘壳作为独立制品进入 V0.1 范围（功能点见 §5.6）；macOS 壳仍归 0.2+，Linux 不发壳（D-h 不变）。

**默认端口变更**：19820 与本机 QoderWake 实证环境冲突，默认端口改为 **19980**（D-f 可配置不变；最终值如另有指定随时可换，全文引用以「19980（原 19820）」标注一次即可）。

## 2 端到端用户故事（V0.1 验收主线）

```
开发者拿到工作台安装包（或脚本）
  -> install.ps1 / install.sh 安装：落盘单体二进制 + 托盘壳 + 注册 OS 守护与壳自启 + 首次自动开浏览器
  -> 任务栏出现托盘图标（四态状态灯）；右键菜单可打开工作台/启停服务/看日志
  -> 浏览器打开 127.0.0.1:19980 -> 企业账号 Keycloak OIDC 登录（未登录无任何业务功能）
  -> 工作台自动提交接入申请（installation_id + ES256 公钥）
  -> 管理员在平台审批 -> 工作台完成 challenge 密钥证明 -> 激活，后台心跳
  -> 创建员工：模板 -> 身份 -> 从 AgentHub 选 skill -> 约束 -> 生成员工包（manifest + AGENTS.md + skills + mcp.json）
  -> 安装到 CodeBuddy CLI / Qoder CLI：文件落位 + 安装报告
  -> 在底座（CodeBuddy / Qoder）内直接派发使用员工（L0/L1，V0.1 不含工作台对话界面）
  -> 期间：平台上传新版本工作台安装包 -> 工作台检查更新 -> 托盘菜单与 UI 提示引导下载升级
```

每个环节分别由 §5 的功能点支撑；整链跑通是 §8 里程碑 M3 的总验收。

## 3 现状盘点：已实现资产与 V0.1 处置

2026-08-23 对 platform/ · workbench/ · iam/ · specs/ · tools/ 的源码排查结论。**这一节决定 V0.1 的新建工作量边界：已有资产只做迁移/复用，不重写。**

### 3.1 管理平台侧（已交付，V0.1 依赖它）

| 资产 | 代码位置 | 已实现内容 | V0.1 处置 |

| 平台发现端点 | [core.py:43](../../platform/backend/app/api/core.py) `GET /.well-known/workbench-configuration` | 下发 oidc_issuer / oidc_client_id / enrollment_endpoint / machine_token_endpoint / protocol_version | 工作台启动时消费，**不动** |
| 人员身份 | iam/（Keycloak realm + PostgreSQL） | OIDC 身份源、用户、组织属性 | **不动** |
| 工作台接入管理 | [enrollment.py](../../platform/backend/app/api/enrollment.py) | 申请/审批/challenge/complete/撤销、ES256 proof 验证、JTI 防重放、幂等 | **不动** |
| 机器身份 | MachineCredential + heartbeat 端点 | private_key_jwt 换 5 分钟机器 Token、心跳校验、撤销即失效 | **不动** |
| **安装包管理** | [packages.py](../../platform/backend/app/api/packages.py) | 公开列表/下载/历史（版本/OS/架构/SHA-256/签名状态）+ admin 上传/发布/下架 | **不动**；它就是工作台「检查更新」的服务端（裁决了调研 D-g：更新源 = 平台，非 GitHub Releases） |
| 组织树与分级权限 | specs/002（foundation 已入库） | 任意深度组织树 + 自定义角色（后端基础） | 平台侧后续迭代，**不阻塞**工作台 V0.1 |
| Compose 部署 + e2e | tools/（compose.yml + Playwright） | 五服务编排 + 真实协议 e2e | **不动**，验收环境复用 |

### 3.2 工作台侧（认证 Demo，逻辑迁移进正式服务）

| 资产 | 代码位置 | 已实现内容 | V0.1 处置 |
|------|---------|-----------|----------|
| 登录服务端 | [server.ts](../../workbench/src/server.ts) | OIDC Authorization Code + PKCE、id_token 验证（JWKS + nonce）、本地 session cookie、/health/live | **逻辑迁移**到正式单体二进制（Express -> Hono），见 §7 |
| 平台客户端 | [platform-client.ts](../../workbench/src/platform-client.ts) | discover / submitEnrollment / enrollment / completeEnrollment（challenge + proof JWT）/ machineToken / heartbeat 全套 | **迁移**，作为工作台内 platform-access 模块的底座 |
| 机器密钥与证明 | [crypto.ts](../../workbench/src/crypto.ts) | PKCE、P-256/ES256 密钥对、proof JWT、private_key_jwt assertion | **迁移** |
| 加密状态存储 | [state-store.ts](../../workbench/src/state-store.ts) | AES-256-GCM 加密持久化（installation_id / 密钥对 / 接入状态） | **迁移**；默认密钥 `development-only-state-secret-change-me` 必须换成首启生成落盘 |
| 登录原型 UI | [ui.ts](../../workbench/src/ui.ts) | 接入状态页（登录/重提申请/心跳/重置/登出） | 交互逻辑 **Vue 化**进正式前端 |
| 单元测试 | workbench/tests/（vitest） | crypto / state-store / ui 三份 spec | 随迁移保留 |

> ⚠️ 两处必须纠正的 demo 妥协：（a）`app.listen(port, '0.0.0.0')` 是为 VM 浏览器访问临时开的口子，正式版必须回到 **仅绑定 127.0.0.1**（登录设计 §4.4 / 调研 §2.1）；（b）会话存进程内存、重启即失效，正式版需要持久化会话（见 A-07）。

### 3.3 由此得出的 V0.1 工作量结构

```
V0.1 新建 = 服务本体（QoderWake 式 daemon，全新）        ← 部署调研 T1–T15
          + Windows 托盘壳（独立制品，全新）              ← §5.6（用户裁决 2026-08-23，推翻 D-i）
          + 认证接入（auth demo 逻辑迁移 + 自动化补全）    ← §5.2
          + 检查更新（对接平台包 API，全新但很薄）          ← §5.3
          + 业务闭环 M1–M4（全新）                        ← §5.4
          + Vue 前端骨架（全新）                          ← §5.5
平台侧 = 0（已交付）
```

**2026-08-23 用户裁决**：对话界面**不进 V0.1**（-> V0.2，随会话路由/看板一起）；底座范围 = **CodeBuddy CLI + Qoder CLI**（Claude Code -> V0.2）；未登录不可用、平台断联宽限 V0.1 不做；**默认端口 19820 -> 19980**（与 QoderWake 冲突）。裁决记录见 §11.1。

### 5.2 A · 认证与可信接入（auth demo 逻辑迁移 + 自动化）

以已实现代码为准（§3.2），V0.1 任务 = 迁移进 S 系列的单体服务 + 把 demo 的手动按钮自动化 + 补运行时边界。

| # | 功能点 | 内容 | 验收标准 | 来源 |

- 迁移完成后 `workbench/` demo 目录退役或转为 e2e fixture（避免双实现漂移）
