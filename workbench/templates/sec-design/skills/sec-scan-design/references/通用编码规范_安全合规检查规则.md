# 通用编码规范安全合规检查规则

| 编号 | 类别 | 规则描述 |
|------|------|----------|
| CC-96 | 通用编码规范 | 为常用的任务使用已测试且已认可的托管代码，而不创建新的非托管代码。 |
| CC-97 | 通用编码规范 | 使用特定任务的内置API以执行操作系统的任务。不允许应用程序直接将代码发送给操作系统，特别是通过使用应用程序初始的命令shell。 |
| CC-98 | 通用编码规范 | 使用校验和或哈希值验证编译后的代码、库文件、可执行文件和配置文件的一致性。 |
| CC-99 | 通用编码规范 | 使用锁来防止多个同时发送的请求，或使用一个同步机制防止竞态条件。 |
| CC-100 | 通用编码规范 | 在同时发生不恰当的访问时，保护共享的变量和资源。 |
| CC-101 | 通用编码规范 | 在声明时或在第一次使用前，明确初始化所有变量和其他数据存储。 |
| CC-102 | 通用编码规范 | 当应用程序运行发生必须提升权限的情况时，尽量晚点提升权限，并且尽快放弃所提升的权限。 |
| CC-103 | 通用编码规范 | 通过了解使用的编程语言的底层表达式以及它们是如何进行数学计算，从而避免计算错误。密切注意字节大小依赖、精确度、有无符合、截尾操作、转换、字节之间的组合、"not-a-number"计算、以及对于编程语言底层表达式如何处理非常大或者非常小的数。 |
| CC-104 | 通用编码规范 | 不要将用户提供的数据传递给任何动态运行的功能。 |
| CC-105 | 通用编码规范 | 限制用户生成新代码或更改现有代码。 |
| CC-106 | 通用编码规范 | 审核所有从属的应用程序、第三方代码和库文件，以确定业务的需要，并验证功能的安全性，因为它们可能产生新的漏洞。 |
| CC-107 | 通用编码规范 | 执行安全更新。如果应用程序采用自动更新，则为代码使用加密签名，以确保下载客户端验证这些签名。使用加密的信道传输来自主机服务器的代码。 |
