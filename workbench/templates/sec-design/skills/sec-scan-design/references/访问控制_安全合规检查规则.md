# 访问控制安全合规检查规则

| 编号 | 类别 | 规则描述 |
|------|------|----------|
| AC-11 | 访问控制 | 只使用可信系统对象（比如：服务器端会话对象）以做出访问授权的决定。 |
| AC-12 | 访问控制 | 如果应用程序无法访问其安全配置信息，则拒绝所有的访问。 |
| AC-13 | 访问控制 | 将有特权的逻辑从其他应用程序代码中隔离开。 |
| AC-14 | 访问控制 | 限制只有授权的用户才能访问受保护的URL。 |
| AC-15 | 访问控制 | 限制只有授权的用户才能访问受保护的功能。 |
| AC-16 | 访问控制 | 限制只有授权的用户才能访问直接对象引用。 |
| AC-17 | 访问控制 | 限制只有授权的用户才能访问服务。 |
| AC-18 | 访问控制 | 限制只有授权的用户才能访问应用程序数据。 |
| AC-19 | 访问控制 | 限制通过使用访问控制来访问用户、数据属性和策略信息。 |
| AC-20 | 访问控制 | 限制只有授权的用户才能访问与安全相关的配置信息。 |
| AC-21 | 访问控制 | 服务器端执行的访问控制规则和表示层实施的访问控制规则必须匹配。 |
| AC-22 | 访问控制 | 如果状态数据必须存储在客户端，使用加密算法，并在服务器端检查完整性以捕获状态的改变。 |
| AC-23 | 访问控制 | 强制应用程序逻辑流程遵照业务规则。 |
| AC-24 | 访问控制 | 限制单一用户或设备在一段时间内可以执行的事务数量。事务数量/时间应当高于实际的业务需求，但也应该足够低以判定自动化攻击。 |
| AC-25 | 访问控制 | 仅使用"referer"头作为补偿性质的检查，它永远不能被单独用来进行身份验证检查，因为它可以被伪造。 |
| AC-26 | 访问控制 | 如果长的身份验证会话被允许，周期性的重新验证用户的身份，以确保他们的权限没有改变。如果发生改变，需注销该用户，并强制他们重新执行身份验证。 |
| AC-27 | 访问控制 | 执行账户审计并将没有使用的账号强制失效（比如：在用户密码过期后的30天以内）。 |
| AC-28 | 访问控制 | 应用程序必须支持账户失效，并在账户停止使用时终止会话（比如：角色、职务状况、业务处理的改变，等等）。 |
| AC-29 | 访问控制 | 服务账户，或连接到或来自外部系统的账户，应当只有尽可能小的权限。 |
