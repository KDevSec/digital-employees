# sec-scan-design — 设计文档安全审核 Skill

一个基于 **大模型 (LLM)** 进行设计文档安全合规审核的 Skill，规则随 Skill 打包分发，开箱即用，**无需任何 Python/Shell 脚本**。

## 一、概述

| 属性       | 值                                                                      |
| -------- | ---------------------------------------------------------------------- |
| Skill 名称 | `sec-scan-design`                                                      |
| 当前版本     | 见 `VERSION` 文件                                                         |
| 内置模块数    | 12个                                                                    |
| 内置规则数    | 133 条                                                                  |
| 审核方式     | LLM 语义分析（按需加载规则）                                                       |
| 支持格式     | `.md` / `.txt` / `.docx`（.docx 三级降级转换：markitdown → Python标准库 → 提示手动转换） |
| 输出格式     | Markdown 报告（`<原文档>.security-audit.md`）                                 |

## 三、安装方法

### 方式 A：放入项目的 `.trae/skills/` 目录（推荐）

将整个 `sec-scan-design/` 文件夹复制到目标项目的 `.trae/skills/` 下：

```
<项目根目录>
└── .trae/
    └── skills/
        └── sec-scan-design/   <-- 整个文件夹放入此处
            ├── SKILL.md
            ├── README.md
            ├── VERSION
            ├── CHANGELOG.md
            └── references/
```

完成后，当你在该项目下说"对设计文档 XX 做安全审核"时，Skill 会被自动识别并触发。

### 方式 B：自定义规则覆盖

如果你需要在某个项目中使用自定义或更新后的规则文件，可以在该项目根目录下创建 `references/` 文件夹，并放入同名规则文件：

```
<项目根目录>
├── references/                           <-- 优先级更高
│   └── 访问控制_安全合规检查规则.md   <-- 此文件会覆盖 Skill 内置的同名规则
└── .trae/skills/sec-scan-design/
    └── references/                       <-- 兜底回退（未命中时读取）
```

查找规则文件的顺序为：

1. `<workspace>/references/<模块名>_安全合规检查规则.md` （用户自定义优先）
2. `<skill>/references/<模块名>_安全合规检查规则.md` （Skill 内置回退）

## 四、使用方法

在支持该 Skill 的 IDE / Agent 环境中，向大模型下达自然语言指令即可，例如：

```text
> 对 docs/用户中心设计.md 做安全审核
> 基于 references/ 目录的规则审一下 design.md
> 检查一下设计文档是否符合安全合规规则
> 给出设计文档的安全合规报告与修改建议
```

### 触发条件

**必须触发**：

- 用户要求对"设计文档"/"详细设计"/"概要设计"/"技术方案"/"架构设计"做安全审核/审计/合规检查
- 用户指定文件是 `.md`/`.txt`/`.docx` 格式的设计类文档

**不应触发**（交给其他技能）：

- 对源代码文件（.js/.py/.go/.java/.c 等）的安全审计 → 使用 `sec-scan-code`
- 对运行时系统进行渗透测试 → 使用其他安全工具

### 审核输出

Skill 会生成一份 Markdown 报告，保存在与被审核文档同目录下的 `<原文档名>.security-audit.md`。报告结构：

1. **文档信息** — 被审核文档名、审核日期、审核工具及版本号（从 VERSION 文件读取）
2. **审核概述** — 涉及模块、使用规则清单
3. **安全规则覆盖情况** — 表格：模块、规则总数、PASS、FAIL、N/A、覆盖率、符合率
4. **发现的问题清单** — 按严重程度排序，每条含：规则编号、所属模块、证据（原文片段）、问题描述、修改建议；Critical/High 级别问题额外包含攻击场景分析与推荐方案
5. **总体结论与后续行动建议** — 总体评估表、核心结论、优先修复建议（P0/P1/P2/P3）

## 五、打包/分发

### 5.1 分发包制作

将整个 `sec-scan-design/` 文件夹打包为压缩包即可：

```bash
# Linux/macOS
zip -r sec-scan-design-v1.0.0.zip sec-scan-design/

# Windows PowerShell
Compress-Archive -Path sec-scan-design -DestinationPath sec-scan-design-v1.0.0.zip
```

### 5.2 分发包内容清单

压缩包内包含以下文件（缺一不可）：

```
sec-scan-design/
├── SKILL.md       必须（Skill 定义文件，含执行步骤、审核指令模板）
├── README.md      建议（本文件，安装与使用说明）
├── VERSION        建议（版本号，如 `1.0.0`）
├── CHANGELOG.md   建议（变更记录）
└── references/         必须（12 个规则文件，共 133 条规则）
```

### 5.3 接收方安装步骤

1. 解压 `sec-scan-design-vX.Y.Z.zip`；
2. 将解压后的 `sec-scan-design/` 目录整体复制到目标项目的 `.trae/skills/` 目录下；
3. 在项目中对设计文档下达自然语言指令，即可开始审核。

## 六、版本管理

- 版本号遵循 **语义化版本（SemVer）**：`主版本号.次版本号.修订号`
  - 主版本号：不兼容的规则/流程变更（如大幅改写审核步骤）
  - 次版本号：向下兼容的功能性新增（如新增模块、新增规则）
  - 修订号：向下兼容的问题修正（如修正规则描述、修正审核指令）
- 每次发布新版本，必须更新 `VERSION` 文件，并在 `CHANGELOG.md` 中记录变更。

## 七、核心特性回顾

- ✅ **零脚本依赖**：全程通过 LLM 完成审核，不执行任何代码。
- ✅ **中间文件自动清理**：执行过程中产生的临时文件，在最终报告输出后自动清理。
- ✅ **按需加载规则**：只加载设计文档涉及的模块，节省 Token、聚焦审核。
- ✅ **规则内置可分发**：`references/` 随 Skill 一起打包，无需额外依赖。
- ✅ **支持自定义覆盖**：在项目 `references/` 放入同名文件即可覆盖内置规则。
- ✅ **可追溯问题证据**：每条问题关联设计文档原文片段，便于修改。
- ✅ **量化覆盖统计**：按模块输出覆盖率与符合率，便于追踪改进。
- ✅ **精确触发**：description 明确区分设计文档与源代码，避免与 sec-scan-code 技能冲突。
- ✅ **多格式支持**：支持 `.md`、`.txt`、`.docx` 格式设计文档，`.docx` 三级降级自动转换。
