# kdev-gen-storymap · 用户故事地图产物生成（author·从规范模板转化）

**开场播报**："我在用 kdev-gen-storymap 生成 <迭代> 用户故事地图（author 模式）。"

> **V4x.1 形态**：本 SKILL 把用户故事地图规范模板的结构 + 生成纪律封装成可调生成器。`0b-生成提示词模板` 因此变薄——只喂坐标+上游料并**调本 SKILL**，不再贴整段生成指令。
> 节点：**用户故事地图**　tier=**T2**（无 T1 追溯镜头）　上游=**SR**（**单上游**）。

## 吃什么（生成提示词喂入）
> **输入骨架与必填字段以 `nodes-data/storymap/prompt-template.md` 为准（占位模板+机检参数单一真源·准入 `prompt-check.sh` 依它核）；本段只述各料语义。**
- 坐标：迭代 / 落位 `迭代N/00-planning/用户故事地图.md`。
- 本轮模式：首次生成 / 整改第K轮 / 打回重做。
- **用户故事地图规范模板**（结构权威，如 `specs/用户故事地图规范.md`，§2 输出结构 = 地图定位 / 泳道·版本分组 / 故事卡 / 版本编排与依赖）。
  - 故事卡骨架（§2.3）：`名称` + 一句话 User Story（作为…我希望…以便于…）。
- **上游产物（单上游）**：
  - SR 需求（**逐 SR-item 取全**，作为故事卡来源）。
  - 〔非首版本〕前序版本用户故事地图（复用泳道/编排形状、共享面）。
- 〔打回重做/整改 时 MUST 含〕前轮便签的 **veto 失败项 + 主要扣分点**（已知坑清单）。

## 生成（按规范结构填·MUST）
1. **严格按规范 §2 结构** 逐段填：地图定位 / 泳道·版本分组 / 故事卡 / 版本编排与依赖（**四段齐**）。不自创、不省略。
2. **忠实覆盖 SR 各 item**（关键·SR→US 可追溯）：SR-item 集合**全部映射**到故事卡，无遗漏、无凭空新增无 SR 支撑的卡；每卡可追溯回具体 SR-item ID。
3. **泳道 / 版本编排清晰**：按版本或用户活动分泳道，各版本在整体中的位置、先后/依赖说清楚；阅读者能一眼看出"哪些卡属于哪个版本、版本间谁先谁后"。
4. **不实质下钻到 AC/字段级**（强约束区纪律）：故事卡 = `名称` + 一句话 User Story（作为…我希望…以便于…），**只给 WHAT/WHY 的一句话**；完整验收标准（GWT）、字段口径、技术选型一律**下沉单条 AR**，本节点不写。
5. **无占位符**：无 TODO/TBD/"待补"；评审版 `[NEEDS CLARIFICATION]` ≤3 且交付前清零（转一句话假设说明）。
6. 〔打回重做时〕先逐条读已知坑清单、规避前轮失败模式，再动笔。

## 落位 + 生成自检（交检查前）
- 写到 `迭代N/00-planning/用户故事地图.md`。
- 自跑：四段结构齐 / 无占位符 / SR-item 全覆盖且每卡可追溯 / 每卡只名称+一句话未下钻 AC / 泳道·版本编排成文 / 落对路径。
- **不自调任何检查 SKILL**——准入已过，准出/顶层约束/质量由编排层另触发。

## 红旗（出现即停）
- 脱离规范 §2 结构另起 / 省略四段中任一段。
- 故事卡里写完整 AC（GWT）、字段级实现、技术选型（应下沉 AR）。
- 有 SR-item 未映射成卡 / 出现无 SR 支撑的凭空卡。
- 打回重做却不读前轮失败教训。
- 喂入不合 `prompt-template` 骨架（缺坐标/上游料/本轮模式，或整改缺教训）——停，退回走准入（输入机检）。
