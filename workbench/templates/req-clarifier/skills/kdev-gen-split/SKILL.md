# kdev-gen-split · 版本拆分产物生成（author·从规范模板转化）

**开场播报**："我在用 kdev-gen-split 生成 <迭代> 版本拆分（author 模式）。"

> **V4x.1 形态**：本 SKILL 把版本拆分规范模板的结构 + 生成纪律封装成可调生成器。`0b-生成提示词模板` 因此变薄——只喂坐标+上游料并**调本 SKILL**，不再贴整段生成指令。
> 节点：**版本拆分**　tier=**T2**（无 T1 追溯镜头）　上游=**SR + 总体设计 + 用户故事地图**（**三上游**）。

## 吃什么（生成提示词喂入）
> **输入骨架与必填字段以 `nodes-data/split/prompt-template.md` 为准（占位模板+机检参数单一真源·准入 `prompt-check.sh` 依它核）；本段只述各料语义。**
- 坐标：迭代 / 落位 `迭代N/00-planning/版本拆分.md`。
- 本轮模式：首次生成 / 整改第K轮 / 打回重做。
- **版本拆分规范模板**（结构权威，如 `specs/版本拆分规范.md`，§2 输出结构 = 拆分依据 / 版本清单 / 依赖关系 DAG / SR 覆盖矩阵）。
  - 版本清单单条骨架（§2.2）：`vX-名称` + `范围概述` + `关联 SR 条目` + `粒度估算` + `依赖的前序版本`（**五字段齐**）。
- **上游产物（三上游）**：
  - SR 需求（**逐 SR-item 取全**，作为覆盖矩阵的左列与切片范围依据）。
  - 总体设计（取模块划分/架构边界，作为切片边界与依赖判断依据）。
  - 用户故事地图（切分的直接对象：故事簇、MVP 骨架——判"切片独立可演示/MVP 切对"的依据）。
  - 〔非首版本〕前序版本版本拆分（复用伞名/切法形状、共享面）。
- 〔打回重做/整改 时 MUST 含〕前轮便签的 **veto 失败项 + 主要扣分点**（已知坑清单）。

## 生成（按规范结构填·MUST）
1. **严格按规范 §2 结构** 逐段填：拆分依据 / 版本清单 / DAG / SR 覆盖矩阵（**四段齐**；每版本五字段齐）。不自创、不省略。
2. **每个版本切片独立可演示 / MVP 切对**（关键·veto 级）：每个 `vX` 都能独立开发、独立交付、可单独演示的纵切片；MVP 切在"能跑通主价值的最小集"上，不把可演示性切碎、也不把 MVP 注水。
3. **拆分理由充分**：§拆分依据成文，按**关联度**给出"为何这样合/这样分"——高关联合并、低关联独立，逐相邻切法可被这套理由解释。
4. **伞名不与版本名碰撞**：迭代级伞名（整体名）与各 `vX-名称` **不重名、不歧义**；版本名彼此可区分。
5. **粒度估算给具体数值**：每版本 `粒度估算` 给**具体数值**（如故事点/人天/卡数区间），不写"较大/适中/不多"等模糊词。
6. **SR 全覆盖 + 上游忠实**：SR-item 集合**全部落进** SR 覆盖矩阵、无空缺格、无凭空范围；切片边界忠实于 SR 范围、总体设计的模块划分与用户故事地图的故事簇，**不在拆分文档里另起技术方案/重新设计架构**（只描述"切哪些 SR、依赖谁、多大粒度"）。
7. **DAG 无环**：版本间依赖画成 DAG，方向一致、无循环依赖。
8. **无占位符**：无 TODO/TBD/"待补"；评审版 `[NEEDS CLARIFICATION]` ≤3 且交付前清零（转一句话假设说明）。
9. 〔打回重做时〕先逐条读已知坑清单、规避前轮失败模式，再动笔。

## 落位 + 生成自检（交检查前）
- 写到 `迭代N/00-planning/版本拆分.md`。
- 自跑：四段结构齐 + 每版本五字段齐 / 无占位符 / 每版本独立可演示且 MVP 切对 / 拆分理由成文 / 伞名无碰撞 / 粒度全为具体数值 / SR 覆盖矩阵无空缺 / DAG 无环 / 落对路径。
- **不自调任何检查 SKILL**——准入已过，准出/顶层约束/质量由编排层另触发。

## 红旗（出现即停）
- 脱离规范 §2 结构另起 / 省略四段中任一段 / 某版本五字段不齐。
- 出现不可独立演示的切片，或 MVP 注水/切碎。
- 伞名与某 `vX-名称` 碰撞。
- 粒度估算用模糊词、无具体数值。
- 有 SR-item 未进覆盖矩阵 / DAG 出现环。
- 在拆分文档里另起技术方案、重新设计架构（越权到详设）。
- 打回重做却不读前轮失败教训。
- 喂入不合 `prompt-template` 骨架（缺坐标/上游料/本轮模式，或整改缺教训）——停，退回走准入（输入机检）。
