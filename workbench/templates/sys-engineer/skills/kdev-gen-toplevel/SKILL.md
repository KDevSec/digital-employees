# kdev-gen-toplevel · 顶层约束产物生成（author·从顶层约束规范模板转化）

**开场播报**："我在用 kdev-gen-toplevel 生成 <版本> 顶层约束文档（CLAUDE.md·author 模式）。"

> **V4x.1 形态**：本 SKILL 把顶层约束规范的双子树骨架 + 生成纪律封装成可调生成器。`0b-生成提示词模板` 因此变薄——只喂坐标+6 类前置材料并**调本 SKILL**，不再贴整段生成指令。
> **节点特殊性**：顶层约束是**根节点**——你写出的这份文档就是 CLAUDE.md 本身，是后续所有下游节点第三步「顶层约束检查」的**判据源**。因此本节点**无强上游产物**；料 = **6 类前置材料**（非"上游产物"）。必须可被别人逐条对抗式核对 → 条目要可枚举、可标记权重。

## 吃什么（生成提示词喂入）
> **输入骨架与必填字段以 `nodes-data/toplevel/prompt-template.md` 为准（占位模板+机检参数单一真源·准入 `prompt-check.sh` 依它核）；本段只述各料语义。**
- 坐标：迭代（根节点常与具体迭代无关，可填 —）/ 版本（vX-名 | v1.0 全局首版）/ 落位（profile，如 项目根/CLAUDE.md 或 docs/process-assets/CLAUDE.md）。
- 本轮模式：首次生成 / 整改第K轮 / 打回重做。
- **顶层约束规范模板**（结构权威，如 `specs/顶层约束规范.md`）——输出骨架 = 形态 C·双子树型：§preamble+顶层优先级 / §hard-constraints 内联硬约束 / §navigation 首跳指针 / §factual-subtree 事实子树（各 leaf：主引用+源码资产深挖+读取时机+优先级注释）/ §process-subtree 过程子树（§routing-table SOP 节点式 + §conflict-resolution 冲突裁决）。
- **6 类前置材料**（根节点的"料"=前置材料·逐类指认路径·无则标"无"）：
  - **C1 · 硬约束 / 红线原则**（团队"绝对不能违反"清单，如 12 条大原则 + 安全底线；无→MUST 基于 C2 起草 6-8 条最小红线待用户确认）。
  - **C2 · 项目背景与目标**（做什么 / 为什么 / 给谁用）。
  - **C3 · 流程 / SOP / 工作流**（团队怎么干活、何时停下评审 = SOP 方法论源）。
  - **C4 · 技术参考资料**（编码规范 / 前端 UED 规范 / 新框架理解；可多份）。
  - **C5 · 历史 / 遗留代码理解**（关联旧项目代码·重构/迁移项目用·可空）。
  - **C6 · 原型 / 设计参考**（设计系统 / 新平台原型风格·可空）。
- profile 技术语境（框架契约 / 设计系统 / 旧码约定）：填事实子树各 leaf 的"读取时机/优先级注释"与冲突裁决内部链。
- 〔打回重做/整改 时 MUST 含〕前轮便签的 **veto 失败项 + 主要扣分点**（已知坑清单，如"硬约束没逐条枚举致下游无法全量核""漏标 veto/加权"）。

## 生成（按规范双子树骨架装配·MUST）
1. **严格按规范骨架装配**：按形态 C·双子树逐节填，不自创章节、不省略必备段（§preamble / §hard-constraints / §navigation / §conflict-resolution）。
2. **硬约束 100% 内联、且逐条枚举可核**（本节点核心）：
   - 把 **C1 的 12 原则 / 安全底线**全文内联进 §hard-constraints，**绝不**用 `./xxx`、"详见 xxx" 指针委托。
   - **逐条枚举**每条原则/底线（C01、C02……一条一行），每条**可标记** `[veto]`（踩即不达标）或 `[加权]`（计入分），对不适用某产物类型的条目预留 `[N/A·代码态/运行态/测试态]` 语义标注——这样下游第三步才能逐条对抗式举证、全量核对。
   - 清理 C1 原文草稿标记（`(?)`/`(待补)`/`(TBD)`/`（？…）`）。
3. **SOP 方法论忠实嵌入**：§process-subtree 入口段引用 C3 全文指针 + 提炼 §routing-table（SOP 节点 → 必读子约束，**≥3 行 ≤12 行**），把"何时停下评审/评审门"纪律落进路由。
4. **技术语境忠实嵌入**：§factual-subtree 按 C4/C5/C6 主题各起一 leaf（编码规范 / 前端 UED 设计系统 / 新框架 / 旧码 / 原型风格），每 leaf 含主引用+源码资产深挖+读取时机+优先级注释；标了 `NON-NEGOTIABLE/MUST/硬约束` 的（如 UED）注明其硬约束语义（禁裸 hex/px/未授权字体等）。
5. **优先级链 + 子约束树级引用**：§preamble 写**层级优先级链**（用户显式指令 > 硬约束 > SOP 过程子树 > 技术语境子树 > 模型默认）；§conflict-resolution 写**技术契约内部优先级链** + 正交说明 +（可选）SOP级/技术契约级冲突两表；子约束以树级 `./路径` 引用挂在对应子树下。
6. **无占位符**：全文 `grep '<<'` 应零结果；无 TODO/TBD/"待补"；所有 `./` 引用都指向真实存在的前置材料路径。
7. 〔打回重做时〕先逐条读已知坑清单、规避前轮失败模式（尤其"硬约束没逐条可核""漏标 veto/加权"），再动笔（不是无记忆重来）。

## 落位 + 生成自检（交检查前）
- 写到 <<落位路径>>（若已存在 CLAUDE.md：Overwrite 先备份再覆盖 / Merge-manually 写 `<原名>.new.md` 交人工合并）。
- 自跑：骨架必备段齐（preamble/硬约束/导航/冲突裁决）/ 硬约束 100% 内联且逐条枚举且标了 veto·加权 / 12原则·安全底线·SOP·技术语境均已忠实嵌入 / 优先级两层链在 / 路由表 3-12 行 / `<<` 残留为 0 / `./` 引用全解析到真实路径 / 落对路径。
- **不自调任何检查 SKILL**——准入已过，准出/顶层约束（根节点忠实性特例·合规核 N/A）/质量由编排层另触发。

## 红旗（出现即停）
- 硬约束用指针委托（`./xxx`、"详见 xxx"）而非 100% 内联。
- 硬约束写成一大段散文、不可逐条枚举，致下游无法全量核对。
- 漏标 veto/加权，或漏 §preamble 顶层优先级链 / §conflict-resolution。
- 12 原则 / 安全底线 / SOP 方法论 / 技术语境（框架/设计系统/旧码）任一未忠实嵌入。
- `<<占位符>>` 残留（该清零而未清）。
- 打回重做却不读前轮失败教训（会原地踏步）。
- 喂入不合 `prompt-template` 骨架（缺坐标/上游料/本轮模式，或整改缺教训）——停，退回走准入（输入机检）。
