# kdev-gen-overview · 总体设计产物生成（author·从总体设计规范模板转化·契约枢纽 T1）

**开场播报**："我在用 kdev-gen-overview 生成 <迭代> 总体设计（author 模式·跨版本契约枢纽 T1）。"

> **V4x.1 形态**：本 SKILL 把总体设计撰写规范模板的九章节骨架 + 生成纪律封装成可调生成器。`0b-生成提示词模板` 因此变薄——只喂坐标+上游料并**调本 SKILL**，不再贴整段生成指令。
> **节点特性**：总体设计 = **跨版本契约枢纽（T1）**，是所有版本详设的**唯一契约权威**。核心定位 = **只锁骨架**（架构/模块边界/技术选型/数据模型骨架/权限·集成基线），字段级实现下沉版本详设/US。

## 吃什么（生成提示词喂入）
> **输入骨架与必填字段以 `nodes-data/overview/prompt-template.md` 为准（占位模板+机检参数单一真源·准入 `prompt-check.sh` 依它核）；本段只述各料语义。**
- 坐标：迭代 / 版本（迭代N-planning）/ 落位 `迭代N/00-planning/总体设计.md`。
- 本轮模式：首次生成 / 整改第K轮 / 打回重做。
- **总体设计规范模板**（结构权威，如 `core/specs/总体设计规范.md`）：九章节骨架（§2）= 1 设计目标与约束 / 2 系统边界 / 3 模块划分(含依赖 DAG + 复用·新建标注) / 4 核心数据模型(ER + 结构性关键字段·完整业务字段表显式下沉) / 5 权限模型 / 6 外部系统集成设计 / 7 关键业务流程 / 8 关键风险与待决问题 / 9 成功标准对齐。
- **上游料（契约枢纽）**：
  - **SR 需求**：取本迭代全部 SR-item 及其成功标准 SC-N，作追溯源。
  - 〔N≥2 或非首迭代 MUST 含〕**上一迭代《总体设计》**：沿用既定共享契约（架构基座/模块边界/数据模型骨架/权限基线），跨迭代以它为承接权威。
  - 〔N≥2 MUST 含〕**迭代收尾交接**：上一迭代遗留项 / 已敲定但待落的契约调整。
  - **profile:框架基线**：当前 profile 框架基座契约（复用优先、与框架核心解耦的硬约束），写进 §1 设计目标与约束。
- 〔打回重做/整改 时 MUST 含〕前轮便签的 **veto 失败项 + 主要扣分点**（已知坑清单。典型坑：四要素有空壳标题 / §4 贴完整字段表或 SQL / SR 成功标准成片漏接 / §8 开放项不标归属）。

## 生成（按规范九章节骨架填·MUST）
1. **严格按规范 §2 九章节**：逐章填充，不自创章节、不省略章节；某章不适用须显式写"不适用（理由：…）"，不裸缺。
2. **【契约枢纽四要素实锁 · 核心】**：本节点是所有版本详设的唯一契约权威。四要素必须**各有实质内容（非空壳标题）且相互自洽**——
   - **系统架构**（§1 目标约束 + §3 模块划分总览）：分层/边界/技术选型锁定，技术选型 MUST 带具体版本标识。
   - **模块边界**（§3）：顶层模块 + 依赖 DAG（无环）+ 每模块复用/新建标注 + 职责单一。
   - **数据模型骨架**（§4）：ER 关系 + 结构性关键字段（主键/外键/来源/状态/逻辑删）；**完整业务字段表显式下沉版本详设/US，不在此展开**。
   - **权限·集成基线**（§5 + §6）：功能权限 + 数据权限基线；外部集成端口/适配器 + mock 基线。
3. **不下钻字段级实现**（§1 锁骨架·brownfield 校准）：强约束区（§4 + §5）只锁结构性关键字段，**禁止完整业务字段表 / 字段类型长度默认值 / 具体 SQL / 接口路径**；容许区（§1 / §8）可指针式**引用既有**框架基座/数据模型/旧码逻辑作约束锚点，但不在此**新设计**未授权技术方案。
4. **【T1 追溯纪律】**：§9「成功标准对齐」MUST **覆盖 SR 全部成功标准（SC-N）**，每条 SC-N → 指向本设计的真实存在、语义对得上的章节；**SR 成功标准成片落空（多条无对应章节或指向错位）= 必退红旗，动笔即防**。反向自核：每个模块/实体/集成端口都能溯回某条 SR 要点，不凭空加设计。
5. **profile:框架契约对齐**：§1 硬约束表锁定框架基座、复用优先；模块划分与数据模型须贴合 profile 框架核心契约，复用 > 新建，与框架核心解耦。
6. **§8 开放项治理**：每条待决问题/风险 MUST 显式标注**归属（详设/US/后续迭代）**与缓解措施，不留无主开放项。
7. **无占位符**：全文无 TBD/TODO/"待补"；评审版未决项一律落 §8 并标归属，不散落正文。
8. 〔打回重做时〕先逐条读已知坑清单、规避前轮失败模式，再动笔（不是无记忆重来）。

## 落位 + 生成自检（交检查前）
- 写到 `迭代N/00-planning/总体设计.md`。
- 自跑：九章节齐（不适用项已论证）/ **契约枢纽四要素各有实质内容且自洽** / 技术选型带具体版本标识 / 依赖 DAG 无环 / §4 未贴完整字段表·无 SQL·无接口路径 / **§9 覆盖 SR 全部 SC-N 且指向语义对得上（追溯 veto 自查）** / §8 开放项均标归属 / 落对路径。
- **不自调任何检查 SKILL**——准入已过，准出/顶层约束/质量由编排层另触发（四要素实锁+不下钻+追溯在质量步带 T1 镜头评）。

## 红旗（出现即停）
- 脱离九章节结构另起 / 省略某章 / 四要素中任一是空壳标题。
- §4/§5 强约束区贴完整字段表、写 SQL/接口路径、下钻字段类型长度默认值。
- **SR 成功标准成片漏接（§9 多条无对应章节或指向错位）**。
- §8 开放项无归属。
- 打回重做却不读前轮失败教训。
- 喂入不合 `prompt-template` 骨架（缺坐标/上游料/本轮模式，或整改缺教训）——停，退回走准入（输入机检）。
